# L1 - High-Level Requirements

ShotThere is a review and comparison site for places to shoot photos in Toronto: rental studios first, then outdoor spots. Every location is reviewed first-hand with the same measurements and the same standard test setup, so locations compare side by side. These requirements cover the Phase 1 MVP web solution: a public, search-friendly site and an owner-only administration area. Taking bookings or payments, user-submitted reviews or listings, studio-owner accounts, paid placement, cities other than Toronto and the surrounding area, and a native mobile app are out of scope.

## L1-001: First-hand listing policy
The site must publish only locations that the reviewer has personally shot at. Every published location must carry the same standard set of measurements and, for studios, the same standard test shots, so that any two locations can be compared on identical data.

## L1-002: Studio review page
The site must provide a page for each published studio containing the basics, pricing with a calculated all-in cost for a standard 2-hour shoot, measured specifications, included gear, logistics, the standard test shots, a gallery from a real shoot, a verdict with scores on a fixed rubric, a disclosure of how the session was paid for, and the YouTube episode when one exists.

## L1-003: Outdoor spot page
The site must provide a page for each published outdoor spot containing its location and map, how to get there, best light by time of day and season, sample shots with lens and angle notes, practical conditions (crowds, parking, washrooms, changing options), a dated permit status linked to the official source, best uses, and rain-backup studios.

## L1-004: Browse, filter and sort
The site must let visitors browse studios and outdoor spots as lists, narrow them with filters relevant to each type, and sort studios by all-in cost, overall score, and most recent review. The current filters and sort must be held in the URL so a filtered view can be shared and revisited.

## L1-005: Map view
The site must show all published locations on a single interactive map, from which a visitor can open any location's page.

## L1-006: Side-by-side studio comparison
The site must let a visitor select two to four studios and view their specifications, pricing, scores, and standard test shots in aligned columns. Every comparison must have a shareable URL and must be fully usable on a phone.

## L1-007: "Best for" guides
The site must provide editorial guide pages (for example, best under a price point, best natural light, best for headshots, best for a large crew) built from review data, each linking to the underlying reviews it draws on.

## L1-008: Rain backup
Every outdoor spot page must point visitors to the nearest reviewed studios as a rain backup.

## L1-009: Email signup
The site must let visitors subscribe with an email address, validating input, preventing abuse, and confirming the result.

## L1-010: Data freshness
Every price field and every permit field must store the date it was last verified. The site must show that date and must visibly flag any such data that is more than six months old.

## L1-011: Editorial integrity and disclosure
Every review page must disclose whether the session was paid for or comped. Review scores must never be influenced by payment, and the MVP must contain no paid placement. Negative findings must be published alongside positive ones.

## L1-012: YouTube integration
Review pages must embed the companion YouTube episode when a video exists, must degrade cleanly when none exists, and must link to the channel.

## L1-013: Owner authentication
The site must provide a single owner account with secure sign-in, sign-out, and session handling. Administration screens and administration APIs must be unreachable without an authenticated owner session.

## L1-014: Content management
The owner must be able to create, edit, publish, unpublish, and delete studios, outdoor spots, and guides, including structured fields, images, video links, and verification dates, through the administration area without code changes. The public site must show only published content.

## L1-015: Responsive, mobile-first user interface
Every screen must work at phone width first and scale up through small, medium, large, and extra-large viewports without horizontal page scrolling, respecting device safe areas.

## L1-016: Accessibility
Every public and administration screen must meet WCAG 2.2 Level AA.

## L1-017: Performance
Image-heavy pages must load quickly on mobile networks through responsive images, lazy loading, caching, and measurable Core Web Vitals budgets.

## L1-018: Search-friendliness
Public pages must be delivered as server-rendered or statically generated HTML with clean, stable URLs, structured data for reviews and places, page metadata, a sitemap, and robots directives.

## L1-019: Security
The system must validate all input on the server, authorize every administration request, handle uploads safely, protect public write endpoints against abuse, enforce transport security and security headers, and keep secrets out of client code, addressing the OWASP Top 10.

## L1-020: Reliability and observability
The system must present clear error pages, expose a health check, emit structured logs for requests and failures, and degrade gracefully when media or video is unavailable.

## L1-021: Low running cost
The public site must be deployable as static or cached output served through a CDN so that hosting cost stays near zero at MVP traffic.
