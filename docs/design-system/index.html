ShotThere design system

Tokens, components and patterns for ShotThere, a review and comparison site for places to shoot photos in Toronto: white space, one ink button per screen, pepper red for “you are here”. Inherited from the Sweet Hand design system; the basic components only, until the ShotThere mocks exist.

Start here

ShotThere reviews and compares places to shoot photos in Toronto: rental studios first, then outdoor spots. Its design system is inherited from Sweet Hand: a white canvas, a bold wordmark, a quiet text-only nav, the selected item in pepper red, generous white space. This copy keeps the tokens, foundations, patterns and the 32 generic components; the domain components (listing cards, gallery, map, filters, compare bar) will be re-derived from the ShotThere mocks. Example copy on these pages still reads as Sweet Hand until then.

How to use

  1. Link the CSS in this order: tokens/tokens.css (every value, both themes), then assets/components.css (every component class). assets/ds.css and assets/ds.js are only for these documentation pages.
  2. Use the classes and attributes from each component's Code section. State lives in real attributes (disabled, aria-pressed, aria-current, aria-invalid, aria-expanded, aria-busy); data-state exists only to show states in static pages. Keep the class names: the mocks, the product and the e2e page objects share them.
  3. Read tokens by role, never by value. Use var(--color-fg-muted), not the hex. Platforms that cannot read CSS consume tokens/tokens.json (W3C DTCG format; aliases preserved; dark overrides under $extensions).
  4. Theme with data-theme="light|dark" on <html>; with no attribute the OS preference applies. Press t on any page here to flip it.
  5. Check before shipping a change: check_contrast.py on tokens.css must pass in both themes, and check_design_system.py on this folder must report 0 errors (see the verification record in the README).
