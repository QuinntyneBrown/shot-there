Pattern

Forms

ShotThere asks for very little: an email address from visitors, and from the admin a sign-in and long, sectioned editors for studios, spots and guides. Every form checks on submit, keeps everything typed, names exactly what to fix, and leaves the final word to the server.

Overview

Visitors meet two forms: the email signup (home hero and footer) and the studio and spot filters. The admin, the only account, meets the rest: sign-in at /admin/sign-in, the studio, spot and guide editors, and the entry picker that adds a studio or spot to a guide. They are built from the form field (label, control, message, help), the controls (text field, textarea, select, checkbox, radio group, combobox, file upload), the form layout (.field-row, .form-summary, .form-actions--sticky) and the editor layout.

  • The server is the authority. The browser only helps: it can catch an empty email before sending, but every rule (a rate of 0 or more, a score from 1 to 5, a booking link that starts with http) is checked again on the server, and server errors render exactly like browser ones.
  • No inline forms on reading pages. A review page never grows a form. Button-triggered editing opens a dialog (Add an entry, Filters) or goes to a screen (Edit, New studio). The screens whose whole job is the form are sign-in, the three editors and the signup block.
  • Never lose input. Refused saves, failed requests, rate limits and the discard check all keep every value. Only an incorrect sign-in clears the password.
  • One primary per form. Subscribe, Sign in, Save changes or Create studio, Show 5 studios, Add entry. Publish and Unpublish live in the status panel as secondary buttons, apart from the save.

Discard changes

Any in-app link or Cancel while there are unsaved changes opens "Discard changes?" ("You changed 3 fields in Corktown Garage Studio since the last save."), with Stay focused and Discard last. Closing the tab triggers the browser's own leave-page prompt instead. A saved form leaves without asking.

Filters: the invalid price range

Filters are a form whose submit is "Show N studios". The only rule a visitor can break is a minimum above the maximum: the maximum explains it before anything is applied and Show is disabled. (A URL that arrives with min above max is not an error: the range is treated as unset.)

Labels, help and required fields

  • The label sits above the control; the error sits directly under the control, then the help. Placeholders are never the label.
  • Required is the default and is not marked. Optional fields add <span class="optional">(optional)</span>: "Backdrops (optional)", "Load-in note (optional)", "YouTube link or video ID (optional)". A conditional field says when it is needed: "Provided by (needed when discounted or comped)". No asterisks.
  • Help states the rule before anyone breaks it: "Whole numbers from 1 to 5. The overall score is calculated by the server." "Write "None" rather than leaving it empty." "JPEG, PNG, WebP or AVIF, up to 20 MB each."
  • Groups of choices use <fieldset> and <legend>: Fees, Natural light, "How was this session paid for?", each filter group.
  • Units live in the label or an addon, never only in help: "Usable width (m)", "Minimum booking (hours)", the $ addon on amounts.

Validation timing

  1. While typing the first time: nothing turns red. The slug fills from the title until it is edited by hand; the preview map follows the coordinates.
  2. On submit: the browser catches only what it can know (an empty required field, an email without an @) and renders it exactly as the server would. Everything else goes to the server, whose errors fill the summary and the fields together, and focus moves to the summary.
  3. After a refused submit: a field re-validates on input and blur, so its error clears as soon as it is right. The summary updates on the next submit.
  4. Live checks inside dialogs (the price range, a duplicate guide entry) show under the field at once and disable the primary rather than waiting for a submit.

Responsive behaviour

  • XS (below 36rem): .field-row stacks; the signup button goes full width under the field; fee rows stack label over field.
  • Below LG (62rem): the editor status panel sits above the form; the sticky bar spans the width and clears the bottom safe-area inset; filters open as a full-height sheet with Clear all and Show N studios sharing the footer.
  • LG and up: the status panel is sticky beside the form (18rem); filters are a sidebar form with Apply filters.
  • Numeric fields use inputmode="decimal" (rates, sizes, coordinates) or numeric (scores, outlets, hours); email uses type="email" and autocomplete="email" or username; dates use the native picker with max set to today.
  • Controls are 44px tall below 48rem and text is at least 16px, so phones never zoom into a field.

Accessibility

Role and pattern

Native <form novalidate> (the product's messages replace browser bubbles), native inputs, <fieldset>/<legend> for groups, <details>/<summary> for editor sections (APG Disclosure), and the entry picker as an APG Combobox. Errors meet WCAG 3.3.1, 3.3.3 (say how to fix), 3.3.7 (no re-entry) and 3.3.8 (paste and password managers allowed).

Focus

A refused submit moves focus to the summary (tabindex="-1", role="alert"); a single-field form (signup) moves focus to the field. An incorrect sign-in focuses Password. After Create studio, the edit screen opens with the success alert; after a save, focus stays where it was. When an upload finishes, its alt-text field takes focus. Price changed focuses Prices last verified.

Labelling

Every control has a <label for>. Error and help join the control with aria-describedby, error first. Repeated controls carry the item in a visually hidden suffix, so "Remove" is announced as "Remove Cleaning fee", "Move up" as "Move up: test shot 1" and "Editor's note" as "Editor's note for Leslieville Daylight Studio". Keep help and error outside the <label> element (div.field + label.field__label), or they become part of the field's name.

Errors never rely on colour: each has the ⚠ glyph, text and a thicker border; invalid sections add a border and are open.

Motion

Errors and sections appear without animation beyond the chevron turn, which reduced motion zeroes. The busy spinner keeps turning because it reports status.

Touch

Controls and section summaries are at least 44px tall below 48rem; the sticky bar's buttons sit 12px apart; the Show toggle on Password is a full-height button, not an icon.

Content

  • Labels are short nouns in sentence case with units: "Hourly rate", "Minimum booking (hours)", "Prices last verified", "Usable width (m)", "Who it's for", "Who should skip it".
  • Field errors say what to enter, in one sentence, with no "please" or "invalid": "Enter an amount of 0 or more", "Enter a whole number from 1 to 5", "Enter a web address that starts with http:// or https://", "The date can't be in the future", "Describe this image", "Enter a latitude from -90 to 90", "Enter a YouTube link or video ID".
  • Summary heading: "Fix N thing(s)" plus what it unblocks: "Fix 2 things to sign in", "Fix 6 things before saving". Each link is "Field label: the field's own message".
  • Primary buttons name the outcome: "Sign in", "Subscribe", "Create studio", "Save changes", "Show 5 studios", "Add entry". Cancel is always "Cancel".
  • Server failures own the problem and reassure: "We couldn't sign you in just now. Try again in a minute. What you typed is still here."

Do and don't

Sources

  • Sign-in: default, invalid, incorrect, submitting, rate-limited, error, session-expired, signed-out
  • Signup: home/default, invalid, submitting, error, rate-limited, success
  • Editors: studio-editor/default, new, invalid, submitting, success, price-changed, uploading, upload-failed, published; spot-editor/invalid, spot-editor/new; guide-editor/default, guide-editor/invalid
  • Dialogs: missing-fields/default, missing-fields/spot, discard-changes/default, studio-filters/invalid, guide-entry-picker/invalid

Drift fixed during extraction: summary headings used three formulas ("Fix 6 things before saving", "Fix 4 problems before saving", "This guide can't be published yet"); the system uses "Fix N thing(s)" plus the action, and summary links keep the field message's capital ("Latitude: Enter…"). The guide editor reports a refused publish as a form summary while studios and spots use the "Can't publish yet" dialog; the system uses the dialog for every refused Publish and the summary for refused saves. The editors wrap valid fields in <label class="field"> with their help inside, which folds the help into the field's name; the system uses div.field with label.field__label everywhere, as the invalid fields already do. The "Can't publish yet" links point at the editor page rather than the field id; they must target the field. The price-changed mock marks a required field "(required)"; the system marks only optional fields and says why in a warning.
