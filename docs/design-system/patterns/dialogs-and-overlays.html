Pattern

Dialogs and overlays

An overlay on ShotThere interrupts for one decision or one close look: confirm a consequence, narrow a list, view a photo, peek at a marker, pick a guide entry. Only one is ever open, focus starts on the safe choice and goes back to the control that opened it.

Overview

  • Confirmation dialog (.dialog__panel--sm): Delete Corktown Garage Studio?, Unpublish The Junction Loft?, Discard changes?, Remove test shot 2?, and the two refusals: Can't publish yet, Can't remove this test shot.
  • Form dialog (.dialog__panel--form): Add an entry, the guide-entry picker.
  • Sheet: Filters and Menu below 48rem; full height, with the title and footer always in view.
  • Lightbox (.viewer.lightbox): gallery photos, standard test shots and spot sample shots, full screen.
  • Map popup (.popover.map-popup): a non-modal card for one marker, docked along the bottom of the map on phones.

Rules for all of them: the page behind is inert (except behind the map popup, which is non-modal); Escape and Close dismiss without side effects; no stacking, so an overlay never opens another overlay on top of itself; and focus returns to the invoking control.

No stacking

  • A link inside an overlay that leads elsewhere closes the overlay first: each "Can't publish yet" link closes the dialog, opens the field's section and focuses the field.
  • The filters sheet applies or discards before anything else can open; there is no confirmation over it.
  • The map popup closes when another marker opens or the list view is chosen; only one popup exists.
  • Toasts are not overlays: they sit in their own region and never take focus, so a toast can appear while a dialog is open (Unpublish's warning toast arrives as the dialog closes).

Responsive behaviour

  • Below 36rem a confirmation dialog docks to the bottom as a sheet with rounded top corners and clears the bottom safe area; from 36rem it centres.
  • Below 48rem the filters and menu sheets fill the screen; the entry picker fills the screen when marked .dialog--full. From 48rem sheets slide in from the right at the sheet width.
  • The lightbox moves Previous and Next under the photo below 48rem (.lightbox__pager) so the photo gets the full width; from 48rem the arrows sit beside it.
  • The map popup docks along the bottom of the map below 48rem (.map-popup--dock) and floats above its marker from 48rem.
  • Footers wrap with the consequence action last; long titles wrap and never truncate.

Accessibility

Role and pattern

Dialogs, sheets and the lightbox are modal dialogs (APG Dialog (Modal)) with aria-modal="true", a title in aria-labelledby and the consequence or rule in aria-describedby. The map popup is a non-modal role="dialog" tied to a marker with aria-haspopup="dialog" and aria-expanded. The picker is an APG Combobox with a listbox.

Keyboard

Tab / Shift+TabCycles inside the open modal overlay only.

Focus

Focus starts on the safe choice (Cancel, Stay, OK, Got it), on Close in sheets and the lightbox, and in the search field in the picker. It never starts on Delete studio, Discard or Remove test shot. On close it returns to the invoking control; if that control is gone (after Delete) it goes to the new page's main landmark.

Labelling

Titles name the item ("Unpublish The Junction Loft?"); Close buttons are icon buttons named "Close"; lightbox arrows are "Previous photo" and "Next photo"; "View the review" carries the studio name in hidden text.

Motion

Dialogs scale in, sheets slide; reduced motion removes both. The lightbox fades in only.

Touch

Close and the lightbox arrows are 44px targets; footer buttons are 44px tall and 12px apart; the docked popup keeps its Close clear of the map edge.

Content

  • Titles are a question naming the item: "Delete Corktown Garage Studio?", "Unpublish The Junction Loft?", "Remove test shot 2?", "Discard changes?". Refusals state the fact: "Can't publish yet", "Can't remove this test shot".
  • Descriptions give the consequence and the way back: "It goes back to draft… You can publish it again any time." "It can't be undone." "It's removed when you save the studio."
  • Consequence buttons repeat the verb and the thing: "Delete studio", "Remove test shot", "Unpublish", "Discard". The safe button is "Cancel", or "Stay" when leaving is the risk.
  • Failures inside a dialog say nothing changed: "We couldn't unpublish it. Nothing changed. Try again."

Drift fixed during extraction: the mocks draw Close, Cancel and the consequence actions as links back to other mocks; in the product they are <button>s (Close an icon button named "Close"). The unpublish and delete busy states swap Close from a link to a disabled button; the system always uses a button so it can be disabled. Toasts after Unpublish nest a role="alert" inside a role="status" region; see Notifications. The map popup is written with inline left/top for its marker; that is positioning data, not styling. Dialog headings are h2 in the mocks, which is right for a dialog; inside this documentation they are shown one level down.
