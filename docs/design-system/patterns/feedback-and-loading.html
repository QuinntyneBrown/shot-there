Pattern

Feedback and loading

While something loads, ShotThere holds its shape with skeletons; while a request is in flight, the button that sent it is busy; when it lands, the result shows where the eye already is. Local choices like Compare are instant. Anything that changes the public site waits for the server.

Overview

Feedback answers two questions: is it working? and did it work? ShotThere uses a small set of tools for both, each with one job:

  • Skeleton: a region is loading. It copies the shape of what will arrive (cards, rows, tiles, editor sections) so nothing jumps when it does.
  • Busy button (aria-busy="true" plus disabled): a request this button sent is in flight. The label stays; a spinner replaces it visually.
  • Progress bar: a measurable wait, only for image uploads.
  • Spinner: a short, unmeasured wait inside a control, only for the entry picker's search.
  • Save status line (.save-status): the editor's running answer to "is this saved?".
  • Toast: the result of an action whose own control can't show it (Copy link, the compare limit, Publish, Unpublish, a failed save). See Notifications for persistence.
  • Alert or a changed view: a result that belongs to the page (Studio created as a draft, You're subscribed).

Public pages arrive server-rendered with their content in the HTML, so a first visit never shows a skeleton. Loading states appear only for client-side refreshes that take longer than 300 ms.

Responsive behaviour

  • Skeleton counts follow the grid: six cards, which is one column at XS, two from SM and two rows of three at LG; admin lists show five skeleton rows that stack as cards below 48rem like the real rows.
  • Toasts span the width with a 16px gutter on phones and sit bottom-right (24rem) from 36rem. On pages with the compare bar the region is raised above the bar so it never covers Compare.
  • The sticky save bar keeps the status line beside the buttons; on narrow phones it wraps under them.
  • Upload rows put the actions under the thumbnail below 48rem and in a column beside it from 48rem; the progress bar always spans the row body.

Accessibility

Role and pattern

Loading regions use aria-busy="true" and a separate polite role="status" message; skeleton shapes are aria-hidden. Upload bars are role="progressbar" with a name ("Uploading gallery-02.jpg"). Busy buttons are native buttons with aria-busy and disabled. Results use the live regions described in Notifications.

Keyboard

KeyAction
TabSkips skeletons and disabled busy buttons; filters and sort stay reachable while the list loads.
EscIgnored by a busy confirmation dialog until the server answers.
Enter on Retry or Try againRe-sends the same request (same file, same filters).

Focus

Loading never moves focus. When a busy dialog finishes, it closes and focus returns to the invoking control (Unpublish), or the next screen opens with focus on its main landmark (after Delete). When an upload finishes, focus moves to that image's alt-text field. A Compare toggle refused at the limit keeps focus.

Labelling

Status messages name the thing: "Loading studios…", "Loading studio…", "Unpublishing The Junction Loft…", "Uploading gallery-02.jpg". A disabled Save changes points at its reason with aria-describedby ("Wait for uploads to finish").

Skeletons are decorative and carry no contrast requirement; the hidden status carries the meaning.

Motion

Under reduced motion the skeleton shimmer stops; the spinner keeps turning because it reports status. Toasts appear without sliding.

Touch

Retry, Remove and Cancel upload are 44px tall below 48rem. A toast's dismiss button grows to 44px on phones.

Content

  • Loading: "Loading thing…" with an ellipsis character: "Loading studios…", "Loading locations…", "Loading studio…".
  • In progress: present participle, no subject: "Saving…", "Signing in", "Searching…", "Uploading… 45%".
  • Done: the fact, with the time when it matters: "Saved 13 Oct 2026, 10:02 am", "All changes saved", "Link copied", "Corktown Garage Studio is published".
  • Blocked: say what to wait for: "Wait for uploads to finish".
  • Failed: what didn't happen, what was kept, what to do: "gallery-04.jpg didn't upload. Check your connection." "Your changes are still here. Check your connection and try again."
