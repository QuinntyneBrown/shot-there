Pattern

Navigation and page structure

ShotThere has two small chromes: the public site, where visitors browse, read a review and compare; and the admin, where the founder keeps studios, spots and guides up to date. Both use the same header, collapse to the same Menu sheet on phones, and keep every view in the URL so it can be shared, reloaded and reached with Back.

Overview

  • Visitor chrome: site header with the wordmark and its "Toronto" tag, then Studios, Spots, Map, Compare and Guides in a <nav aria-label="Primary">; the footer repeats Studios, Spots, Guides, Editorial policy and the YouTube channel beside a secondary email signup.
  • Admin chrome: the same header with the "Admin" tag, then Dashboard, Studios, Spots, Guides, View site and Sign out in <nav aria-label="Administration">. No footer signup.
  • Phones (below 48rem): the links collapse into one Menu button that opens the site menu, a full-height sheet of .section-link rows with a one-line description each.
  • Where am I: aria-current="page" on the header link for the section (a studio review marks Studios), a breadcrumb on every review and editor, and the page <h1>.
  • Every view is a URL. Filters, sort, compared studios and the map view live in the query string; paths and page titles come from one central place (APP_PATHS, PAGE_TITLES), never typed inline.
  • Every page starts with the skip link ("Skip to content") to main#main.

Responsive behaviour

  • Below 48rem: header links (.site-nav__extra) hide and Menu (.site-nav__menu) shows; the menu is a full-height sheet that respects the top and bottom safe areas. Below 24rem the wordmark's tag hides so the header never scrolls sideways.
  • From 48rem: all links sit in the header; the sheet is not used.
  • Breadcrumbs wrap; the current crumb keeps its full name.
  • The compare bar is fixed to the bottom at every width, clears the home indicator, and the page pads its end so the last card and the footer stay visible.
  • The map page drops the footer and fills the viewport under the header; below LG the Map / List toggle switches views.

Accessibility

Role and pattern

Landmarks on every page: header, nav with distinct names ("Primary", "Administration", "Breadcrumb", "Footer", "About ShotThere"), one main, footer. The menu is a modal dialog (APG Dialog (Modal)) holding navigation lists; the breadcrumb follows the APG Breadcrumb pattern.

Keyboard

KeyAction
Tab from the top"Skip to content" first, then the wordmark, then the header links or Menu.
Enter on MenuOpens the sheet; focus moves to Close.
EscCloses the menu and returns focus to Menu.
Browser BackRestores the previous filters, sort or map view.

Focus

On a route change focus moves to main (which has tabindex="-1" and shows no ring). Opening the menu traps focus inside it; the page behind is inert.

Labelling

The current page is marked with aria-current="page" in the header, the menu and the breadcrumb, never by colour alone (it is also semibold). Menu says "Menu" in text beside its icon.

Motion

Touch

Header links and Menu are 44px tall and 8px apart on phones; menu rows are 72px tall.

Content

  • Navigation labels are the plural nouns of the catalogue: Studios, Spots, Guides; plus Map, Compare, Dashboard, View site, Sign out. Use "Spots" in navigation and "outdoor spots" in sentences ("Browse outdoor spots").
  • Menu descriptions give a fact, not a slogan: "7 rental studios, measured the same way", "Up to 4 studios side by side", "2 items need re-verifying".
  • Breadcrumbs use the list name and the item's own name, never "Home" or "Edit".
  • Back actions name the destination: "Back to studios", "Back to dashboard", "Go to the home page".

Drift fixed during extraction: the compare bar's actions are Clear then Compare on the lists but Compare then Clear on the review page, and its landmark is "Studios to compare" in one and "Comparison" in the other; the system uses Clear, Compare and "Studios to compare". Counts read "7 published, 2 draft" (dashboard), "7 published · 2 drafts" (admin menu) and "7 published · 2 draft" (admin list header); the system uses the dashboard's form. The admin menu in the mock omits the header's View site link from its inert copy of the header; harmless, but the real header always has it. Menu is drawn as a link to the dialog mock; in the product it is a <button> with aria-expanded.
