Pattern

Empty and error states

An empty or failed region on ShotThere says what is missing, why, and the one thing to do next, in the place the content would have been. Filters, chrome and everything that did load stay put, and nothing typed or chosen is lost.

Overview

Three families, each with its own tool:

  • Nothing here yet (first run, a section with nothing to show): the empty state (.empty, .empty--compact inside a section). ShotThere only lists places it has shot, so "empty" always means "not reviewed yet", never "nothing exists".
  • Nothing matches (filters or a search): a compact empty state under the active filter chips or the search box, with the action that undoes the narrowing: Clear filters, Clear search.
  • Something failed: .empty--error where a whole region failed, an alert where part of a screen failed or the server refused (rate limited, session expired, partial dashboard), .media-fallback and .map-unavailable where an image or the map tiles failed, and the error page (.system-page) for 404 and 500.

Every one follows the same formula: an icon that is decoration, a title that names the thing ("No studios match these filters", "We couldn't load the studios"), one sentence on why or what happens next, and at most two actions, the first being the way forward.

Responsive behaviour

  • Empty states centre in their region, text capped at 36ch, actions wrapping and centred; nothing overflows at 320px.
  • On the map page the empty and error cards float over the tiles, centred, at most 24rem wide; below LG the map/list toggle stays usable.
  • Map tiles failing below LG offer "Show the list"; from LG the list is already beside the message, so the button is hidden (.until-lg).
  • .media-fallback fills the slot the image would have had (3:2 hero, 4:5 shot, 16:9 poster), so nothing shifts; long alt text wraps.
  • The 404 and 500 pages use .system-page (34rem, centred) and stay readable with no horizontal scroll at XS.

Accessibility

Role and pattern

Empty states are plain content with a heading at the region's level; no live role, because the result count (role="status", "0 studios") already announced the change. Error states that replace content after a request carry role="alert". Alerts for compare links and session expiry are role="status" (information, not failure); rate limits are role="alert".

Keyboard

KeyAction
TabReaches the remaining filter chips' remove buttons, then the empty state's action.
Enter on Try againRe-sends the same request; focus stays on the button while it loads.

Focus

Empty and error states never steal focus, except on a full page (404, 500, editor error), where focus lands on the main landmark like any page load. After Clear filters or Clear search, focus moves to the first result or stays on the search box.

Labelling

Icons are decoration (aria-hidden on the icon wrapper). Fallback images show their alt text as visible text, so the meaning survives the failure. External links say "(opens in a new tab)" in hidden text.

Content

  • Empty: say what isn't here yet and why, in ShotThere's terms: "No studio reviews yet. The first reviews are being shot now. Each one goes up only after a full test shoot." Never "No data".
  • No results: "No things match these filters" or "No studios match “parkdale”", then how to widen: "Try removing a filter, or clear them all to see all 7 studios."
  • Failure: "We couldn't verb the thing", then what is safe and what to do: "Nothing has changed. Check your connection, then try again." "Your content is safe."
  • Partial: say what did load: "The counts above are current."
  • Actions are the way forward: Clear filters, Clear search, Try again, Browse studios, Browse outdoor spots, New studio, Back to dashboard, Go to the home page.

Drift fixed during extraction: load errors carry role="alert" on the public lists and map but not on the dashboard and admin lists; the system gives every content-replacing error role="alert". Some mocks hide the empty-state icon on its wrapper and others only on the SVG; the system hides the wrapper. The map's empty and error cards are styled inline (surface, radius, shadow, max width); listed as a CSS need. The 404 page puts its code above the title while the 500 page puts its reference below the text; both are kept, since the 404 code orients and the 500 reference is for quoting.
