Layout

Mobile first, from 320px to 2560px. Five viewport classes from the L2 requirements, a 4, 8 and 12 column grid, and nine page templates that every ShotThere screen is built from.

Overview

Photographers scout on their phones, often on location, so every layout starts as a single column at 320px and adds columns, side regions and wider margins as space allows. The viewport classes come straight from the L2 requirements (XS, SM, MD, LG, XL), so a criterion such as "at LG and above the filters are shown in a sidebar" (L2-022.5) maps to exactly one breakpoint in the CSS.

The layout tier (--layout-*) sits on top of the spacing scale. Columns, gutter, margin, header height and section gap are redefined at each breakpoint in tokens.css; components read the tokens and never need their own media query for these values.

  • Phone (XS): one column, 16px margins, links behind "Menu", filters behind "Filters", the summary panel straight after the photo, tables as stacked cards, the map with a Map / List toggle, the compare bar fixed to the bottom.
  • Tablet (SM–MD): two-up location grids, dialogs centred, 32px margins and the inline site nav from MD, side sheets for filters and the menu.
  • Desktop (LG–XL): the filter column appears beside the list, the summary panel sticks beside a review, the map list sits beside the map, and the editors gain a sticky status aside.

Viewport classes and breakpoints

L2 defines the classes by CSS pixel width: XS < 576px, SM ≥ 576px, MD ≥ 768px, LG ≥ 992px, XL ≥ 1200px. The system adds 2XL at 1440px, where the container stops growing. All queries are min-width (mobile first). Media queries cannot read custom properties, so components write these values literally, and only these values; "below" rules use the breakpoint minus 0.01rem (for example max-width: 61.99rem).

The column grid is a guide, not a cage. Most ShotThere screens use purpose-made layouts (the location grid, the review layout, the map page, the editor layout) whose tracks line up with the grid at each class; use .grid with .span-full for anything new, and .grid--auto (cards at least 18rem wide) for card collections.

Location grid

Studio and spot cards go 1 / 2 / 2 / 3 / 3 across XS / SM / MD / LG / XL on the home page and in the guides, with gaps growing from 40 × 24px to 48 × 32px. Beside the filter column on the studio and spot lists the grid is 1 / 2 / 2 / 2 / 3, because a 15rem column plus three cards would make each photo too small at 992px. L2-021.4 asks for three columns "at LG and above"; the lists meet it from XL only, an open question for the requirements.

Container and measure

.container centres content, caps it at --layout-container-max (1440px including margins, so 1280px of content at XL margins, as L2-064.3 requires) and pads it with --layout-margin. Beyond 1440px the page simply gets wider margins: nothing stretches across a 2560px monitor.

--layout-measure (62ch) caps every paragraph, so a verdict or guide note never runs wider than about 12 words even inside a wide container. Narrower containers exist for focused tasks:

Usage

  • Start from a template. A new screen is one of the nine templates; if it is not, the structure belongs on the navigation and page structure pattern first.
  • Write mobile first. Base styles are XS; add @media (min-width: 36rem | 48rem | 62rem | 75rem) only. No other breakpoint values.
  • Read layout tokens, not numbers. Pad with --layout-margin, gap with --layout-gutter; they already change per class.
  • Let regions appear, not shrink. The filter column, summary panel, map list and editor aside are either present at full width (LG and up) or moved: into a dialog, above the content, or behind a toggle. Never squeeze a 15rem column onto a phone.
  • Keep content in the container. Only the map page, the lightbox and the compare bar's background run edge to edge.
  • Use min-width: 0 on grid children that hold long names or tables (.browse__results, .review-main, .editor-form already do) so they cannot force the page wider; wide tables scroll inside .table-wrap.
  • Use 100dvh for the map, sheets and the lightbox so phone browser bars do not clip them.
  • Reserve room for fixed bars. A page that can show the compare bar adds .has-compare-bar.

Accessibility

  • Reflow (1.4.10, L2-064.1). At 320px document.documentElement.scrollWidth equals the viewport width on every screen; the compare table and admin tables scroll inside their own region.
  • Zoom (L2-066.1). At 200% in a 1280px window the page is 640 CSS px wide and gets the SM layout, with every function available.
  • Orientation (1.3.4, L2-066.2). Layouts work in portrait and landscape; the map in landscape at SM keeps its toggle usable and the header under 25% of the height.
  • Focus not obscured (2.4.11). The fixed compare bar never covers the focused element: pages reserve bottom padding, and scroll-padding-top uses --layout-topbar-height so anchors land below the header.
  • Safe areas (L2-065.1). The header adds env(safe-area-inset-top); the compare bar, sheets and the lightbox caption add env(safe-area-inset-bottom); pages set viewport-fit=cover.
  • Source order matches visual order. On phones the summary panel is moved above the review sections with order: -1; in the DOM it follows them, so screen-reader users meet the sections first while sighted phone users see the price first. This is the one deliberate exception, and both orders keep the heading outline intact.
  • Landmarks (L2-069.1). Every template has one <header>, one <main id="main"> reached by the skip link, the filter column and summary panel as labelled <aside>s, the compare bar as a labelled <aside>, and on public screens a <footer>.
