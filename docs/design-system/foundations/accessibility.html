Accessibility

ShotThere meets WCAG 2.2 AA by construction: the tokens, components and checks below make the accessible choice the default one, so a review page, a comparison or an editor built from the system starts compliant.

Overview

Photographers, models, clients and small crews choose a studio or a spot on whatever is in their hand: a phone on the streetcar, a laptop the night before, sometimes with a screen reader, magnification, a switch or a keyboard. The owner publishes every review from the same admin screens. The target is WCAG 2.2 AA (AGENTS.md, L2-069.4) for both the visitor and the admin.

  • Built in, not bolted on. Contrast is solved in the tokens (every pair is checked in both themes), focus is one shared ring, the default control is 44px tall, and reduced motion is a token change.
  • Never colour alone. A score is a number with pips, a light level is a word with pips, a map marker is a shape with a legend and a list, a stale price says "Prices may be out of date".
  • Native first. Real <button>, <a>, <label>, <input>, <table>, <details>; ARIA only fills gaps, following the WAI-ARIA Authoring Practices pattern named on each component page.
  • Every component page answers the same seven questions (see the contract), so nothing is left to the implementer's memory.

Text spacing1.4.12Nothing clips at 1.5 line height, 2× paragraph spacing, 0.12em letter and 0.16em word spacing: no fixed heights on text, long studio and guide names wrap.
Orientation; animation1.3.4, 2.3.3Portrait and landscape everywhere (L2-066). Motion follows reduced motion.

Titles and headings2.4.2, 2.4.6A unique <title> that names the location, guide or screen; the comparison title names every studio compared (L2-033.2). One <h1> per page.
Link purpose2.4.4Link text makes sense alone: "Read the full review of Kensington Window Room", "View the review: The Junction Loft". Repeated actions add the object in a visually hidden span ("Edit Ossington Blackbox prices", "Remove test shot 2"). Links that open a new tab say "(opens in a new tab)".
Pointer cancellation2.5.2Actions fire on click, never on pointer down.
Hover and focus content1.4.13ShotThere shows no content on hover alone. The map popup opens on activation, stays until closed, and closes with Escape.

Checklist for every screen

  • One <h1>, one main, a unique title and a working "Skip to content" link.
  • Every informative image has alt text describing what it shows; thumbnails beside their name have alt="".
  • Every score, light level, permit and stale flag is in words or numbers, not only pips, shapes or colour.
  • Every control has a visible label or an accessible name naming its object.
  • Tab order follows reading order at 360px and at 1280px.
  • No sideways page scroll at 320px; nothing lost at 200% zoom.
  • Overlays move focus in, trap it, close on Escape and return focus.
  • Errors are summarised, linked, tied to their fields and announced.

Focus

One focus ring serves every interactive element: a 2px outline in --color-focus-ring (the accent red, the "you are here" colour), drawn 3px outside the element so it never touches the fill. Inputs draw it at 0 offset; on the inverse toast it switches to the toast's text colour; a location card draws it around the whole card. It appears only for keyboard focus (:focus-visible), never on mouse click.

Target sizes

The default control is 44px tall (--control-height-md), so most buttons, fields, header links, segmented options, icon buttons and map markers already meet the phone target. Two tokens set the floor and the comfortable size (L2-065).

24px floor (--target-min) · 44px comfortable (--target-comfortable) · a 44px icon button · a 44px button · a small button, 36px from 48rem and 44px below it

The visible glyph can be smaller than the target: a 24px marker square sits centred in a 44px .map-marker, a 20px cross in a 44px close button, and a checkbox's whole label row is its target. Never shrink padding to fit more controls in a row on a phone; wrap them instead, as the image-row actions do.

Testing procedure

Automated

  1. Contrast. check_contrast.py checks every pair in tokens/contrast-pairs.json against tokens.css in light and dark. Both must exit 0. Add a pair whenever a component puts a new foreground on a new background.
  2. Structure. check_design_system.py checks every page for lang, one <h1>, a main landmark, labels on every field, names on every button and link, alt on every image, resolving links and no raw colours.
  3. Product screens. axe-core with WCAG 2.2 A and AA rules on every public and administration screen in its default state, plus open dialogs, the lightbox, errors and empty states; any violation fails CI (L2-069.4). Playwright runs in Chromium only.

Manual, for every new component or screen

  1. Keyboard. Unplug the mouse. Tab through a studio page, the comparison, the map and an editor: is the ring always visible and the order sensible? Open and close the filters, the lightbox and a confirmation with Enter and Escape; does focus come back? Open a map popup from a marker and close it.
  2. Screen reader. NVDA with Chrome on Windows and VoiceOver on iOS Safari. Check the verdict scores ("Light: 5 out of 5"), the compare toggle and bar, the comparison table's headers, the lightbox name and count, and one form with errors.
  3. Zoom. 200% in a 1280px window (nothing lost, L2-066.1) and 400% (equivalent to 320px: reflow, no sideways scroll except tables).
  4. Reduced motion. Emulate prefers-reduced-motion: reduce; nothing slides, scales or shimmers, and busy spinners still turn.
  5. Forced colours. Emulate forced-colors: active; controls keep visible edges, the ring uses Highlight, pressed segments are underlined, and markers are still told apart by shape.
  6. Touch. On a real phone at 360px, check every target is 44px, the compare bar clears the home indicator, and nothing depends on hover.
  7. Text spacing. Apply the 1.4.12 bookmarklet; nothing clips or overlaps.

The component contract

Every component page has an #accessibility section with the same seven parts, in this order. A component is not "stable" until all seven are written and true.

PartWhat it answers
1. Role and patternThe native element or ARIA pattern used, named from the WAI-ARIA Authoring Practices (dialog for the lightbox and filters, button with aria-pressed for the compare toggle, table for the comparison).
2. KeyboardA key map: Tab, Shift+Tab, Enter, Space, Escape and any arrows, with the effect of each.
3. FocusWhere focus starts, where it goes on close or removal, and how the ring is drawn.
4. LabellingWhat must be labelled, how, and what a screen reader announces.
5. ContrastThe token pairs involved with live ratios in both themes; every pair exists in contrast-pairs.json.
6. MotionWhat animates, with which tokens, and what happens with reduced motion.
7. TouchTarget sizes at each breakpoint, spacing, and the alternative to any hover behaviour.

Usage

  • Never remove the focus outline, and never replace it with a colour change alone.
  • Never use tabindex above 0; use tabindex="-1" only on things that receive focus by script (main after the skip link, the error summary).
  • Never put information only in pips, a marker colour, a placeholder or a photo.
  • Never publish an image without alt text, and never write "photo of" or the file name as alt.
  • Never auto-dismiss an error, and never move focus without a reason the person caused.
  • When in doubt, use the native element and the component's existing markup; it already passes.
