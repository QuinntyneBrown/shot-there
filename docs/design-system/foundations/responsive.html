Foundation

Responsive

People check a studio's price on the way to a shoot and scout a spot standing in it, so every ShotThere screen is designed at 360px first. Wider screens add columns, a filter sidebar, a sticky summary and the map beside its list, without ever scrolling sideways down to 320px.

Overview

Base styles are the phone layout. Breakpoints only add: a second and third column of studio cards, the summary panel beside the review, the filter sidebar beside the list, the list beside the map. Nothing is designed at desktop width and squeezed down.

  • 360px is the design width. Every mock is drawn there first. 320px must still work: document.documentElement.scrollWidth equals the viewport width on every screen (L2-064.1).
  • Breakpoints are in rem and use min-width, so they follow the person's text size. "Hide below" rules use the breakpoint minus 0.01rem.
  • Tokens change, components follow. --layout-columns, --layout-gutter, --layout-margin, --layout-topbar-height and the display type sizes change at 48rem, 62rem and 75rem in tokens.css; components read them instead of writing their own queries where they can (values on Layout).
  • Content stops at 1280px. From XL the container holds content to 1280px and centres it (L2-064.3).

Touch, pointer and the device

  • Targets. Every target is at least 24 × 24px everywhere (L2-065.2). Below 48rem the primary navigation, filter controls, form submit buttons and every other control are at least 44px tall with 8px between neighbours (L2-065.3): the compare toggle on a card, Move up and Move down and toast Dismiss all grow; map markers are 44px at every width. See target sizes.
  • No hover dependency. Hover only adds polish (the photo zoom, a darker link). Admin row actions are always visible on touch screens (@media (hover: none)). ShotThere has no tooltips.
  • (pointer: coarse) is not used to grow targets. They are already large enough below 48rem; growing them per device makes layouts shift unpredictably.
  • Safe areas. Pages set viewport-fit=cover. Fixed and sticky bottom elements add env(safe-area-inset-bottom) to their padding: the compare bar (L2-065.1), dialog panels, sheet footers, the lightbox caption, toasts and the site footer. The site header, sheet headers and the lightbox bar add env(safe-area-inset-top).
  • Dynamic viewport height. Full-height layouts use 100dvh (page shell, dialog max height, the map page, the lightbox photo) so mobile browser chrome never hides "Show 7 studios" or the map toggle.
  • Keyboards on screen. Fields bring up the right keyboard: type="email" with inputmode="email" for signup, inputmode="decimal" for cost and rate, type="date" for "Prices last verified", type="url" for booking and permit links.
  • Rotation. Portrait and landscape both work; in landscape at SM the map and its toggle stay usable and the 64px header stays under 25% of the height (L2-066.2).
  • Swipe is never the only way. The lightbox steps through photos with its Previous and Next buttons, never a swipe alone; the comparison table scrolls with a trackpad, a scrollbar or the keyboard once focused.

Usage

  • Write the phone layout as the base rule, then add @media (min-width: 36rem | 48rem | 62rem | 75rem). Use max-width only for "below" rules, as 47.99rem and so on.
  • Prefer intrinsic layouts (flex-wrap, minmax(0, 1fr), min(100%, …)) to a new breakpoint.
  • Never add a breakpoint value outside the scale. If a component breaks between two breakpoints, fix the component.
  • Long names wrap (overflow-wrap: anywhere on card and review names): "Allan Gardens Conservatory" and "Best studios under $120 for 2 hours" must fit at 320px. Never truncate a price, a score, an error or a date; only the compare bar's list of names may end in an ellipsis, because the count above it says how many.
  • Keep DOM order equal to reading order at every size. Reordering with order or grid placement must not change what a screen reader or the Tab key meets first.
  • Spacing never scales with viewport width; the token changes at a breakpoint.

Accessibility

  • Reflow (1.4.10). Content reflows at 320px CSS width, which is also what 400% zoom on a 1280px window produces. Only the comparison and other data tables scroll sideways, inside their wrapper.
  • Resize text (1.4.4). Because breakpoints are in rem, doubling the text size moves layouts to their narrower form instead of overflowing. A studio page at 200% zoom in a 1280px window keeps every control reachable with no sideways page scroll (L2-066.1).
  • Orientation (1.3.4). Both orientations work everywhere.
  • Focus not obscured (2.4.11). The compare bar reserves its height with .has-compare-bar bottom padding, and toasts on pages with the bar sit above it, so focused content is never hidden behind them.
  • Same content, same names. The phone and desktop forms of a component (filters sheet and filter sidebar; lightbox pager and arrows; map list and map) expose the same options with the same accessible names.
  • Reading order. Below LG the summary panel is moved before the review sections with CSS order. The panel must also come first in the DOM, or screen-reader and keyboard users meet it last while sighted users see it first.

Tokens

Responsive behaviour has no tokens of its own. The breakpoint, column, gutter, margin, container, sidebar, panel, dialog, sheet and header tokens (--layout-*) are documented on Layout; the target sizes on Accessibility; the display type sizes that grow at 62rem on Typography.

Drift found during extraction: below LG the summary panel on review pages is moved above the review sections by CSS order while it stays last in the DOM; the toast above the compare bar is lifted by an inline style in notifications/public-toast/warning rather than a class. Both are reported for a fix in the mocks and the stylesheet.
