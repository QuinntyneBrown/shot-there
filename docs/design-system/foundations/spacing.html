Foundation

Spacing

White space is ShotThere's main divider. A 4px scale, tight inside a location card or a fact list and generous between review sections, lets a long review read as a few calm blocks instead of a wall of boxes.

Overview

The ShotThere mocks separate things with space, not lines: a wide gap between the filter column and the location grid, big rows between location cards, 64px between the sections of a review, and a short gap between a studio's name and its "neighbourhood · reviewed" line. The spacing scale encodes that rhythm so every screen uses the same handful of distances.

The scale is built on 4px (0.25rem). Token names are multiples of the base: --space-4 is 4 × 4px = 16px. Small steps are dense (2, 4, 8, 12, 16, 20, 24px) for component internals; large steps jump (32, 40, 48, 64, 80, 96, 128px) for layout. All values are rem, so spacing grows with the visitor's text size.

Spacing tokens are fixed; what changes with the viewport is the layout tier built on them (--layout-gutter, --layout-margin, --layout-section-gap), documented on Layout.

Inside versus between

One rule decides almost every gap: space inside a group is smaller than the space between groups. A studio's name sits 8px above its meta line, the photo 16px above the name, and the next card starts 40px below (48px from 62rem). The eye groups by proximity, so a location card needs no border or shadow.

Control heights

Three heights for everything a visitor or the admin can press or type into, so a button, an input and a select line up in one row. Medium (44px) is the default because it already meets the phone target (L2-065.3). Small (36px) is a desktop density, from 48rem only: below 48rem every compact control grows to 44px through one rule at the end of components.css, so phones never get a target under 44 × 44px.

Usage

  • Use the tokens. Every margin, padding and gap is a --space-* token. If a design needs 14px, it needs 12 or 16.
  • Use gap, not margins, inside components. .stack (16px), .stack--sm (8px), .stack--lg (32px) and .cluster (12px) set rhythm without margin-collapse surprises.
  • Separate with space before lines. Reach for a bigger gap first; add a hairline only where space alone is ambiguous (fact rows in .kv, score rows, table rows, admin rows).
  • Grow between, not inside. On larger screens the layout gaps grow (gutters, margins, grid gaps); component padding stays the same.
  • Keep controls on the height scale. Do not stretch a button with padding; choose sm, md or lg.
  • Respect safe areas. The compare bar adds env(safe-area-inset-bottom) to its bottom padding, and pages that show it add the same to their own bottom padding (.has-compare-bar) so the last card is never hidden (L2-030.6, L2-065.1).

Accessibility

  • Target size (2.5.8, L2-065). Nothing is smaller than 24 × 24px anywhere (L2-065.2); at XS and SM every navigation link, filter control, compare toggle and submit button is at least 44px tall (L2-065.3), with at least 8px (--space-2) between neighbouring targets. Map markers are 44 × 44px hit areas around a 24px mark.
  • Spacing survives text resizing. Because every value is rem, a visitor who sets 20px text gets proportionally larger gaps and taller controls, and nothing overlaps.
  • Text spacing (1.4.12). No component uses a fixed height for text, only min-height, so overriding line, word and letter spacing never clips content.
  • Focus has room. The focus ring sits 3px outside the element (8px outside a location card); gaps of at least --space-2 between controls keep neighbouring rings from overlapping.
  • Nothing hides under the compare bar. The page's bottom padding reserves the bar's height, so the last card and the footer stay reachable and a focused control is never covered (2.4.11).
