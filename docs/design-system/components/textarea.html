Textarea

Room to write a few sentences: who a studio is for and who should skip it, a guide's introduction, the editor's note on each guide entry, how to get to a spot. It shares the text field's look and grows by rows, not by size modifiers.

Overview

Use a textarea when the answer is prose that visitors will read on the public page. Only the owner writes in ShotThere, so every textarea is in an editor:

  • Verdict in the studio editor: "Who it's for" and "Who should skip it", the two lines visitors read first on a studio review.
  • Introduction in the guide editor, shown above the ranked entries.
  • Editor's note on each guide entry: one or two sentences on why it is ranked there.
  • How to get there in the spot editor: Transit, Driving and Walking.

A short phrase that fits on one line ("Shared, down the hall", "Bench for 3") is a text field. A textarea always sits in a form field. No ShotThere textarea has a character limit, so none shows a counter; if a limit is added, use the field's counter.

Anatomy

  1. LabelFrom the form field: label.field__label above the box.
  2. Text area--text-body (16px) in --field-fg; padding --space-2 --space-3; --radius-md; 1px --field-border edge; at least --control-height-md tall (44px); rows sets the starting height.
  3. Resize handleresize: vertical: the owner can make it taller, never wider than the column.

The Corktown Garage Studio verdict in pages/studio-editor/default.

Variants

There is one textarea. What changes from use to use is the number of rows and whether the label needs a visually hidden suffix.

Verdict and introduction

The Junction Loft's verdict (pages/studio-editor/published) and the "Best studios under $120 for 2 hours" introduction (pages/guide-editor/published).
HTML
<div class="field">
  <label class="field__label" for="verdictFor">Who it's for</label>
  <textarea class="textarea" id="verdictFor" name="verdictFor" rows="3"></textarea>
</div>

Editor's note on a guide entry

"Best for headshots" in pages/guide-editor/default. Every entry has the same visible label, so a visually hidden suffix names the entry: screen readers hear "Editor's note for Kensington Window Room".
HTML
<label class="field__label" for="note-1">Editor's note<span class="visually-hidden"> for Kensington Window Room</span></label>
<textarea class="textarea" id="note-1" name="entries[1].note" rows="2"></textarea>

Directions

Evergreen Brick Works in pages/spot-editor/published, under the "How to get there" section heading.

Sizes

A textarea has no size modifiers; its height comes from rows, over a 44px minimum. Text is always 16px.

UseRowsLimit
Introduction (guide)4None
Who it's for, Who should skip it (studio)3None
Editor's note (guide entry)2None
Transit, Driving, Walking (spot)2None

The minimum is one control height (--control-height-md, 44px), shorter than any row count in use, so rows="2", "3" and "4" each open at their own height.

States

Hover and focus are forced with data-state; invalid, disabled and read-only use aria-invalid, disabled and readonly. No mock shows a textarea error, disabled or read-only; those cells use the same rules as the text field so they are ready when needed.

With its message

Write who this studio is for
No mock shows this error; it follows the editors' wording ("Describe this image", "Enter a title"): a verb, then what is missing.

Both themes

  • Hover darkens the edge; focus draws the 2px accent ring flush with it. Neither changes the size, so the text never jumps.
  • Invalid doubles the edge in danger red and always comes with a .field__error under the box.
  • While saving, the editors keep every textarea editable and show "Saving…" in the sticky actions (pages/studio-editor/submitting).

Responsive behaviour

  • Full width of its column at every breakpoint; in the guide editor the note sits in the entry row beside the rank and the move buttons, and takes the row's remaining width.
  • Long text wraps inside the box; there is never a horizontal scrollbar. The owner can drag it taller; the page grows with it.
  • 16px text at every width, so phones don't zoom on focus.

Theming

The textarea shares --field-bg, --field-border and --field-fg with the text field, and every state overrides those tokens. It adds only its minimum height and resize: vertical. In dark the fill follows the page, the stone edge keeps 3:1, and the ring and invalid edge move to their lighter steps.

Accessibility

Role and pattern

Native <textarea> (a multi-line textbox) with a <label for>. Errors set aria-invalid="true" and are referenced from aria-describedby (L2-069.2).

Keyboard

KeyAction
Tab / Shift+TabMoves into and out of the textarea; Tab never inserts a tab character.
EnterInserts a new line. It never submits the editor; Save changes does.
Arrow keys, Home, EndMove the caret (browser behaviour).

Focus

The ring sits flush on the edge (offset 0) and the edge turns accent red: 2px at 3:1 or more (L2-067.2). From the error summary, the link moves focus into the textarea.

Labelling

A visible label always. Repeated labels get a visually hidden suffix ("Editor's note for Leslieville Daylight Studio") so each accessible name is unique and still starts with the visible words (WCAG 2.5.3).

Motion

Edge colour transitions over --duration-fast; reduced motion zeroes it. Resizing is direct, never animated.

Touch

Even at two rows the box is taller than the 44px target, and tapping the label focuses it. The resize handle is a pointer convenience; nothing depends on it.

Content

  • The verdict names people, not features: "Portrait and fashion shooters who want…", "Video crews and anyone hauling heavy cases."
  • Editor's notes give the reason for the rank in one or two sentences, with the number that matters: "$80.00 all-in. The cheapest good window in the city; book mornings."
  • Directions start with the route, then the walk: "TTC 28A shuttle from Davisville or Broadview station." Use TTC route numbers and station names as the TTC writes them.
  • Canadian spelling, metric first, prices with cents ($120.00).
