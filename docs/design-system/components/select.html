Select

A native dropdown for one answer from a short, fixed list: how to sort the studios, which way the windows face, how strong the morning light is, whether a fee is mandatory. The phone's own picker does the hard work.

Overview

Use a select when there is exactly one answer, the options are known and fixed, and showing them all at once would crowd the form. ShotThere uses it for:

  • Sort order on the studio list: Most recent review, All-in cost, low to high, Overall score, high to low (L2-023). It sits inline above the results and at the top of the filters dialog.
  • Filters: Minimum usable space (Any size, 20 m² or more, 30 m² or more, 50 m² or more).
  • Editor facts from a fixed set: window direction, natural light for each time of day (None, Low, Medium, Strong), cyc wall, load-in, parking, fee type (Mandatory, Optional), gear category, spot type, permit status per shoot type, weekday and weekend crowds.

When the options must be compared before choosing, or there are only two or three, use a radio group (parking in the filters, the disclosure answer). When people type to find one of many, use a combobox (the guide entry picker). A select always sits in a form field.

Anatomy

  1. LabelFrom the form field.
  2. Container and valueSame as the text field: 44px, --radius-md, 1px --field-border, --text-body; appearance: none with --space-10 end padding for the chevron.
  3. ChevronTwo CSS gradients in currentColor, 5px, centred --space-3 from the end. Decorative; the native role says it opens.

Corktown Garage Studio's south window (pages/studio-editor/default).

Variants

Form select

The Junction Loft (north windows, freight elevator) and Evergreen Brick Works (park, weekend crowds High). "No windows" is a real answer with an empty value, so a studio without windows needs no extra checkbox.
HTML
<div class="field">
  <label class="field__label" for="windowDirection">Window direction</label>
  <select class="select" id="windowDirection" name="windowDirection">
    <option value="">No windows</option>
    <option value="north" selected>North</option>
    <option value="east">East</option>
    <option value="south">South</option>
    <option value="west">West</option>
  </select>
</div>

A set of selects in a fieldset

Natural light
The Junction Loft's light: morning Medium, midday Strong, afternoon Strong, evening Low. The legend groups the four; each select keeps its own short label. The spot editor does the same for its permits ("Permit needed for": Portrait, Wedding or engagement, Commercial, Video).

Filter select

In "Space and light" in the studio filters (L2-022). The first option, "Any size" with an empty value, means no filter, so the URL leaves it out (L2-025).

Sort (inline)

5 studios, sorted by all-in cost

pages/studios/filtered: changing the sort reloads the list and the result count announces "5 studios, sorted by all-in cost" (L2-023.3). In the filters dialog the same select is a full-width field at the top.

  <label class="field__label" for="sort">Sort by</label>
  <select class="select" id="sort" name="sort">
    <option value="recent">Most recent review</option>

  </select>
</div>

In a fee row

$
The Junction Loft's $25.00 cleaning fee. Mandatory fees count toward the all-in cost; optional ones don't (L2-054.5).

Sizes

The select has one size, 44px (--control-height-md), with 16px text. .input--sm and .input--lg apply only to .input; sign-in has no select, so no large select is needed.

States

Hover and focus are forced with data-state; invalid and disabled use aria-invalid and disabled. Open is the platform's own list and can't be drawn. No mock shows an invalid or disabled select; those cells are ready for the server's rejection of a tampered value (L2-055.3) and for a select that doesn't apply yet.

Both themes

  • Hover darkens the edge; focus draws the flush 2px accent ring, exactly like the text field.
  • The chevron follows the text colour, so it fades with the text when disabled and stays 3:1 or more otherwise.
  • A sort change takes effect at once on the studio list; in the filters dialog it waits for "Show 7 studios".

Responsive behaviour

  • Full width of its field; pairs share a .field-row from 36rem. The natural-light and permit sets fit as many 9rem columns as the row allows: one per row on a phone, four across from about 40rem.
  • The inline sort keeps its natural width and wraps under "Sort by" on the narrowest phones. Option text ("Overall score, high to low") sets that width; keep options short.
  • Phones open their native picker (a wheel on iOS, a sheet on Android); nothing about the list is styled.
  • In a fee row the fields stack on phones and sit in one row on wider screens.

Theming

The select shares --field-bg, --field-border and --field-fg with the text field. The chevron is drawn in currentColor, so it themes with the value. The open list is drawn by the platform and follows the page's color-scheme in dark.

Accessibility

Role and pattern

Native <select> (a combobox with a listbox popup in the accessibility tree) with a <label for>. Not a custom ARIA listbox: the native control gives the phone picker, type-ahead and screen reader support for free.

Keyboard

KeyAction
Tab / Shift+TabMoves into and out of the select.
Space / Alt+DownOpens the list.
Up / DownMoves through the options (on Windows, also changes the value while closed).
Typing a letterJumps to the first option starting with it: "S" for South, Stairs or Strong.
Enter / EscChooses the highlighted option / closes without changing.

Focus

The ring sits flush on the edge (offset 0), 2px at 3:1 or more (L2-067.2). Changing the sort never moves focus; the list updates below and the count is announced.

Labelling

A visible label always, including the inline "Sort by". Options are complete phrases that make sense on their own ("All-in cost, low to high", "20 m² or more"), because screen readers read the chosen option with the label. An empty first option says what it means ("No windows", "Any size"), never "Select…".

Motion

Edge colour transitions over --duration-fast; reduced motion zeroes it. The open list's animation belongs to the platform.

Touch

44px tall at every width (L2-065.3); the whole control opens the picker, not just the chevron.

Content

  • Options in sentence case, in a meaningful order: by strength (None, Low, Medium, Strong), by compass (North, East, South, West), by size (20, 30, 50 m²), never alphabetical for its own sake.
  • Sort options name the field and the direction: "All-in cost, low to high", "Overall score, high to low".
  • Use the same words the public page shows: the select's "Freight elevator" is what visitors read under Load-in.
  • Every option has a stable value key (freight-elevator), so the words can change without breaking saved studios or shared URLs.

Sources

Extracted from these mocks:

  • pages/studios/default and filtered (inline sort, usable-space filter, announced sort)
  • dialogs/studio-filters/default and selected (sort and usable space in the sheet)
  • pages/studio-editor/default and published (window direction, natural light, cyc wall, fee type, gear category, load-in, parking)
  • pages/spot-editor/default (type, light by time of day, permits per shoot type, crowds)

Drift fixed during extraction: no editor select gives its options a value, so they submit display words, while the disclosure radios send keys (paid_in_full); every option now has a key. Editor selects have no id and are wrapped in label.field; they get an id and a sibling label for. The natural-light and rubric rows set grid-template-columns inline (an auto-fit 9rem and 7rem grid); .field-row--fit and .field-row--fit-sm now do this (see form layout), and the example here uses .field-row--fit. The cyc wall is a No/Yes select beside a 20 A checkbox; the checkbox is documented as the rule for yes-or-no facts. No mock shows an invalid or disabled select.
