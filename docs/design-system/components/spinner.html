Spinner

A spinner says "working on it" when a wait is short and has no amount: deleting a draft, signing in, searching for a guide entry. It never stands alone; a status message says what is happening.

WCAG 2.2 AAStatus: stable.spinner.btn[aria-busy="true"]role="status"

Overview

A spinner is a 2px ring with an ink arc that turns once every 800ms. ShotThere uses it in two forms:

  • Busy button: the button that started the request draws its own ring (aria-busy="true") in its label colour. Used by Delete studio and Unpublish in the confirm dialogs, Sign in, Subscribe in the email signup, and Save changes in the studio, spot and guide editors.
  • Inline spinner (.spinner--sm): beside a short caption while something small is fetched. The guide entry picker shows it with "Searching" while results for "ju" load (L2-060.4).

Choose something else when:

  • A list, map or editor is loading into a known layout (studio cards, admin rows, editor sections): a skeleton in the same shape, so nothing jumps.
  • The amount is measurable (an image upload): a progress bar.
  • The wait already has a visible status line (the editors' "Saving…" beside Save changes): keep the button's ring and that line; do not add a second spinner.

Anatomy

  1. TrackFull circle, --border-width-thick (2px) in --color-border-default. Decorative.
  2. ArcThe top quarter in --color-fg-default (ink), turning linearly every --duration-loop-fast. In a busy button the arc is the button's --btn-fg with one transparent quarter.
  3. Status textA visible caption ("Searching", aria-hidden) plus a visually hidden role="status" with the full words ("Searching…"). The ring itself is always aria-hidden. Shown at the base 20px here; the picker uses .spinner--sm.

Variants

Busy button in a confirm dialog

The confirming button gets aria-busy="true" and the ring; every other control in the dialog (Cancel, Close) is disabled, and Escape waits for the answer. The label stays the same; a hidden status line says what is happening.

    Never put a .spinner element inside a button: the button draws its own ring, and two rings would overlap.

    Sizes

    Match the spinner to the text beside it. Only the small size is on a ShotThere screen today; the busy-button ring is always 1.1em of the button's font size, so it scales with .btn--sm and .btn--lg.

    Small · 16px Medium · 20px
    Small (--icon-size-sm) beside captions, as in the entry picker; medium (--icon-size-md, the base .spinner) beside body text, in the stylesheet with no screen yet.
    The button ring at small, medium and large button sizes.

    States

    The standalone spinner has no interactive states: it is present while working and removed when done. The busy button is a state of the button, and the matrix shows how it differs from disabled: busy is never dimmed, so the ring keeps its contrast.

    Both themes

    • Delayed: show the spinner only if the wait passes 300ms, as the list loading states do; most searches and saves end sooner.
    • Done: remove the ring and the status text together. A dialog closes and the next screen confirms (the studio list without Corktown Garage Studio; a warning toast after Unpublish).
    • Failed: the button returns to its default state and the error appears where the work was, such as "We couldn't delete it. Try again." in the delete dialog or "We couldn't sign you in just now" on sign-in.

    Responsive behaviour

    • Spinner sizes never change by breakpoint.
    • A busy button keeps its exact width because the label stays in place (transparent), so the dialog footer or form row does not reflow when the ring appears.
    • On phones the sign-in button is full width (.btn--block) and the signup button is full width below 36rem; the ring stays centred in either.
    • The editors' sticky action bar keeps Save changes, Cancel and "Saving…" on one wrapping row, clear of the home indicator (env(safe-area-inset-bottom)).

    Theming

    The standalone ring reads --color-border-default and its arc --color-fg-default; both flip with the theme, giving a pale arc on a dark-stone track in dark. The busy-button ring reads the button's --btn-fg, so it is ink on the default button, the on-action colour on primary and the on-danger colour on danger in both themes. There are no spinner tokens.

    .btn[aria-busy="true"]         { color: transparent; pointer-events: none; opacity: 1; }
.btn[aria-busy="true"]::after  { border: var(--border-width-thick) solid var(--btn-fg); border-right-color: transparent; }

    Accessibility

    Role and pattern

    The ring is decoration: aria-hidden="true" on .spinner, and a CSS pseudo-element on the button. The words live in a role="status" region (polite live region, WCAG 4.1.3) that is in the DOM before the text changes. A busy button keeps its native button role and label, with aria-busy="true". There is no APG spinner pattern; this follows Understanding 4.1.3 Status Messages.

    Keyboard

    KeyAction
    TabSkips the spinner. In a busy dialog every control is disabled, so focus stays in the dialog until it answers.
    EscapeDoes nothing while a confirm dialog is busy. After a failure ("We couldn't delete it. Try again.") it closes the dialog again.
    Enter / SpaceIgnored on a busy button, so a second press can't send the request twice.
    Typing in the entry pickerKeeps working while "Searching" shows; each keystroke restarts the search.

    Focus

    A spinner never takes focus. A native disabled attribute drops focus from the button that was just pressed, so the dialog or form must keep focus inside: either give the busy button aria-disabled="true" instead of disabled (the CSS styles both) or move focus to the dialog panel. When the work ends, focus goes where the next screen says: the next page's main heading, or back to the button on failure.

    Labelling

    Say what is happening, with the item's name: "Deleting Corktown Garage Studio…", "Unpublishing The Junction Loft…", "Searching…". Keep the button's own label as it was ("Delete studio", "Save changes"): it is invisible while busy, and changing it to "Saving…" makes screen readers hear the same word twice.

    Contrast

    Ring in a default button
    Ring in a primary button
    Ring in a danger button
    Inline arc in a dialog
    "Searching" caption in a dialog
    "Saving…" status on the page

    The arc tells the user something is working, so it needs 3:1 against what is behind it (WCAG 1.4.11). The track is decorative. A busy button is never dimmed to 50% for the same reason.

    Motion

    The spinner and the busy-button ring keep turning under prefers-reduced-motion: a still ring reads as frozen, the turn is small, slow and linear, and it ends as soon as the work does. Skeleton shimmer, which is decorative, does stop.

    Touch

    A busy button ignores taps (pointer-events: none), so a double tap on a phone can't delete twice. The ring never covers another control.

    Content

    • Name the thing: "Deleting Corktown Garage Studio…", "Unpublishing The Junction Loft…". Not "Loading…" or "Please wait".
    • Present participle plus the ellipsis character (…). Short captions on screen ("Searching") can drop it; the status text keeps it.
    • No time estimates. If the answer is slow, the request fails into the screen's error state with Try again.
