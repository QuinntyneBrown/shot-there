Sheet and drawer

A sheet is a full-height modal panel for things too long for a dialog: the site menu on phones and the studio and spot filters below 62rem. It fills the phone screen and becomes a 28rem side sheet from 48rem.

Overview

A sheet is a dialog with a different shape: same role, same focus rules, same Escape. Use it when the content is a list of links or a set of filters that would scroll inside a small panel. ShotThere has three:

  • Site menu (dialogs/site-menu): below 48rem the header's inline links move into a Menu sheet (L2-064.2). The public menu lists Studios, Spots, Map, Compare, Guides and the editorial policy; the admin menu lists Dashboard, Studios, Spots, Guides and View site, with Sign out in the footer (L2-052).
  • Studio filters (dialogs/studio-filters): below 62rem the filter sidebar of the studio list opens here instead (L2-022.5). Sort, all-in cost, neighbourhood, space and light, gear, parking; the footer shows the live count, "Show 7 studios".
  • Spot filters (dialogs/spot-filters): the same for outdoor spots: type, use case, permit (L2-024).

Use a dialog for one question, a popover for a small non-blocking detail, and the page itself (the filter sidebar at 62rem and wider) when there is room to show the content inline.

Anatomy

  1. Header.sheet__header: the title (.sheet__title, --text-h4, an <h2>) and a hairline below; top padding adds env(safe-area-inset-top).
  2. CloseA ghost icon button named "Close", 44px.
  3. Body.sheet__body: scrolls on its own; --space-8 between groups. A <form> for filters, <nav> lists for the menu.
  4. Footer (optional).sheet__footer: hairline above, buttons share the width equally, bottom padding adds env(safe-area-inset-bottom).

Variants

The examples are live sheets inside frames: at this page's width they show as side sheets (from 48rem) or fill the frame (below). They leave out aria-modal and autofocus so this page stays usable.

No ShotThere mock uses them: the sheet already becomes a side panel from 48rem and fills the phone screen below it. Keep the drawer for a future side panel that should never go full screen.

Sizes

One size. Below 48rem the sheet fills the viewport; from 48rem it is min(100%, --layout-sheet-width) () wide and full height, against the right edge. The drawer is the same width at every viewport.

The minimum must be lower than the maximum

  • Selected (studio-filters/selected, spot-filters/selected): the chosen controls are checked or filled and the primary's count drops ("Show 5 studios", "Show 2 spots"). Nothing applies until it is pressed; Close and Escape discard the choices.
  • Invalid (studio-filters/invalid): minimum above maximum. The maximum field gets aria-invalid and the error, focus moves to it, and the primary reads "Show studios", disabled and described by the error (README open question 5).
  • Busy does not apply: Apply only changes the URL and the list shows its own loading state.

  • Header and footer stay put; only .sheet__body scrolls. Both add the safe-area insets (top and bottom), and the body padding follows --layout-margin on phones and --space-6 in the side sheet.
  • Footer buttons share the width equally (flex: 1), so "Show 7 studios" is a full-width half on a 320px phone and never wraps under Clear all.
  • Uses position: fixed; inset: 0 rather than 100vh, so mobile browser chrome never clips the footer.

Theming

The sheet reads --color-bg-surface-raised for the panel, --color-border-default for the header and footer hairlines and --shadow-4 for the side sheet's edge. In dark the raised surface is lighter than the canvas, so the side sheet reads as on top. In forced colours the shadow vanishes and a 1px CanvasText edge marks the inner side.

Accessibility

Role and pattern

APG Dialog (Modal): role="dialog", aria-modal="true", aria-labelledby on the title and aria-describedby on the intro line (visually hidden in the menus: "Site navigation", "Administration navigation"). The page behind is inert and aria-hidden="true". Inside, the menus are <nav> landmarks with names ("Primary", "About ShotThere", "Administration"); the filters are a <form> of <fieldset> groups. The Menu and Filters triggers carry aria-haspopup="dialog".

Keyboard

KeyAction
Tab / Shift+TabCycles through Close, the body's links or fields, then the footer; focus does not leave the sheet.
EscCloses without applying, like Close.
Space / arrowsToggle a checkbox / move within a radio group (native).
EnterFollows a menu link; in the filters, submits the form (same as the primary).

Focus

On open, focus goes to Close (both menus and both filter sheets), so the first Tab reaches the content. On close it returns to Menu or Filters. When the filters are invalid, focus moves to the invalid field. The shared ring is 3:1 against the raised surface.

Labelling

The primary names the result ("Show 7 studios"), not the action ("Apply"), so the count is read with it. The current menu item is announced as "current page".

Header and footer hairlines are decorative and exempt from 1.4.11.

Motion

The sheet slides up on phones and in from the right from 48rem, over --duration-slow with --ease-enter; the drawer slides in from its edge. Reduced motion zeroes the duration.

Touch

Menu rows are at least 72px tall (min-height: 4.5rem); Close, checkboxes, radios and footer buttons are 44px on phones. No swipe to dismiss: Close and Escape are the only ways out, so nothing depends on a gesture.

Content

  • Titles are one word: "Menu", "Filters".
  • Menu rows: the page name, then one line that says what is there with a real number: "7 rental studios, measured the same way", "5 published · 1 draft", "2 items need re-verifying".
  • The filter intro says when things change: "The list updates when you show the results."
  • Footer: "Clear all" and "Show 7 studios" / "Show 2 spots" with the live count; "Show studios" without a number when the filters are invalid. Admin: "Sign out".
  • Filter labels in sentence case with Canadian spelling: "Neighbourhood", "All-in cost for 2 hours", "No permit needed for the selected use".

Drift found during extraction (recorded, mocks unchanged): the admin menu marks Dashboard with aria-current="page", but .section-link had no current-page style, so it looked like every other row; .section-link[aria-current="page"] now adds an accent bar and title. No sheet mock has a .backdrop, so from 48rem the side sheet sits over an undimmed (inert) page, unlike the dialogs. The cost fields force two columns with an inline grid-template-columns on .field-row (which is one column below 36rem); the examples here use .field-row--pair instead. The mocks use <a> for Close, Clear all and the primary so the static set can be clicked through; the product uses buttons and form="…". .drawer and .drawer--left have CSS but no mock.
