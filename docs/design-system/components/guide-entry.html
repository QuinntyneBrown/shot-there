Guide entry

A guide entry is one ranked place in a guide: the location card, the data points the guide is about, the editor's note and a link to the full review. The guide index lists the guides themselves.

Overview

A guide is an editorial shortlist built from the same measurements as every review: "Best studios under $120 for 2 hours", "Best natural light", "Best for a large crew". Each guide page is an ordered .guide-list of .guide-entry items (L2-034); the guides page and the home page list the guides with .guide-index (L2-035).

  • Use a guide entry only inside a guide page, where the order is the editor's ranking and the rank number means something.
  • Use the guide index to list guides: as location cards on the guides page, and as compact title and summary items on the home page.
  • Don't use it for the studio or spot list. There the order comes from the sort the visitor picks, so there is no rank; use the location card in a .location-grid. To set studios side by side use the comparison table.

The data points are the live values from the reviews, never typed into the guide: when The Junction Loft's prices change, every guide that ranks it shows the new all-in cost on the next render (L2-034.3). An entry whose studio goes back to draft is left out and the remaining entries renumber themselves (L2-034.2), because the rank comes from the list position, not from stored text.

Anatomy

  1. DividerHairline --color-border-default top border with --space-8 above the entry; entries sit --space-12 apart.
  2. Location cardThe standard location card (photo 3:2, name, neighbourhood and review date). The photo is decorative (alt=""); the name link covers the card.
  3. Rank.guide-entry__rank: a 40px --color-bg-subtle disc with the position in --text-h4 tabular figures, beside the name. aria-hidden; the <ol> position is the programmatic rank.
  4. Data points.guide-entry__data: a <dl> of the one or two values the guide ranks by. Label in --text-label, --color-fg-subtle; value in --text-h4.
  5. Editor's note.guide-entry__note in --text-body-lg: why this place earned this rank, in two or three sentences.
  6. Review linkA .link--standalone "Read the full review", with the studio name added for screen readers.

Variants

There is one entry layout. What changes is the pair of data points, which follows the guide's subject, and how the guides themselves are listed.

Sizes

One size. The entry changes layout by breakpoint, not by size; see Responsive behaviour.

States

The entry is content, not a control: its interactive parts are the card's name link (which covers the card) and the review link. Pointer and focus states are forced with data-state; real pages get them from :hover and :focus-visible.

Content states

  • Entry omitted: when a ranked studio goes back to draft, its entry is not rendered and the next one moves up; the rank discs read 1, 2 with no gap because they come from the list position (L2-034.2). The guide's entry count in the index ("3 studios") counts published entries only.
  • Value changed: data points are read from the review at render time, so a price change shows in every guide without an edit (L2-034.3). The ranking itself is the editor's and does not re-sort on its own.
  • No guides: the guides page shows the empty state "No guides yet" with "Browse studios" (pages/guides/empty). The home page hides its Guides section rather than showing an empty list.
  • Image failed: the photo slot keeps its 3:2 shape and shows the .media-fallback icon; the photo is decorative, so there is no alt text to show (L2-086.1).

Responsive behaviour

  • XS and SM (below 48rem): one column. The card (photo, rank and name, meta) comes first, then the data points, the note and the link. Nothing scrolls sideways (L2-034.4).
  • MD and up (48rem): two columns, the card capped at 18rem on the left and the body filling the rest, with a --space-8 gutter. Entries keep their --space-12 rhythm at every width.
  • The data points wrap as a row of label-over-value pairs with --space-8 between them; a long measurement ("9.1 m × 7.3 m (30 ft × 24 ft)") moves to its own line rather than shrinking.
  • The rank disc never shrinks (flex-wrap: nowrap on the name row); a long studio name wraps beside it.
  • Guide index: one column at XS and SM, two from MD, on both the guides page and the home page.

Theming

The entry reads only semantic tokens: --color-border-default for the divider, --color-bg-subtle for the rank disc, --color-fg-subtle for data labels and --color-fg-default for values and notes. It has no component tokens of its own; a theme changes those roles and the entry follows. Location card, link and media fallback colours come from their own pages.

In dark, the rank disc becomes neutral stone 800 on the stone 950 page, so it still reads as a quiet marker rather than a button, and the divider drops to stone 750. Photos keep their own colours in both themes.

Accessibility

Role and pattern

A native ordered list: <ol class="guide-list"> with one <li class="guide-entry"> per place, so screen readers announce "list, 3 items" and each position. Because the list has list-style: none, add role="list" so WebKit and VoiceOver keep the list semantics; the visible rank is aria-hidden, so without them the rank would be lost. The data points are a <dl> with each <dt>/<dd> pair wrapped in a <div>. The guide index is a plain <ul>; the order there has no meaning.

Keyboard

KeyAction
Tab / Shift+TabMoves through each entry's two links in order: the studio name, then "Read the full review". The photo, rank and data are not focusable.
EnterFollows the focused link to the studio review.
Heading navigation (H in screen readers)Each studio name is a heading one level below the guide title, so visitors can jump entry to entry.

Focus

Focus on the name link draws the shared ring around the whole card (.location-card:has(a:focus-visible), --space-2 offset, --radius-lg), matching the area the stretched link covers. The review link gets the standard ring. Neither ring is clipped: entries have no overflow: hidden.

Labelling

The card's name link is the entry's name. "Read the full review" carries a visually hidden " of Kensington Window Room" so a links list reads uniquely (WCAG 2.4.4). Scores add a visually hidden " out of 5". The photo is decorative (alt="") because the name says which studio it is. Use real headings for names (h2 on a guide page, h2 in the guides index, h3 under the home page's "Guides" heading).

The entry divider (--color-border-default) is decorative: the headings and list structure separate entries, so it is exempt from 1.4.11.

Motion

Only the card photo moves: it scales to 1.04 on hover over --duration-slow. Reduced motion zeroes the duration, so the photo changes size instantly; the underline on the name still marks hover.

Touch

The whole card is the name link's target, far above 44 × 44. "Read the full review" is a .link--standalone with a 44px minimum height (L2-065.1). Nothing depends on hover.

Content

  • Guide titles name the reader's need in sentence case: "Best studios under $120 for 2 hours", "Best natural light", "Best for a large crew". Put the threshold in the title when there is one.
  • Index summaries say what the guide ranks by in one sentence: "Studios where the windows do the work, ranked by our light score and window direction."
  • Data labels are short nouns that match the review: "All-in for 2 hours", "Overall", "Light score", "Usable space", "Ceiling height". Prices are CAD with cents ("$80.00"); measurements are metric first with imperial in brackets.
  • Editor's notes are two or three sentences of first-hand judgement that justify the rank and say when to book or who should skip it: "Book a morning; by mid-afternoon the room goes flat." Don't repeat the data points in the note.
  • Meta lines give the count and the update date: "3 studios · Updated 3 Oct 2026".
  • The review link is always "Read the full review". The intro above the list explains how the guide was ranked.
