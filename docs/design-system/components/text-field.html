Text field

One short value typed on one line: the owner's email, a booking link, an hourly rate, a ceiling height, a search. A white field with a neutral stone edge that turns accent red on focus and danger red, doubled, when the value is wrong.

Overview

Use a text field for one short value. It always sits in a form field, which gives it a label, help and a message.

  • Pick the type, inputmode and autocomplete that match the data, so phones show the right keyboard and browsers can fill it: email with autocomplete="username" on sign-in and autocomplete="email" in the email signup, password with a Show button, url for booking and permit source links, date for the last-verified dates.
  • Numbers are type="number" with an inputmode: decimal for money, metres and coordinates (hourly rate, usable width, latitude), numeric for whole counts (minimum booking hours, outlets, rubric scores, focal length). min, max and step describe the rule; the server checks it again.
  • Input group (.input-group + .addon) joins a fixed "$" to every price: the hourly rate, fee and extra amounts, and the all-in cost range in the filters. The sign-in password joins its Show button the same way.
  • Search (.search, type="search") adds a leading icon. It filters the admin studio, spot and guide lists. A search that suggests results as you type is a combobox (the guide entry picker).
  • Read-only: a readonly input while sign-in submits, and .read-only-value when a value is shown as text.

For more than one line, use a textarea. For a fixed list of answers, use a select or a radio group.

Anatomy

  1. Addon (optional).addon: --color-bg-subtle fill, --color-fg-muted text, the same strong edge, joined with the outer corners rounded. Decorative "$" is aria-hidden.
  2. Value--text-body (16px, so phones don't zoom on focus) in --field-fg; padding --space-2 --space-3.
  3. ContainerFull width, 44px minimum (--control-height-md), --radius-md, 1px edge in --field-border (--color-border-strong), fill --field-bg.

The studio editor's hourly rate (pages/studio-editor/default). No ShotThere mock uses a placeholder; when one is needed it is a format hint in --color-fg-subtle, never the label.

Read-only

Basics

Corktown Garage Studio · Corktown

A readonly input (sunken fill) while sign-in submits (pages/sign-in/submitting): selectable and focusable, not editable. .read-only-value shows a value as 18px text, as in the editor summaries behind dialogs/missing-fields/default.

Sizes

Medium is the default everywhere. Large is for sign-in, where the two fields are the whole task.

Heights --control-height-md/lg; text --font-size-md / lg. An input group's addon or button matches its input: Show is .btn--lg beside the large password.

States

Hover and focus are forced with data-state; invalid, disabled and read-only use aria-invalid, disabled and readonly. A text field has no active state of its own.

Both themes

$
$
  • Hover darkens the edge to --color-fg-muted. Focus draws the 2px accent ring flush with the edge (offset 0) and turns the edge the same colour.
  • Invalid doubles the edge in danger red (1px border plus a 1px inset shadow), so it differs from default by width as well as hue. It always comes with a .field__error. The value is kept ("-5", "corktowngarage").
  • Read-only uses the sunken fill; the value stays selectable and in the tab order. Sign-in goes read-only while it submits, and Show is disabled.
  • Disabled fades to the subtle fill and disabled text and leaves the tab order: "Provided by" until Discounted or Comped is chosen, and the admin search while the list loads (pages/admin-studios/loading).

Responsive behaviour

  • Every input is width: 100% of its field. Short pairs (Usable width and depth, Latitude and Longitude, Hourly rate and Minimum booking) share a .field-row from 36rem; the cost minimum and maximum in the filters stay side by side at every width because both are short.
  • Text is 16px at medium and large, so iOS Safari never zooms the page on focus.
  • Input groups never wrap: the addon or Show stays joined to the field. At 320px the password keeps 190px for typing beside Show; keep addons to one or two characters.
  • Date inputs use the platform picker: a wheel on iOS, a calendar on Android and desktop. max (today) limits it; the server checks again.
  • The admin search is capped at 28rem so it doesn't run across the whole table on wide screens.

Theming

The input declares three component tokens that alias semantic ones, and every state overrides them instead of setting colours directly:

.input { --field-bg: var(--color-bg-surface); --field-border: var(--color-border-strong); --field-fg: var(--color-fg-default); }
/* hover → --field-border: --color-fg-muted;  focus → --color-focus-ring;  invalid → --color-danger-solid
   disabled → --field-bg: --color-bg-subtle, --field-fg: --color-fg-disabled;  read-only → --field-bg: --color-bg-surface-sunken */

The same tokens drive the select and the textarea, so a re-skin is one rule on a container, for example .fee-row .input { --field-bg: var(--color-bg-surface); }. In dark, the field takes the dark page colour and the stone edge carries it at 3:1 or more; danger red and the accent ring move to their lighter steps.

Accessibility

Role and pattern

Native <input> with a <label for> (see form field). Errors set aria-invalid="true" and are referenced from aria-describedby (L2-069.2). The password Show button is a toggle button (aria-pressed, aria-controls) that switches type between password and text and keeps its name. Searches sit in a role="search" form. autocomplete tokens meet WCAG 1.3.5: username and current-password on sign-in, email in the signup.

Keyboard

KeyAction
Tab / Shift+TabMoves into and out of the field; in the password group, from the field to Show. Read-only fields are tab stops; disabled ones are not.
EnterSubmits the form: signs in, subscribes, saves the editor, or runs the admin search.
Space / Enter on ShowShows or hides the password; focus stays on Show.
Up / Down in a numberSteps the value by step (0.1 m, 1 hour, $10 in the filters). Typing is always allowed.
Esc in a searchClears the value (browser behaviour).
PasteAlways allowed, including the password (WCAG 3.3.8).

Focus

The ring sits flush on the edge (offset 0) and the edge turns accent red, a 2px indicator at 3:1 against the page (L2-067.2). Focus never moves on its own while typing. After a failed submit it goes to the error summary, whose links bring it back here.

Labelling

Every input has a visible label. Its accessible name matches the visible words, and the "$" addon is not part of it. A unit suffix that changes the meaning is referenced from aria-describedby. Show is named "Show password" with a visually hidden word, because "Show" alone is ambiguous out of context.

Disabled fields are exempt (WCAG 1.4.3). The search icon is decorative.

Motion

Edge colour and the invalid shadow transition over --duration-fast; reduced motion zeroes it. No shake on error.

Touch

Medium (44px) and large (52px) meet the 44px phone target (L2-065.3), and the label adds to the tap area. Show is a 52px button beside the large password.

Content

  • Prices are entered as plain numbers after the "$": "65.00", never "$65" or "65 CAD". Visitors see them as $65.00.
  • Metric only in the editors: metres to one decimal ("7.6"), focal length in millimetres. The public pages add imperial in brackets ("6.1 m × 4.3 m (20 ft × 14 ft)").
  • Name the unit in the label ("Usable width (m)", "Minimum booking (hours)") or in an addon, never in the value.
  • Free text that visitors read is written as a short phrase, not a sentence fragment with a full stop: "Roll-up garage door off the lane", "504 King streetcar at Sumach, 2-minute walk".
  • Show says "Show" whether or not the password is visible; aria-pressed carries the state.

Drift fixed during extraction: every sign-in state puts style="flex: 1; min-width: 0;" on the password; the group already fits at 320px without it, so it is dropped. The joined Show button and any suffix addon sat beside the input with both edges showing, a 2px seam where a prefix has 1px; .input-group now overlaps every joined part by 1px, and the focused part rises above its neighbour so its ring is never clipped. Fee and extra amounts in the studio editor have no step, so cents are a step mismatch; money fields now take step="0.01" (the hourly rate's step="0.5" also rejects $45.25).
