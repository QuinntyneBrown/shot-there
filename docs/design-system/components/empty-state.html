Empty state

An empty state fills the space where content would be (no studio reviews yet, no spots match these filters, the list didn't load) with a title, one line of why and one way forward.

Overview

Use an empty state in place of a list, map, table or editor that has nothing to show. ShotThere has four reasons for one:

  • Nothing published yet: before the first reviews go up ("No studio reviews yet", "No outdoor spots yet", "No guides yet", "No locations on the map yet"), and in the admin before the first draft ("No studios yet", "Nothing published yet"). Because nothing is listed until it has been shot there, the public copy says the reviews are being shot.
  • No results: filters or a search leave nothing ("No studios match these filters", "No studios match “parkdale”"), or the page needs a choice first ("Pick at least two studios to compare").
  • Didn't load (.empty--error): the list, map data, dashboard or a record failed to arrive, with Try again (L2-026.2).
  • All done (.empty--success): the dashboard's re-verification list has nothing in it ("Everything is up to date").

Choose something else when:

  • The whole page can't be shown (unknown URL, server failure): the error page.
  • The page still has content and only part of it is missing or dropped (one unknown studio in a compare link, a map without tiles): an alert above what remains.
  • An action failed inside a dialog or form ("We couldn't delete it. Try again."): an alert or inline message where the action was.
  • Data is still on its way: a skeleton.

Anatomy

  1. Icon.empty__icon: a 72px circle in --color-bg-subtle holding a 28px line icon. The svg is aria-hidden. Optional in a compact state inside a section.
  2. Title.empty__title, --text-h3, a heading at the level the page outline needs (h1 to h3), or a p when it sits under a section heading.
  3. Text.empty__text, --color-fg-muted, at most 36 characters wide: why it is empty and what to do.
  4. Actions.empty__actions: one button or link, two at most (Try again plus a way out). Centred and wrapping.

Default: 48px above and below, 24px each side (--space-12 / --space-6), for a whole list or page area. Compact: 32px / 16px (--space-8 / --space-4), for a search with no hits, a section or an overlay. The dashed outline is documentation only.

States

The empty state itself is static. Its action is a button or link and carries the interactive states; Try again also has a busy state while it re-requests. An empty state never shows a disabled action: if nothing can be done, it has no action.

  • Retrying: Try again turns busy for a moment, then the region shows its skeleton (studios/loading) and either the content or the same error comes back.

Responsive behaviour

  • The block is centred in its container at every width; the text column stops at 36 characters, so lines stay short on a 1440px screen too.
  • Actions wrap onto their own centred lines when two buttons can't share one, as Try again and Go to the home page do at 360px.
  • In the studio and spot lists the state takes the place of the card grid, beside the filter sidebar from 62rem and under the Filters button below it.
  • Over the map, the compact card is centred with a 16px inset and at most 24rem wide, so the map edges still show on a phone.
  • Long search terms in a title ("No studios match “parkdale”") wrap; the title never truncates.

Theming

The icon circle reads --color-bg-subtle with an ink glyph; --error swaps to --color-danger-bg and --color-danger-icon, --success to --color-success-bg and --color-success-icon. Title reads --color-fg-default, text --color-fg-muted. All are semantic roles, redefined for dark; the component has no tokens of its own. The block has no background, so it sits on whatever surface holds it: the page, an editor panel or the raised map card.

Accessibility

Role and pattern

No widget role: a heading (or paragraph) for the title, a paragraph and native links or buttons. When an error replaces content after a client-side request, the block gets role="alert" so the failure is announced (WCAG 4.1.3); a no-results state is announced by the result count's role="status" ("0 studios", "0 spots") rather than by the block. Follows the APG alert pattern for the error tone.

Keyboard

KeyAction
TabMoves to the action (Clear filters, Try again, New studio), then the secondary link.

Focus

Focus is not moved into an empty state that appears after a filter change; it stays on the filter. Try again re-requests the same filters and sort (L2-026.2); focus stays on the button while it is busy. In an editor that couldn't open its record, the error title is the page's h1 and focus lands on main.

Labelling

The title is a real heading at the right level: h3 under the visually hidden "Results" h2 in the lists, h2 on admin pages, compare, guides and the map, h1 when the editor has nothing else to show. Icons are decorative. Try again names what it retries through the title above it; it needs no hidden text.

Motion

None. The state appears in place of the skeleton without animation.

Touch

Actions are full-size buttons (44px tall on phones) with 12px between them, and wrap rather than shrink.

Content

The formula

  1. Title: what is (not) here, in plain words. "No studio reviews yet", "No studios match these filters", "We couldn't load the studios". Errors start "We couldn't…", owning the failure.
  2. Text: why, and what next, one or two sentences. Reassure when something failed ("Nothing has changed.", "Your content is safe.", "your filters are kept").
  3. Action: one way forward, named for what it does: Clear filters, Clear search, Try again, New studio, Browse studios. A second action only to leave (Go to the home page, Back to dashboard).
  • Give the count that clearing would restore: "clear them all to see all 7 studios".
  • When filters clash, say which: "The only waterfront spot isn't rated for family shoots."
  • Public first-run copy keeps the promise honest: reviews are "being shot now" and go up "only after a full test shoot". Never "coming soon" with a date.
  • Quote the search term with curly quotes: No studios match “parkdale”.
  • No exclamation marks, no "Oops", no illustrations.
