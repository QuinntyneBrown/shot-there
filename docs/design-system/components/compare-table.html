Component · Data display

Comparison table

The comparison table sets two to four studios side by side as aligned columns, every measurement in the same row and the test shots in the same order. The row labels stay pinned on the left, so on a phone the studios scroll past them (L2-031).

Overview

The comparison page (/compare?studios=a,b,c) is server-rendered from its URL (L2-032, L2-033) and holds one comparison table. Every studio was measured and shot with the same setup, so each row is a fair comparison: the table's job is to keep the rows aligned and the labels in view.

  • Use it only for the studio comparison. Studios reach it from the compare bar.
  • Use a table for admin lists of studios, spots and guides: rows there are records, not measurements side by side.
  • Use a description list for one studio's specs on its review page.

Rows come in five groups, always in this order: Cost (all-in for 2 hours, hourly rate, minimum booking, mandatory fees, prices verified), Space and light (usable space, ceiling height, natural light, cyc wall), Gear and logistics (included gear, parking, load-in), Scores (value, light, space, gear, logistics, condition, overall) and Test shots (shot 1 headshot, shot 2 full length, shot 3 product on table).

Anatomy

  1. Corner cellAn empty <td class="compare-table__label">, so the label column starts under it and stays opaque while studios scroll.
  2. Studio header<th scope="col">: 3:2 photo (alt="", --radius-md), the studio's name as a link to its review, the neighbourhood as a caption.
  3. Group row.compare-table__group: a <th scope="rowgroup"> spanning every column, meant for the sunken surface (overridden today; see Sources). Each group is its own <tbody>.
  4. Row label<th scope="row" class="compare-table__label">: muted label type, sticky at left: 0, with a hairline inner edge on its right.
  5. Value.compare-table__value inside each <td>: a column of value lines, tabular figures, 4px apart.
  6. MarkerA badge under the value: success "Lowest" on the lowest all-in cost (L2-031.2), warning "Prices may be out of date" on stale prices.
  7. Scroll wrapper.table-wrap: the only thing that scrolls sideways; a focusable region labelled by the caption.

Variants

The table has one design; the variants are the number of studios, set by the URL and written to --compare-cols on the table.

Sizes

Width follows the column count. Below LG the table has a minimum width of 9rem + --compare-cols × 10rem, which gives the label column 144px and every studio column at least 160px (L2-031.4); from LG the minimum is dropped and the columns share the container (L2-031.5).

Responsive behaviour

  • XS to MD (below 62rem): the table keeps every column and scrolls sideways inside .table-wrap; the label column stays fixed at the left edge and the page itself never scrolls sideways (L2-031.4). Each studio column is at least 160px.
  • LG and up (62rem): the minimum width is dropped and up to four studios fit the container without scrolling (L2-031.5). The layout is fixed (table-layout: fixed), so every studio column is the same width whatever its content.
  • Long values wrap inside their cell ("4 strobes, 2 LED panels, octabox, 2 stripboxes, beauty dish, 8 C-stands"); badges in a cell wrap too (inline white-space: normal today; class rule proposed under Sources).
  • Group labels span the full table, so after scrolling sideways on a phone the label ("Cost") is out of view and the group row looks empty. Proposed fix under Sources.
  • The page header's Copy link and Change studios wrap below the title on phones, as every page header does.

Theming

The comparison table is a .table with a modifier, so it reads the table's semantic tokens: --color-bg-surface for cells and the sticky label column, --color-border-default for rules and the label column's inner edge, --color-bg-surface-sunken for group rows and --color-bg-subtle for the hovered row. The sticky column must repeat the surface colour because a transparent cell would let the scrolled values show through; in the dark theme that is the dark surface, so nothing changes in the CSS.

Photos and test shots are content and keep their own colours. Badges switch to the dark success and warning pairs.

/* A wider label column for longer row labels in another language */
:lang(fr) .compare-table col.compare-table__labels { width: 11rem; }
:lang(fr) .compare-table { min-width: calc(11rem + var(--compare-cols, 3) * 10rem); }

Accessibility

Role and pattern

A native data <table> (the WAI-ARIA APG Table pattern, static): a <caption> naming the studios (visually hidden, because the h1 and subtitle say it on screen), <th scope="col"> per studio, <th scope="row"> per measurement and <th scope="rowgroup"> per group, each group in its own <tbody>. No ARIA grid: the table is not interactive.

Keyboard

KeyAction
Tab / Shift+TabReaches the scroll region (when it can overflow), then each studio-name link in the header.
← →With the region focused: scrolls the studio columns sideways; the label column stays.
EnterOn a studio name: opens its review.
Screen-reader table keysMove cell by cell; each value is read with its row and column headers ("Hourly rate, Leslieville Daylight Studio, $45.50").

Focus

The wrapper takes tabindex="0", role="region" and aria-labelledby pointing at the caption, like every scrollable table; the mocks leave these out (see Sources). The shared focus ring shows on the region and on header links. Focusing a header link that is scrolled out of view scrolls it into view.

Labelling

  • Header photos have alt=""; the studio's name follows as the link text.
  • Test shots have full alt text naming the studio, the shot and what it shows: "The Junction Loft, test shot 1, headshot: even falloff on grey seamless."
  • Scores read "4 out of 5": the visible " / 5" is aria-hidden and " out of 5" is visually hidden.
  • "Lowest" and "Prices may be out of date" are badge text, so they are read with the value.
  • The unknown-slug and over-limit alerts are role="status", announced after the page loads.

Row rules and the label column's edge (--color-border-default) are decorative; alignment and the header cells carry the structure.

Motion

None. Row hover is an instant fill; horizontal scrolling is the browser's own.

Touch

Swipe scrolls the studio columns; the sticky label column does not intercept the gesture. Header links are text links (at least 24px tall with their line height); the photo above each name is not a second link.

Content

  • Page: h1 "Compare 3 studios"; subtitle names them in URL order and ends "All-in is a 2-hour shoot with every mandatory fee."; the page title also names them (L2-033.2).
  • Row labels: sentence case, the same words every time: "All-in, 2 hours", "Hourly rate", "Minimum booking", "Mandatory fees", "Prices verified", "Usable space", "Ceiling height", "Natural light", "Cyc wall", "Included gear", "Parking", "Load-in", the six rubric names, "Overall", "Shot 1 · Headshot", "Shot 2 · Full length", "Shot 3 · Product on table".
  • Values: prices to the cent ("$45.50"), dates as "22 Sep 2026", hours as "2 hours", metric dimensions ("6.1 m × 4.3 m"), scores as "4 / 5" and the overall to one decimal ("3.8 / 5"), natural light one line per time of day ("Morning: Medium").
  • Missing: "—". Mandatory fees: the fee's name and amount ("Cleaning $25.00", "Cyc touch-up $35.00").
  • Messages: unknown slug "One studio in this link couldn't be found, so we're comparing the other two."; over the limit "You can compare up to 4 studios. We're showing the first 4 from this link."; empty "Pick at least two studios to compare" with "Browse studios".
  • Copy link toasts: "Link copied · Anyone with the link sees these 3 studios side by side." and, on failure, "Couldn't copy the link · Copy the address from your browser's address bar instead."

Drift found during extraction (the CSS was not changed; each proposal is in the extraction report):

  • Group rows never get their fill. .table tbody th (0,1,2) outranks .compare-table__group th (0,1,1), so the sunken background and the 16px label type lose to background: none and the small row-header type; group rows render as plain rows in every compare mock and in the examples on this page, and turn sunken only on hover, where .compare-table__group:hover th (0,2,1) happens to win. Proposed: raise the base selector to .compare-table .compare-table__group th.
  • Inline badge wrapping. Every compare mock sets style="white-space: normal;" on the stale badge. Proposed: .compare-table .badge { white-space: normal; }.
  • Inline caption display. Every studio header sets style="display: block;" on the neighbourhood caption. Proposed: .compare-table thead .text-caption { display: block; }.
  • Scroll region missing. The mocks' .table-wrap has no tabindex, role or label, so keyboard users without a header link in view cannot scroll it. Resolution: tabindex="0" role="region" aria-labelledby="<caption id>", as on the table page; used in the examples here.
  • Group label scrolls away. At 360px, after scrolling sideways the full-width group cell's text is off-screen (checked in pages/compare/default). Proposed: wrap the label in a span and add .compare-table__group th > span { position: sticky; left: var(--space-3); }.
  • No static hover hook for the label cell. .compare-table tbody tr:hover .compare-table__label has no tr[data-state="hover"] twin, so a forced hover row keeps a white label. Proposed: add .compare-table tbody tr[data-state="hover"] .compare-table__label to that rule.
  • Alert spacing inline. pages/compare/over-limit and unknown-slug set style="margin-bottom: var(--space-6);" on the alert. Resolution: page layout, not this component; a .stack around the alert and table would remove it.
  • Copy link is a link in the mock (<a class="btn" href="…toast">) only so the mock can navigate to its toast; in the product it is a <button type="button"> because it acts and does not navigate.
  • Metric only. Usable space and ceiling height omit the imperial in brackets that the content rules ask for elsewhere ("6.1 m × 4.3 m (20 ft × 14 ft)"), presumably to fit 160px columns. Recorded for a content decision.
