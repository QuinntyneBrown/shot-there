Progress

A progress bar shows how far an image upload has got in the admin editors: one bar per file, named after the file, until the image is in and its alt text field takes focus.

Overview

ShotThere has one measurable wait: the admin uploading test shots, gallery images and sample shots. Each file gets its own bar inside its row of the image manager (L2-057.6), so the admin can see which file is slow and cancel just that one.

  • Upload bar (.progress in .image-row[data-state="uploading"]): under the file line "2 of 3 · gallery-02.jpg · 6.4 MB", with "Uploading… 45%" beneath and a Cancel upload button beside it. Save changes stays disabled until every upload has ended.
  • Toast timer (.toast__progress): a thin decorative bar along the bottom of an auto-dismissing toast ("Corktown Garage Studio is published", "Link copied"). It shows the 8 seconds running out; it is not a progressbar and is hidden from assistive technology. The toast page owns it.

Choose something else when:

  • The wait has no amount (deleting a draft, signing in, searching the entry picker): the button's busy state or a spinner.
  • A list or editor is loading into a known layout (studio cards, admin rows, editor sections): a skeleton.
  • The number is a score, not progress (rubric pips, the overall 3.8 out of 5): the review's own score components.

Fills are ink (--color-action), never accent red: red on ShotThere marks the selected item and the compare toggle, and a red bar would read as a failure.

Anatomy

  1. File line.image-row__meta: position, file name and size ("2 of 3 · gallery-02.jpg · 6.4 MB"). The bar's name repeats the file name.
  2. Fill.progress__bar, width from --value (a percentage), ink, pill ends, eases over --duration-deliberate.
  3. Track.progress: full width of the row body, --space-2 (8px) high, --color-bg-subtle-hover, --radius-full.
  4. Value text"Uploading… 45%" in .image-row__meta, aria-hidden because the progressbar already reports 45%.

Variants

Upload bar (determinate)

Set --value on .progress__bar and keep aria-valuenow in step. The row's thumbnail drops to 50% opacity while it uploads; the only action is Cancel upload.

Toast timer

The last child of an auto-dismissing toast: 2px, the toast's text colour at 40% opacity, shrinking over the toast's 8 seconds and pausing on hover and focus. Danger toasts never dismiss on their own, so they have no timer.

Sizes

The bar has one height (8px, --space-2): readable at a glance on a phone and thin enough to sit between two lines of file meta. Width comes from the row body. The toast timer is a fixed 2px (--border-width-thick).

States

A progress bar is not interactive, so hover, focus, active and disabled do not apply; the controls beside it (Cancel upload) have their own states on the button page. The states that matter are values and outcomes, set with the real ARIA attributes.

  • Value changes animate the fill over --duration-deliberate (500ms), so 45% to 80% glides instead of snapping.
  • Finished: the bar and "Uploading… 100%" go, the row shows its Alt text field, and that field takes focus (L2-057.1).
  • Failed: the row switches to data-state="failed"; the bar is replaced by the error and Retry re-sends only that file (L2-057.7).
  • Cancelled: Cancel upload removes the row; there is no "cancelled" bar.

Responsive behaviour

  • The bar is always 100% of .image-row__body; the row decides the width.
  • Below 48rem: the row is a 5rem thumbnail beside the body, and Cancel upload drops to a full-width line under both, so the bar keeps the whole body column at 360px.
  • From 48rem: the thumbnail grows to 6rem and Cancel upload moves to a third column on the right; the bar does not get longer than the body column.
  • The toast timer spans the toast, whose width is the screen less 16px each side on phones and 24rem from 36rem.

Theming

The track reads --color-bg-subtle-hover; the fill reads --color-action (ink); the file lines read --color-fg-muted. There are no component tokens, so a theme changes only the semantic roles.

In dark, ink flips to light stone and the track to a raised dark stone, so the filled part is still the brighter one. The toast timer uses currentColor, so it follows the inverse toast text in both themes.

Accessibility

Role and pattern

role="progressbar" with aria-valuemin="0", aria-valuemax="100" and aria-valuenow. A plain percentage needs no aria-valuetext. See WAI-ARIA progressbar; the APG has no separate pattern, so follow its range properties guidance. The toast timer is aria-hidden="true".

Keyboard

KeyAction
TabSkips the bar; it is not focusable. Cancel upload, Move up, Move down and Remove in the other rows are.
Screen reader browse keysRead "Uploading gallery-02.jpg, progress bar, 45%" where the bar sits in the row.

Focus

The bar never takes focus. When an upload finishes, focus moves to that image's Alt text field (L2-057.1), because alt text is required before the save (L2-057.4).

Labelling

Every bar is named after its file with aria-label ("Uploading gallery-02.jpg"), so three bars in one list are three different names. The visible "Uploading… 45%" is aria-hidden to avoid hearing the value twice. Do not announce every percentage: the failure is announced by the row's role="alert" error, and the finish by the focus move.

Contrast

Ink fill on track
File line in an editor section
Toast text (timer uses the same colour, decorative)

The fill must reach 3:1 against the track (WCAG 1.4.11), because the boundary between them is the information. The track does not need 3:1 against the section: the value is also in text.

Motion

Fill changes read --duration-deliberate, which reduced motion zeroes, so the bar jumps to the new value.

Touch

Nothing to touch. Cancel upload keeps a 44px target on phones and sits on its own line below the bar, never on top of it.

Content

  • Name the file: "Uploading gallery-02.jpg" in the label, "2 of 3 · gallery-02.jpg · 6.4 MB" above the bar. Not "Upload progress".
  • Value text is "Uploading… 45%": present participle, ellipsis character, numerals, no space before %.
  • Outcome words are plain: "gallery-04.jpg didn't upload. Check your connection." No "Oops" and no "Success!".
  • Limits come before the upload, under the drop area: "JPEG, PNG, WebP or AVIF, up to 20 MB each." A refused file never gets a bar.

bar.style.setProperty('--value', pct + '%');
track.setAttribute('aria-valuenow', pct);
valueText.textContent = 'Uploading… ' + pct + '%';
Class / attributeEffect
.progressTrack: full width, 8px, pill.
.progress__barFill; width from --value (default 0%).
.toast__progress2px timer along the bottom of a toast, currentColor at 40%. Always aria-hidden.
.image-row[data-state="uploading"]Dims the thumbnail to 50% while the bar runs.
role="progressbar" + aria-valuemin/max/nowRequired on every determinate bar.
aria-label / aria-labelledbyRequired name, with the file name.
