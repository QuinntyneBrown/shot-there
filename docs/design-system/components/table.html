Component · Data display

Table

Tables hold ShotThere's records that people read across and down at once: a spot's light by time of day and by season, its permits by shoot type, and the admin lists of studios, spots and guides. Below 48rem each row becomes a label-over-value card, so nothing scrolls sideways on a phone.

Overview

Use a table when every row has the same two or more columns and the reader compares rows: "Golden hour · Strong · West light rakes the brick" against "Midday · Low · Harsh". Every ShotThere table sits in .table-wrap, has a <caption> (visually hidden when a heading already names it), column headers with scope="col" and a row header with scope="row".

  • Reference table (.table.table--stack): a spot's best light by time of day (Time, Rating, Note) and by season (Season, Note) on the spot page (L2-015).
  • Permit table: shoot type against "Required" or "Not required" (L2-018), followed by the verified line and its source link.
  • Admin list: studios, spots or guides with Status, Last updated (sorted, newest first), Flags and an Edit action (L2-063). It is the only table with links and buttons in its rows.

Two neighbours are not this component:

  • A studio's pricing and fees, measured specifications, gear and logistics are one label and one value per row (Usable shooting space · 6.1 m × 4.3 m (20 ft × 14 ft)). They use the .kv description list, not a table: there is nothing to read down a column.
  • The side-by-side comparison of two to four studios is the comparison table: a .table.compare-table with a sticky label column and studio columns, which scrolls sideways instead of stacking.

Anatomy

  1. Caption<caption> names the table; visually hidden (.visually-hidden) under a section heading, as on every ShotThere page.
  2. Column headerth scope="col", --text-label in --color-fg-muted on the surface; sticky to the top of the wrap.
  3. Row headerth scope="row" in default ink at medium weight: the time of day, the season, the shoot type or the studio name.
  4. Celltd with data-label when the table stacks; --space-4 × --space-3 padding and a hairline rule beneath.
  5. Wrap.table-wrap: hairline top border, the surface fill and sideways scroll when a table cannot stack.

Helpers: .num and .na

  • .num sets tabular figures so prices, distances and coordinates line up: "$60.00", "3.1 km", "43.6846, −79.3653". On a td or th inside .table it also right-aligns the cell. The studio pricing .kv rows and the rain-backup list use it outside tables.
  • .na mutes a value the visit did not record, written as words: Not measured. Never leave a cell blank or put a lone dash in a reference table; L2-017.2 asks for "None nearby" rather than an omitted row, and L2-007.2 for "Nothing costs extra at this studio".

Sizes

One density: --space-4 block and --space-3 inline cell padding. ShotThere tables are short (four or five reference rows, nine admin rows), so no mock uses .table--dense; the class remains in the stylesheet for a long list but should not be reached for by default.

States

Rows react to the pointer; only the admin list has controls in its rows. Pointer and focus states are forced with data-state here; real pages get them from :hover, :focus-visible and :active. Loading is aria-busy="true" on the wrap with skeleton cells.

Responsive behaviour

  • Below 48rem (--layout-breakpoint-md) .table--stack hides the header row visually (it stays in the accessibility tree), turns each row into a bordered card, makes the row header the card title and prints each cell's data-label above its value (L2-015.3, L2-017.3, L2-063.3). The wrap drops its border and scroll.
  • From 48rem the same markup is an ordinary table; nothing is duplicated for phones.
  • Every ShotThere table stacks. The only table that scrolls sideways instead is the comparison table, whose columns are the point.
  • Long notes wrap in the cell; the admin Edit button keeps 44px on phones via the shared small-button rule (L2-065.1).

Theming

The table reads semantic tokens only: --color-bg-surface for the wrap and header, --color-border-default for the rules, --color-bg-subtle for the hovered row and --color-fg-muted / --color-fg-subtle for header text and stacked labels. The dark theme swaps those roles, so the same markup works in both; badges and status labels in cells bring their own tone tokens.

/* A denser admin list would override padding, not colour */
.table--dense th, .table--dense td { padding-block: var(--space-2); }

Accessibility

Role and pattern

A native <table> with <caption>, <thead>, th scope="col" and th scope="row": the WAI-ARIA APG Table pattern without ARIA roles. The stacked layout changes CSS display only; headers stay in the DOM, so screen readers still announce "Golden hour, Rating, Strong". Never rebuild a table out of divs for the phone layout.

Keyboard

KeyAction
Tab / Shift+TabMoves through the links and Edit buttons in admin rows, in reading order. Reference tables contain nothing focusable.
EnterFollows the studio name link or the Edit link.
Screen reader table keysMove cell by cell with headers announced; no arrow-key grid behaviour is added.

Focus

Focus lands on the link or button, never the row. The shared ring (--color-focus-ring) stays at least 3:1 on the hovered row.

Labelling

The caption names the table ("Studios, most recently updated first"). The empty action header holds a visually hidden "Actions". Each Edit link appends the studio name in .visually-hidden, so a links list reads "Edit Ossington Blackbox", not nine "Edit"s. Pips are aria-hidden; the rating word is the content.

Content

  • Column headers are one or two words in sentence case: "Shoot type", "Last updated". Row headers are the thing being described: "Golden hour", "Wedding or engagement".
  • Ratings are words from the fixed scale (None, Low, Medium, Strong); permits are "Required" or "Not required". No icons without words.
  • Notes are one sentence with a full stop: "Valley colour peaks mid-October."
  • Dates are short in admin lists ("6 Mar 2026") inside <time datetime>; long on public pages ("1 September 2026").
  • Absent values are words ("None", "Not measured"), never a blank cell.
  • Captions say what and whose: "Permit needed at Evergreen Brick Works by shoot type".
