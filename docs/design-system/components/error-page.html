Error page

When a whole page can't be shown (the URL matches nothing, the location isn't published, or the server failed) the error page says so plainly under the normal site header and offers a way home (L2-083).

Overview

ShotThere has two error pages, both inside the public site header and footer so the visitor can still navigate:

  • Not found (HTTP 404): any URL that matches no route, and any studio, spot or guide that is a draft, so a draft can't be found by guessing its slug (L2-001, L2-083.1). Links to the home page and the studio list.
  • Something went wrong (HTTP 500): an unhandled server error while rendering. Shows a reference (the request's correlation ID from the logs) and never a stack trace or internal detail (L2-083.2, L2-085).

Choose something else when:

  • Part of the page can still be shown: a compare link with one unknown studio keeps the comparison of the other two and says so in an info alert (compare/unknown-slug).
  • A list or map's data didn't arrive but the page did: the error empty state with Try again.
  • An admin record can't be opened: the editor's error empty state ("We couldn't open this studio"), which keeps the admin header.
  • Sign-in is rate-limited (HTTP 429): a warning alert on the sign-in form ("Too many sign-in attempts. Wait 15 minutes, then try again."), not an error page (L2-050).

Anatomy

  1. Code line.system-page__code, small, --color-fg-subtle: "Error 404" above the heading, or "Reference 7f3a-91c2" below the text on a 500.
  2. HeadingThe page's only h1, --text-display (48px on phones, 64px from 62rem). Says what happened. Shown as a paragraph here because this page already has its h1.
  3. TextOne paragraph of why and what to do, in body text.
  4. Actions.system-page__actions: a primary and a secondary button-link, centred and wrapping.

Sizes

One size: a centred column up to 34rem with 64px above (--space-16) and 32px below (--space-8). Only the heading's type steps up from 62rem, through --font-size-5xl.

States

The page is static; its actions are button-links and carry the interactive states. There is no disabled or busy state: both actions are plain links that load a page.

Responsive behaviour

  • The column is centred in .container, so it keeps the page margins (16px on phones) and stops at 34rem on wide screens.
  • The heading is 48px on phones and 64px from 62rem, and wraps; at 360px "We couldn't find that page" is two lines with no horizontal scroll (L2-083.3).
  • The two actions sit side by side when they fit and stack, centred, when they don't.
  • The reference code never wraps mid-code; it is short by design.

Theming

The page uses semantic roles only: heading and text in --color-fg-default, the code line in --color-fg-subtle, the mail link in --color-fg-link, and the button tokens. It sits on --color-bg-canvas. No illustration or photo, so nothing has to be redrawn for dark.

Accessibility

Role and pattern

A normal document: the site header's banner and navigation, main holding the h1, and the footer. No live region and no role="alert": the page loads as a page, and the document title names the error from the central page titles. The HTTP status (404 or 500) is the machine-readable part (L2-083).

Keyboard

KeyAction
TabSkip link, header navigation, then the mail link (on a 500), the primary action and the secondary action.
EnterFollows the focused link.

Focus

A full page load starts at the top as usual. When the app routes to the error page on the client, focus moves to main (tabindex="-1") so the heading is read next.

Labelling

The h1 is the message. Action labels say where they go ("Go to the home page", "Browse studios"), and Try again reloads the same URL. The reference code is plain text so it can be selected and copied.

Touch

Content

  • Heading says what happened, from the visitor's side: "We couldn't find that page", "Something went wrong on our side". The 500 takes the blame.
  • The 404 never reveals drafts: "It may have been renamed, or the location isn't published." covers both an unknown slug and a draft.
  • The 500 says what to do: try again in a minute, and how to report it, with a reference to quote.
  • Code line: "Error 404"; "Reference" plus the correlation ID. No other technical detail.
  • No jokes, no illustrations, no exclamation marks.

Drift fixed during extraction: none. The 404 puts its code line above the heading and the 500 puts its reference below the text; that is deliberate (the code names the error, the reference is quoted after the instruction) and both are documented. There is no admin-only error page; admin failures use the error empty state inside the admin header.
