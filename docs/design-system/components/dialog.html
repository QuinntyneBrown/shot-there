Dialog

A dialog stops the admin for one decision: delete a draft, unpublish a studio, discard edits, remove a test shot, or pick a guide entry. On phones it docks to the bottom of the screen.

Overview

Every ShotThere dialog belongs to the administration area: the visitor side of the site never interrupts. Use a dialog when the owner must answer one question before carrying on, and the answer fits on one small panel. The editor behind stays visible for context but is inert and dimmed by a backdrop.

  • Destructive confirmation: something is lost. "Delete Corktown Garage Studio?" (L2-061), "Discard changes?" (L2-062), "Remove test shot 2?" (L2-058). The confirm button is danger red and names the loss.
  • Reversible confirmation: something changes for visitors but can be undone. "Unpublish The Junction Loft?" (L2-056). The confirm button is ink.
  • Acknowledgement: the server refused, and the owner needs to know why. "Can't publish yet" lists the missing fields as links (L2-056.3); "Can't remove this test shot" explains the rule (L2-058.4). One button.
  • Form dialog: one short input. "Add an entry" searches published studios and spots with a combobox (L2-060.4).

Use something else when:

  • The panel is navigation or a long set of filters (the site menu, studio and spot filters below 62rem): use a sheet.
  • The content is photos to page through: use the lightbox viewer.
  • The content is a small, non-blocking detail attached to something (a map marker): use a popover.
  • Nothing needs deciding, only confirming that it happened ("Saved", "Unpublished"): use a toast.
  • The task is editing a studio, spot or guide: use the editor page (editor layout). No inline forms in dialogs beyond one field.

Anatomy

  1. Backdrop.backdrop: --color-bg-backdrop over the inert page, at --z-overlay. Clicking it does nothing; Escape, Close and Cancel close.
  2. Title.dialog__title (--text-h3), an <h2> referenced by aria-labelledby. Phrased as the question, naming the item.
  3. Description.dialog__desc: the consequence in one or two sentences, muted, referenced by aria-describedby. Title and description sit in .dialog__heading.
  4. CloseA ghost icon button (.btn--ghost.btn--icon) named "Close". Same as Cancel; disabled while busy.
  5. Footer.dialog__footer: right-aligned, wraps, sticky to the panel bottom. Safe action first, confirm last.
  6. Panel.dialog__panel: --color-bg-surface-raised, --radius-lg (--radius-xl top corners when docked on phones), --shadow-4. .dialog__body (not shown) holds lists, alerts, an image row or a field.

Variants

The examples are live dialogs inside a frame, so they lay out exactly as on a page of this width (narrow your window below 36rem to see them dock to the bottom). They leave out aria-modal and autofocus so this page stays usable; the code shows the real attributes.

  • Busy (delete-content/busy, unpublish/busy): the confirm keeps its label with aria-busy="true"; Cancel, Close and Escape wait for the answer; a visually hidden role="status" line says "Deleting Corktown Garage Studio…". A body holding only that line takes no space.

  • Invalid (guide-entry-picker/invalid): the field's error, aria-invalid="true", and Add entry disabled until the choice is valid. Also busy ("Searching") and no-matches ("No published studios or spots match “parkdale”"); see combobox.
  • Refused (remove-image/refused): the rule in a warning alert, which is also the description; one "Got it".

The failed example leaves role="alert" off so this page does not interrupt on load; the mocks carry it.

Responsive behaviour

  • Below 36rem the panel docks to the bottom edge at full width, with --radius-xl top corners, square bottom corners and env(safe-area-inset-bottom) padding so the footer clears the home indicator. It rises in (slide-up).
  • From 36rem it is centred with --space-6 around it and scales in.
  • The footer wraps when its buttons do not fit and stays pinned to the panel bottom while the body scrolls. Buttons stay 44px tall on phones.

Theming

The panel reads --color-bg-surface-raised, --color-fg-default, --color-fg-muted (description), --shadow-4 and the radius tokens; the backdrop reads --color-bg-backdrop. In dark the raised surface is lighter than the canvas and the backdrop darker (66% black), so the panel reads as on top without relying on the shadow. In forced colours the shadow and backdrop vanish and a 1px CanvasText outline keeps the panel apart.

Accessibility

Role and pattern

APG Dialog (Modal): role="dialog", aria-modal="true", aria-labelledby on the title and aria-describedby on the description (or, when refused, on the alert text). The page behind gets inert (and aria-hidden="true" for older assistive technology), as every dialog mock does. The trigger carries aria-haspopup="dialog".

Keyboard

KeyAction
Tab / Shift+TabCycles through the dialog's controls only: Close, body links or field, then the footer.
EscSame as Cancel (or Stay, or Got it). In the picker it first closes an open list. While busy it does nothing until the answer comes back.
Enter, SpaceActivates the focused button. In the picker Enter picks the active option.
↓ / ↑Picker only: moves through the options (aria-activedescendant).

Focus

On open, focus goes to the safe action for confirmations (Cancel, Stay), to the only button for acknowledgements (Got it) and to the search field in the picker. On close it returns to the control that opened the dialog (Delete studio, Unpublish, Remove, Add entry). A link in "Can't publish yet" closes the dialog and moves focus to the named field instead (L2-056.3). The shared ring is 3:1 against the raised surface.

Labelling

The title names the item ("Delete Corktown Garage Studio?"), so the dialog is announced with what is at stake. The Close icon button is named "Close". A busy dialog announces progress through its status line, not by changing the button label.

Motion

The backdrop fades in over --duration-base; the panel slides up on phones and scales in from 36rem over --duration-slow with --ease-enter. Reduced motion zeroes both durations, so the dialog simply appears. The busy spinner keeps turning.

Touch

Footer buttons and Close are 44px. Docking to the bottom on phones puts Cancel and the confirm within thumb reach; tapping the backdrop does nothing, so a stray tap never confirms or cancels.

Content

  • Title as the question, naming the item: "Delete Corktown Garage Studio?", "Unpublish The Junction Loft?", "Remove test shot 2?". Refusals state the fact: "Can't publish yet", "Can't remove this test shot".
  • Description says what happens and whether it can be undone: "It can't be undone." / "You can publish it again any time." / "It's removed when you save the studio."
  • Confirm repeats the verb and the object: "Delete studio", "Remove test shot", "Unpublish", "Add entry". Never "OK", "Yes" or "Confirm".
  • The safe action is "Cancel", or "Stay" when leaving is the question. An acknowledgement's only button is "Got it".
  • Failure copy says nothing changed and what to do: "We couldn't unpublish it. Nothing changed. Try again."
