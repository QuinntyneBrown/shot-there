Icon button

A 44px round button that holds one outline icon and no visible text. On ShotThere it closes the photo lightbox and the map popup, and steps to the previous or next photo.

WCAG 2.2 AAStatus: stableNative <button>.icon-btn.icon-btn--outline

Overview

Use an icon button only where a glyph is universally understood and space is tight: over a photo, on a map, in a viewer's bar. Everywhere else a visible word wins, so the site header's phone control is "Menu" with an icon and a label, not a bare glyph.

  • Ghost (.icon-btn) has no border and no fill at rest. It is the Close in the corner of the map marker popup ("The Junction Loft · All-in for 2 hours: $145.00").
  • Outline adds a hairline ring so the target reads against a large photo. In the photo lightbox Close, "Previous photo" and "Next photo" get it from their container (.viewer .icon-btn). .icon-btn--outline applies the same ring anywhere else; no ShotThere mock uses the class directly yet.

Not icon buttons: the Close in dialog and sheet headers (filters, confirmations, site menu) is a ghost button with .btn--icon, so it lines up with the dialog's other buttons; the × on an active filter is the chip's own .remove button (chip); the play control on an episode poster is part of the episode poster.

Anatomy

  1. Icon24-unit outline icon at 20px (--icon-size-md), --icon-stroke, currentColor, aria-hidden="true".
  2. Ring (outline only)1px --color-border-default. Decorative: the 44px hit area and the hover fill do the work, so the ring needs no 3:1.
  3. Container44px circle (--target-comfortable, --radius-full). Transparent at rest; --color-bg-subtle on hover, --color-bg-subtle-hover while pressed down. The accessible name is its aria-label.

Sizes

One size: 44 × 44px (--target-comfortable) with a 20px icon, at every breakpoint. There is no small icon button. A compact icon-only control in a dialog header is .btn.btn--ghost.btn--icon, also 44px; row actions use small text buttons ("Move up", "Remove").

44px container, 20px glyph, 12px clear space around the glyph.

States

Hover, focus and active are forced with data-state; disabled uses the real disabled attribute.

Both themes

  • Disabled uses the native attribute at 50% opacity with no hover fill. No current ShotThere icon button is ever disabled: the lightbox arrows wrap, and the only busy overlay (the delete dialog) disables its .btn--icon Close, not an .icon-btn.
  • Pressed (aria-pressed="true"), expanded (aria-expanded="true") and current (aria-current="page") have CSS: the hover fill stays on and the glyph turns --color-fg-accent. No ShotThere mock uses an icon toggle or an icon trigger yet; use them only for a real toggle or the trigger of an open popover.
  • Busy is not an icon-button state. An action that waits on the server is a button with aria-busy.

Responsive behaviour

  • Lightbox, from 48rem: Previous and Next flank the photo in the viewer stage; Close sits at the end of the top bar after "Photo 8 of 8". The bar's top padding adds env(safe-area-inset-top) so Close clears a notch.
  • Lightbox, below 48rem: the arrow icon buttons are hidden (.lightbox .viewer__stage > .icon-btn) and the text "Previous" and "Next" buttons appear under the caption. Close stays an icon button.
  • Map popup: Close stays in the popup's top-right corner at every width. Below 48rem the popup docks as a card along the bottom of the map (.map-popup--dock), so Close is reachable with a thumb.
  • An icon button never shrinks with the viewport. If a bar cannot fit its icon buttons, the bar wraps.

Theming

The icon button reads --color-fg-default for the glyph, --color-bg-subtle and --color-bg-subtle-hover for hover and active, --color-border-default for the outline ring and --color-fg-accent for a pressed or current glyph. It has no component tokens. In dark the glyph turns light stone and the hover fill a dark stone, keeping the same contrast steps; the lightbox's canvas background darkens with it, so the photo stays the brightest thing on screen.

Accessibility

Role and pattern

A native <button type="button"> (APG Button) inside the lightbox's modal dialog or the map popup's non-modal dialog. The mocks draw Close as a link back to the page because they are static; in the product it is a button that closes the overlay and returns focus to the thumbnail or marker that opened it (L2-010.2, L2-028.2).

Keyboard

KeyAction
Tab / Shift+TabMoves between Close, Previous and Next; focus stays inside the lightbox (L2-010.4).
Enter, SpaceActivates the button.
EscCloses the lightbox or popup, the same as Close, and returns focus.

Focus

When the lightbox opens, focus goes to Close (autofocus in the mocks), so Escape and Enter both close it. The shared 2px ring with a 3px offset draws round the circle.

Labelling

Every icon button has an aria-label naming the action: "Close", "Previous photo", "Next photo". The position "Photo 8 of 8" is a polite live region in the bar, so the arrows' names don't need to repeat it. Icons are aria-hidden="true".

Motion

Only the fill transitions, over --duration-fast. Reduced motion zeroes it. The lightbox itself fades in over --duration-base, also zeroed.

Touch

44 × 44px at every width (L2-065.3). Previous and Next sit at opposite sides of the photo, far apart; Close is alone in the bar.

Content

  • Names are short verb phrases in sentence case: "Close", "Previous photo", "Next photo".
  • One icon, one meaning: × closes, chevrons step, the external arrow leaves ShotThere. Never reuse × for "remove" outside a chip.
  • If a glyph needs a tooltip to be understood, it needs a word instead: give the button a visible label.

Drift fixed during extraction:

  • Close is drawn two ways: .icon-btn in the lightbox and map popup, .btn.btn--ghost.btn--icon in the dialogs, sheets and site menu. Both are 44px and look alike at rest; the page documents which belongs where rather than merging them.
  • components.css styles .viewer .icon-btn[aria-disabled="true"] for "end arrows", but L2-010.3 and dialogs/lightbox/last wrap the gallery and never disable an arrow. The rule is unused; removal is proposed.
  • The mocks draw Close as <a href> back to the page because they are static. The product uses <button> so focus can return to the opener.
