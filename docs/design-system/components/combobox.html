Combobox

A search field that filters a list as you type. The admin uses it to find a published studio or spot by part of its name and add it to a guide.

Overview

Use the combobox when the admin has to pick one record out of many by name: the guide editor's Add an entry dialog lists every published studio and spot, and typing "studio" narrows it to three (L2-060.4: matches within 500 ms, selectable by keyboard). The text box keeps focus the whole time; arrow keys move an active option through the list and Enter picks it.

  • Use a select when the options are few and fixed (a guide's sort, a fee's kind). A combobox earns its place only when the list is too long to scan.
  • Use the plain search input (.search, see text field) when typing filters a table already on the page, as on the admin guide list. That field has no popup, so it is not a combobox.
  • The list only ever holds published locations. Drafts are not offered: a guide can only point at a place that has been shot there and is live.

Anatomy

  1. LabelVisible .field__label tied to the input with for; it names the combobox.
  2. Search icon20px, --color-fg-subtle, aria-hidden, centred on the 52px field.
  3. Text box.input with role="combobox" inside .search-field: full pill, --control-height-lg, left padding clears the icon.
  4. Help.field__help, "Type part of a name", referenced by aria-describedby.
  5. Listbox.suggestions: raised surface, --radius-lg, --shadow-3, scrolls after eight options.
  6. Option.suggestion, at least 44px tall. The active one has the subtle fill and a 2px accent bar on its left edge; the matched text is bold through <mark>.
  7. Hint.suggestion__hint: kind and neighbourhood in caption type, so two similar names can be told apart.

Variants

One field, one popup. What varies is what the popup holds: options with hints, or a single message when nothing matches. A flat listbox (.suggestions--inline) drops the raised surface for a list that sits in the flow of an already raised panel.

Sizes

The combobox has one size: the field is --control-height-lg (52px) and each option is at least --target-comfortable (44px) tall at every breakpoint.

States

The field and its options have separate state sets. Hover and focus are forced with data-state so they can be reviewed without a pointer; everything else uses the real attribute: disabled, aria-invalid, aria-expanded, and aria-selected for the active option.

          Responsive behaviour

          • The field and listbox are always full width of their container. Inside the picker that is the dialog body, which is a bottom sheet below 36rem and a centred 40rem form panel above it.
          • The listbox sits in the flow under the field, not floating over the dialog, so it can never be clipped by the sheet's edge or the on-screen keyboard. It scrolls on its own after eight options (max-height of 8 × 44px plus padding).
          • Option rows wrap: a long name breaks inside its span (overflow-wrap: anywhere, combobox D-11) and the hint drops below the name instead of squeezing it.
          • The text box uses 16px body type at every width, so iOS does not zoom when it takes focus.
          • Options are 44px tall at every breakpoint (L2-065), so no phone-only override is needed.

          Theming

          The text box is a text field and reads the same component tokens (--field-bg, --field-border, --field-fg); .search-field only changes its shape and padding. The listbox reads semantic tokens directly: --color-bg-surface-raised, --color-border-default and --shadow-3 for the panel; --color-bg-subtle plus a --color-accent bar for the active option; --color-fg-subtle for hints.

          In the dark theme the raised surface is a step lighter than the dialog behind it and the shadow deepens, so the list still reads as lifted; the accent bar lightens with the accent ramp and stays above 3:1 on the subtle fill. In forced colours the fill and the bar disappear, so the active option takes Highlight and HighlightText (combobox D-9).

          @media (forced-colors: active) {
  .suggestion[aria-selected="true"] { forced-color-adjust: none; background: Highlight; color: HighlightText; }
}

          Accessibility

          Role and pattern

          WAI-ARIA APG Combobox, list autocomplete with automatic selection: an <input type="text" role="combobox" aria-autocomplete="list"> that controls a <ul role="listbox"> of role="option" items. aria-expanded says whether the list is showing, aria-controls names it (the listbox stays in the DOM, hidden, so the reference always resolves) and aria-activedescendant names the active option. autocomplete="off" keeps the browser's own suggestions out of the way.

          Keyboard

          KeyAction
          TypingFilters the list within 500 ms (L2-060.4), opens it when there is at least one match and makes the first option active.
          ↓Opens the list if it is closed and has matches; otherwise moves the active option down, wrapping from the last to the first.
          ↑Moves the active option up, wrapping from the first to the last.
          EnterPicks the active option: its name fills the text box, the list closes and Add entry becomes available. Enter does not submit the dialog while the list is open.
          EscWith the list open, closes it and keeps the text. With the list closed, the dialog handles it: it closes and focus returns to the Add entry button in the guide editor.
          ← / →, Home / EndMove the caret in the text box, as in any text field.
          TabCloses the list without picking and moves on to Cancel.

          Focus

          The dialog opens with focus in the text box, and DOM focus never leaves it. The shared ring (2px --color-focus-ring) sits on the text box; the active option shows by its fill and 2px accent bar, never by a second ring, and is scrolled into view as it moves. Clicking an option picks it and returns focus to the text box.

          Labelling

          The visible label "Studio or spot" names the combobox; "Type part of a name" describes it. The listbox has aria-label="Matching studios and spots". An option's name is its text, so the hint is read with it ("Leslieville Daylight Studio, Studio · Leslieville"). The result count ("3 results"), "Searching…" and the no-match sentence go to a role="status" region so they are announced without moving focus. An error comes first in aria-describedby, as on every other field.

          Motion

          The listbox appears and disappears without animation, so results never lag behind typing. Only the field border eases over --duration-fast, which reduced motion zeroes. The busy spinner keeps turning under reduced motion because it reports status.

          Touch

          The field is 52px tall and every option at least 44px, the whole row being the target. Nothing depends on hover: tapping an option picks it, and the active fill is only a keyboard and pointer cue.

          Content

          • Label names what is being picked, in sentence case: "Studio or spot". No placeholder; the help line under the field says "Type part of a name".
          • Options are the location's published name, with the typed text in bold through <mark>. Never reword a name to fit.
          • Hints are "Kind · Neighbourhood": "Studio · Leslieville", "Outdoor spot · Don Valley". The same words the map popup and the location cards use.
          • No match repeats the query in curly quotes and says what was searched: "No published studios or spots match “parkdale”". No apology, no exclamation mark.
          • Busy is one word, "Searching"; the status region reads "Searching…".
          • Count: "1 result", "3 results".
          • Errors say what is wrong with the pick in plain words: "This studio is already in the guide" (L2-060.2), "This spot is already in the guide".
