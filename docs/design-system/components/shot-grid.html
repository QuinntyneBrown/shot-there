Shot grid

The photo evidence on every review. Each studio gets the same three test shots under the same light setup, plus a gallery from a real shoot, and each spot gets sample shots. Every thumbnail opens the lightbox.

Overview

Use the shot grid for any set of photos a visitor should be able to scan and then open full size:

  • Standard test shots are three images taken with the identical setup at every studio: 1 · Headshot, 2 · Full length, 3 · Product on table. They appear in that order and at the same place in the page outline on every studio page, under one setup line (L2-009). This is the side-by-side evidence the site exists for.
  • Gallery ("From a real shoot") is eight or so photos from a real session in the studio, with no captions (L2-010.1).
  • Sample shots on a spot page are captioned with the focal length and a position note, such as "85 mm · Shoot north from the lower steps" (L2-016).

Do not use it for the hero photo (that is .review-hero, one image, not openable), for card media (location card) or for the owner's image list (image manager). Test shots in the comparison table sit in table cells instead, one studio per column.

Anatomy

  1. Setup line.shot-grid__setup: the standard test setup, once, above the grid. Muted small text, 16 px above the grid.
  2. Gridul.shot-grid: 2, 3 or 4 equal columns with a 16 px gap. Each <li> holds one shot.
  3. Shotbutton.shot: a 4:5 slot with 12 px corners and a photo-grey fill while the image loads. The image covers the slot. A pointer shows the zoom cursor.
  4. Caption (optional)figcaption: small muted text 8 px below. <strong> picks out the number and name of a test shot or the focal length of a sample shot.
  5. Figure (with captions)figure: stacks shot and caption with an 8 px gap. A gallery shot without a caption skips the figure.

Variants

One grid in three variants. The variant is chosen by what the photos are evidence of, not by look.

Sizes

There is one size. The column count sets each shot's width (see Responsive behaviour) and the slot is always 4:5, so a slow or failed image never changes the layout.

States

Pointer and focus states are forced here with data-state. Real pages get them from :hover and :focus-visible. A failed image swaps the <img> for .media-fallback inside the same button.

Sample shot
Same as hover. Never disabled.
  • Hover zooms the photo to 104% inside its clipped slot over --duration-slow. The slot itself does not move.
  • Focus draws the shared ring around the slot, following its 12 px corners.
  • Loading is the empty slot in --color-bg-photo at its final size. Images below the first screen use loading="lazy".
  • Failed (HTTP 404 or a network error) keeps the slot and shows an image-off icon with the photo's alt text on the sunken surface (L2-086.1). The button still opens the lightbox, which shows the same fallback.

  • The columns are minmax(0, 1fr), so long captions wrap under their shot and never widen the grid. At 320 px each shot is about 136 px wide.
  • The gap stays 16 px at every width. The grid sits inside the review column, which already carries the page margins.
  • Shots are well over 44 × 44 px at every width, so no extra target padding is needed on phones.
  • Serve the variant that fits: srcset over the 480, 960, 1440 and 2048 px variants with sizes="(min-width: 62rem) 25vw, (min-width: 48rem) 33vw, 50vw".

Theming

Photos are content and keep their own colours in both themes. The chrome around them is themed: the loading slot uses --color-bg-photo, captions and the setup line use --color-fg-muted with --color-fg-default for the strong part, and the failed slot uses --color-bg-surface-sunken with muted text and a subtle icon. In the dark theme the slot darkens to stone-800 so an unloaded photo does not flash white. The grid has no component tokens. To re-theme it, change the semantic roles.

Forced colours: images still show and the focus outline becomes the system highlight. The fallback text stays readable because it is real text.

Accessibility

Role and pattern

A native list (<ul>) of native buttons (<button type="button">) that open a modal lightbox (WAI-ARIA APG Dialog (Modal) pattern). Captioned shots use <figure> and <figcaption>. The grid is not a grid or listbox widget: every shot is its own tab stop.

Keyboard

KeyAction
Tab / Shift+TabMoves through the shots in reading order: left to right, then down.
Enter, SpaceOpens the lightbox on this shot, for example "Photo 3 of 8".
Esc (in the lightbox)Closes the lightbox and returns focus to this shot (L2-010.2, L2-067.3).

Focus

The shared 2 px ring with a 2 px offset follows the slot's 12 px corners. Focus returns to the same shot after the lightbox closes, even if the visitor paged to another photo.

Labelling

The button's accessible name is the image's alt text, which is required and non-empty for every test shot, gallery photo and sample shot (L2-009.3, L2-010, L2-016). A failed image keeps that name because the fallback prints the alt text. Captions are read after the button as part of the figure. The setup line is plain text before the list, so it is read once. The section heading ("Standard test shots", "From a real shoot", "Sample shots") names the region.

Motion

The hover zoom (104%, --duration-slow, --ease-standard) is the only motion. Under prefers-reduced-motion the duration token is zeroed, so the zoom happens without animating. Nothing moves on its own.

Touch

Each shot is a large target, at least 136 × 170 px at 320 px wide, with 16 px between shots. There is no hover on touch, so nothing depends on it: a tap opens the lightbox.

Content

  • The setup line starts "Same setup in every studio:" and lists light, modifier, angle, distance, then exposure separated by " · ": "f/8 · 1/160 s · ISO 100 · 85 mm". Metric first.
  • Test-shot captions are "number · name", with the whole caption in <strong>: "1 · Headshot", "2 · Full length", "3 · Product on table".
  • Sample-shot captions are "focal length · position note". The note starts with a capital and has no full stop: "135 mm · Compress the valley from the top of the Beltline".
  • Alt text says what the photo shows and what it proves about the place, in one sentence: "Test shot 2, full length on the cyc: the scuffs show as faint marks behind the feet." Never "Image 2" or the file name.
  • The section head may count the photos: "8 photos", "5 photos".

Sources

Extracted from these mocks:

  • pages/studio/default (setup line, three test shots, eight-photo gallery, hover on photo 2)
  • pages/studio/media-failed (gallery photos 2 and 5 failed: fallback in the slot)
  • pages/spot/default (five sample shots captioned with focal length and note)
  • dialogs/lightbox/default (what a shot opens)

Drift fixed during extraction: the mocks make each .shot an <a href> to the lightbox mock file, only so the static set can be clicked through. The detailed design renders thumbnails as buttons that open a dialog, so the system uses <button type="button">, which the .shot reset already expects. The spot mocks declare the sample images as width="800" height="1000", but the files are 1200 × 800 landscape. The system uses the true size so the browser reserves the right ratio before the 4:5 crop.
