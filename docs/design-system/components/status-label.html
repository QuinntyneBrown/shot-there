Status label

A status label tells the admin whether a studio, spot or guide is on the public site: Published or Draft. It is always a word plus a shape, so the state never rests on colour alone.

WCAG 2.2 AAStatus: stablePlain text <span>.status .status--published .status--draft

Overview

Every piece of content the admin manages has one of two publish states. The status label shows it wherever the admin sees content: the Status column of the studio, spot and guide lists (L2-063.1), the editor's page header and the editor's Status aside.

  • Published: on the public site. A filled dot in success green.
  • Draft: only the admin can see it. A hollow ring in neutral stone.

Use a status label only for the publish state. Use a badge for attention flags that sit beside it ("Prices stale", "Permits stale", "Due soon"), and a tag for descriptions visitors see. Status labels never appear on public pages: visitors only ever see published content, so the word would say nothing.

Anatomy

  1. Filled dot (Published)8px (--space-2) circle in currentColor, drawn by ::before, so it always matches the word.
  2. Word--text-label, on one line; the colour comes from the variant. This is what assistive technology reads.
  3. Ring (Draft)The same 8px circle, transparent, with a 2px (--border-width-thick) currentColor ring. The shape, not the colour, tells Draft from Published.

Sizes

One size: --text-label with an 8px shape, in table cells, page headers and the editor aside alike.

States

The label is text, not a control: it has no hover, focus, active or disabled state of its own. What changes is the surface under it, so the matrix shows it on each surface the admin screens use. The hover column shows the --color-bg-subtle fill a hovered table row puts behind the label.

Responsive behaviour

  • The label never wraps (white-space: nowrap); both words are short enough for any column.
  • Below 48rem the admin tables become label-over-value cards (.table--stack, L2-063.3); the label sits under its "Status" caption with the name, flag and Edit action.
  • From 62rem the editor's Status aside sits beside the form and stays in view while scrolling; below that it comes before the form, so the state is the first thing the admin reads.
  • Size and shape do not change by breakpoint.

Theming

The label sets only color; the dot and ring use currentColor, so one token per variant themes both the word and the shape. Published reads --color-success-fg; Draft and the base .status read --color-fg-muted. There are no component tokens.

In dark, Published lightens from success green 700 to 300 and Draft from neutral stone 700 to 350. In forced colours both become the system text colour; the filled dot and the ring still tell them apart.

Accessibility

Role and pattern

Plain text in a <span>; no ARIA role. In tables the column header ("Status") gives it context; in the aside it sits in a <dd> under "Visibility". It is not a live region: a state change is announced by the toast that confirms it.

Keyboard

KeyAction
TabSkips the label; it is not interactive. Focus moves between the row's name link and Edit.
Table navigation (screen readers)Reading across a row announces "Status, Draft" from the column header.

Focus

Not focusable, and it must not be made focusable or clickable. Publishing is done with the editor's buttons.

Labelling

The word is the accessible text; the shape is a CSS pseudo-element and is not read. Never ship the shape without the word, and never replace the word with an icon (WCAG 1.4.1: colour plus shape plus text).

The dot and ring share the word's colour, so they clear 3:1 (1.4.11) wherever the word clears 4.5:1.

Motion

None.

Touch

Not a target. The row's name link and its Edit button carry the touch targets (44px on phones, L2-065.1).

Content

  • Exactly two words, in sentence case: "Published", "Draft". Not "Live", "Public", "Hidden" or "Unpublished".
  • Where there is room, say what the state means next to it: "Published · on the public site", "Draft · not on the public site".
  • Pair it with the time in page headers: "Draft · Last saved 11 Oct 2026, 4:12 pm".
  • List subtitles count by state with the same words: "9 studios · 7 published · 2 draft".

Drift found during extraction:

  • components.css sets .status--published twice (in the Status label section and again under Administration) and adds a redundant .status--draft colour that equals the base. Same values, so nothing renders differently; the second copies can go.
  • The CSS comment cites "L2-069.5" for "a word plus a shape", but L2-069 has four acceptance criteria. The rule comes from WCAG 1.4.1 and L2-063.1 ("status badges"); cited that way here.
  • The editors' Status aside heading is styled with an inline style="font: var(--text-h4);" (pages/studio-editor/default and siblings); it belongs to the editor layout, not to this component.
