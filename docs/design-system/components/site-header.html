Component · Navigation

Site header

The wordmark, the city it covers and five plain links: Studios, Spots, Map, Compare, Guides. The header is the first thing on every page and the quietest. On phones the links fold behind one Menu button that opens the site menu.

Overview

The site header holds the wordmark and the primary navigation. Canvas background, no border, no shadow: the wordmark in bold ink at --text-wordmark, the links in muted ink at --text-nav. It scrolls away with the page; nothing in it is sticky, so the studio photo and the price block get the whole screen.

  • Use it on every page, including the owner sign-in and the 404 and server-error pages, so a visitor can always get back to the studio list.
  • Three variants by area: the public header (tag "Toronto", five links) on every public page, the admin header (tag "Admin", Dashboard to Sign out) on every admin screen, and the bare wordmark on the sign-in page.
  • The current section carries aria-current="page": Studios on the studio list and on every studio review, Spots on the spot list and spot pages, Map, Compare, Guides on the guides list and each guide. The home page, the editorial policy and the error pages mark nothing.
  • Below 48rem (XS and SM) the links are hidden and the Menu button opens the site menu, a full-height dialog that lists the same places with a one-line description each (L2-064.2).

There is no search, no account and nothing to sign in to on the public side: ShotThere has one owner and no visitor accounts. Don't add icons, a "Book now" button or a compare count to the header; the compare bar carries the selection.

Anatomy

  1. Wordmark"ShotThere" in --text-wordmark (bold, --font-size-2xl), --color-fg-default. A link to the home page (public) or the dashboard (admin), at least 44px tall.
  2. Area tag.wordmark__tag: "Toronto" on public pages, "Admin" on admin screens. --text-label in --color-fg-muted inside a hairline pill. Part of the wordmark link's name ("ShotThere Toronto"). Hidden below 24rem.
  3. Current link.site-nav__link[aria-current="page"]: --color-fg-default, semibold. Weight, not colour alone, marks it.
  4. Nav links.site-nav__link.site-nav__extra in --text-nav, --color-fg-muted, 44px tall, --space-3 side padding. Shown from 48rem; below it they move into the site menu.
  5. Menu button (XS and SM only).btn.btn--ghost.site-nav__menu with the three-line icon and the word "Menu". Opens dialogs/site-menu. Hidden from 48rem, so it is not visible in this figure; see Responsive behaviour.

Responsive behaviour

  • XS and SM (below 48rem): every .site-nav__extra is hidden and .site-nav__menu shows. Menu opens the site menu: a full-height sheet dialog listing Studios, Spots, Map, Compare and Guides as section links with one line each ("7 rental studios, measured the same way"), then Editorial policy. The admin menu lists Dashboard to View site with live counts ("7 published · 2 drafts") and puts Sign out in the sheet footer (L2-064.2).
  • MD and up (48rem): the links are inline and the Menu button is hidden. Nothing collapses in between; the header never wraps onto two lines.
  • Below 24rem the area tag is hidden so the header fits at 320px without horizontal scrolling (L2-064.1); the wordmark link's name drops to "ShotThere".
  • On phones the targets sit 8px apart (gap: var(--space-2)) and every one is 44px tall (L2-065.3).
  • The header pads its top by env(safe-area-inset-top), so the wordmark clears the notch in portrait and landscape; in landscape at SM it stays at 4rem, well under the 25% of the viewport L2-066.2 allows.
  • At 200% zoom on a 1280px window the layout is 640px wide, so the Menu button takes over, exactly as on a phone (L2-066.1).

Theming

The header reads semantic tokens only: --color-bg-canvas behind it, --color-fg-default for the wordmark and the current link, --color-fg-muted for the other links and the tag, --color-border-default for the tag's hairline. It has no component tokens. In dark the canvas is near-black stone and the wordmark light stone; the header still has no edge or shadow, because the page below shares its background. The Menu and Sign out buttons are ordinary ghost buttons and theme with them.

Accessibility

Role and pattern

<header> at the top of <body> is the banner landmark; the links sit in a <nav> named "Primary" (public) or "Administration" (admin). The Menu button is a native <button type="button"> with aria-haspopup="dialog", aria-expanded and aria-controls, opening a modal dialog (APG Dialog (Modal)). The current link uses aria-current="page".

Keyboard

KeyAction
Tab / Shift+TabSkip link, wordmark, then each nav link (or the Menu button) in reading order.
EnterFollows a link; on Menu, opens the site menu.
SpaceOpens the site menu from the Menu button; Sign out submits.
Esc (menu open)Closes the menu; focus returns to the Menu button (L2-067.3).

Focus

The shared 2px --color-focus-ring with a 3px offset shows on :focus-visible. Opening the menu moves focus to its Close button; while it is open, focus is trapped in the sheet and the page behind is inert.

Labelling

The wordmark's name includes its tag ("ShotThere Toronto", "ShotThere Admin"), so screen-reader users hear which area they are in. Nav links are single visible words; no aria-label overrides them. The Menu button's name is the visible "Menu"; its icon is aria-hidden="true".

Contrast

Wordmark and current link on canvas
Nav links and area tag on canvas
Menu button label on its hover fill

The current link differs from the others by weight (semibold) and by colour; it never relies on colour alone.

Motion

Links change colour over --duration-fast (120ms). Reduced motion zeroes it. The site menu's own slide-in is documented on Sheet and drawer.

Touch

The wordmark, every link, the Menu button and Sign out are at least 44px tall (--target-comfortable), with 8px between targets on phones.

Content

  • Public links, in this order: Studios, Spots, Map, Compare, Guides. One plural noun each; never "Browse studios" or "Outdoor locations".
  • Admin links, in this order: Dashboard, Studios, Spots, Guides, View site, Sign out. "Sign out", not "Log out".
  • The tag is "Toronto" on public pages and "Admin" on admin screens. Don't add a strapline.
  • The button says "Menu" next to its icon, so it is clear on every phone.
  • Mark every label for translation; the wordmark "ShotThere" is a name and stays as is.

Drift fixed during extraction:

  • All 119 mocks with a Menu trigger use <a href="…/site-menu/…"> with aria-haspopup and aria-expanded, because static mocks can only link to the open state. The system specifies a <button type="button">.
  • The public site menu (dialogs/site-menu/default) marks no link current; the admin menu marks Dashboard. The system puts aria-current="page" in both.
  • At exactly 768px (the first MD width) the admin header is 1px wider than the viewport (six items plus "ShotThere Admin"); a narrower link padding between 48rem and 62rem is proposed as a CSS fix. The 16 admin dialog mocks (delete, unpublish, discard and others) also leave the Menu button out of the inert header behind the dialog; the header is the same as on the page underneath.
  • L2-064.2 asks for "an accessible disclosure"; every mock opens a modal sheet dialog instead. The system follows the mocks (focus trapped, page inert, Escape closes) and this is listed as an open question.
