File upload

How the owner adds test shots, gallery images and sample shots in the studio and spot editors. A real file input does the work; a small button label and a dashed box with the accepted types make it look like ShotThere. Each chosen file then becomes a row in the image manager.

Overview

The control is always a real <input type="file" class="file-input visually-hidden" multiple>. It is hidden visually but stays in the tab order; the visible part is the <label for> right after it, styled as a small button. Both sit in an .upload-drop box with the accepted types, at the end of an image group inside an editor section.

  • Studio editor, Images section: "Add test shots" under Standard test shots and "Add gallery images" under Gallery. Publishing needs at least one of each (L2-056.3).
  • Spot editor, Sample shots section: "Add sample shots". Each sample also gets a focal length and an angle note in its row.
  • Rules: JPEG, PNG, WebP or AVIF, up to 20 MB each, several at once. A file that breaks a rule is refused before it uploads, with a message under the box that names the file; the server checks type and size again (L2-057.2, L2-057.3).
  • After choosing: each accepted file appears at once as an image row with its own progress bar, Cancel upload, and on failure Retry (L2-057.6, L2-057.7). Those rows are documented on Image manager; while any is uploading, Save changes is disabled (see Form layout).

The public site has no uploads: visitors never send files to ShotThere.

Anatomy

  1. Box.upload-drop: a wrapping flex row, 2px dashed --color-border-strong edge, --radius-md, padding --space-4, muted --text-body-sm. It frames the way in; it is not a drop target.
  2. Input and labelThe hidden .file-input comes first and keeps focus; its <label class="btn btn--sm"> shows the ring (.file-input:focus-visible + .btn) and names the input.
  3. Accepted types"JPEG, PNG, WebP or AVIF, up to 20 MB each." Always visible before a file is chosen; tied to the input with aria-describedby.
  4. RefusalsOne .field__error per refused file in a full-width role="alert" stack, so it is announced as it appears.

Sizes

One size. The trigger is always a small button (.btn--sm): 36px from 48rem, 44px below it, like every other row action in the editor (L2-065.3). The box takes the width of its group; its padding is --space-4.

--control-height-sm from 48rem; --target-comfortable below.

States

Hover, focus and active are forced on the label with data-state; in the product the focus ring comes from .file-input:focus-visible + .btn. Disabled uses the input's real disabled, which .file-input:disabled + .btn turns into a dimmed label. No editor mock disables the input; it stays usable while other files upload.

Responsive behaviour

  • The box is a wrapping flex row. When the box is wide enough the button and the accepted types share a line; on narrow phones the types line drops under the button. Nothing scrolls sideways at 320px (L2-064.1).
  • Refusal lines always take the full width of the box (.upload-drop > [role="alert"] sets flex-basis: 100%) and wrap; long file names break anywhere.
  • Below 48rem the button grows to 44px tall (L2-065.3). On a phone the native picker offers the camera roll and files; ShotThere adds nothing to it.
  • The box sits inside the editor section's padding, so its edges line up with the image rows above it at every breakpoint.

Theming

The box reads --color-border-strong for its dashed edge and --color-fg-muted for its text; refusals use --color-danger-fg. It has no fill of its own, so it shows the editor section's --color-bg-surface. The trigger is a secondary button and themes with Button. In dark the dashed edge stays above 3:1 against the surface, so the box is still visible as a group.

Accessibility

Role and pattern

The native <input type="file" multiple>, hidden with .visually-hidden (never display: none) and labelled by the button-styled <label for>. The group's <fieldset> and <legend> ("Standard test shots", "Gallery", "Sample shots") give the context. Refusals are in a role="alert" container.

Keyboard

KeyAction
Tab / Shift+TabFocuses the hidden input; the ring shows on its label.
Space, EnterOpens the system file picker.
Esc (in the picker)Closes it without choosing; focus is back on the input.

Focus

Focus stays on the input after choosing files. When an upload finishes, focus moves to that image's alt text field so the owner can describe it at once (L2-057.1); refused files do not move focus; the alert announces them.

Labelling

The label names the input ("Add gallery images") and the legend the group. The accepted-types line is the input's description through aria-describedby, so it is read before the picker opens.

Motion

Only the button's own 120ms colour change, zeroed by reduced motion. Progress is in the image rows.

Touch

The trigger is 44px tall below 48rem. The whole label is the target, not just its text.

Content

  • Trigger: "Add" plus what the group holds, plural: "Add test shots", "Add gallery images", "Add sample shots". Not "Upload", "Browse" or "Choose files".
  • Accepted types, exactly: "JPEG, PNG, WebP or AVIF, up to 20 MB each."
  • Empty group: "No gallery images yet. Publishing needs at least one." (also for test shots and sample shots).
  • Wrong type: "file name isn't a supported image. Use JPEG, PNG, WebP or AVIF."
  • Too large: "file name is 25 MB. The limit is 20 MB." Round the size to whole megabytes.
  • Failed in transit (in the row): "file name didn't upload. Check your connection."

Drift fixed during extraction:

  • No mock ties the accepted-types line to the input; the system adds an id and aria-describedby.
  • The refusal stack in pages/studio-editor/upload-failed uses an inline flex-basis: 100%; .upload-drop > [role="alert"] now sets it, so the examples here drop the inline style.
  • The name .upload-drop suggests dropping files, but no mock shows a drag state and L2-057 does not ask for one. The box is documented as a frame, with the button as the way in.
