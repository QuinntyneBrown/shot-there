Filters

Filters narrow the studio and spot lists to what a shoot needs: cost, neighbourhood, light, gear, parking, spot type, use and permits. From LG they sit in a column beside the results; below LG a Filters button with a count opens them in a sheet. The chosen filters show as removable chips above the results, and every choice lives in the URL.

Overview

Visitors use filters to find a studio or an outdoor spot that fits a particular shoot. The studio list filters by all-in cost for 2 hours (minimum and maximum), neighbourhood, natural light, cyc wall, minimum usable space, included gear and parking (L2-022); the spot list by type, use case and permit (L2-024). Filters combine with AND; several choices in one group combine with OR.

  • Filter group (.filter-group on a <fieldset>, .filter-group__title on its <legend>): one question, answered with checkboxes, radios, a select or a minimum and maximum pair.
  • Filter trigger (.filter-trigger): the pill-shaped Filters button below LG. It opens the filters sheet and carries the count of active filters (.filter-trigger__count, L2-022.6).
  • Active filters (.active-filters with .chip--filter): one removable chip per active filter, then "Clear all".
  • Result count (.result-count): "7 studios", a polite live region that announces every change (L2-069.3).
  • Browse layout (.browse, .browse__aside, .browse__results): the page grid that puts the filters beside the results from LG.

Filter state lives in the URL query (L2-025): the filters form is a plain GET form, so /studios?costMax=150&light=medium&sort=cost reproduces the same list in a new session, Back and Forward restore earlier filter sets, unknown values are ignored without an error, and a minimum above the maximum in a URL is treated as no range.

Use something else for navigation between pages (the site header), for switching between views of the same data (a segmented control, as on the map), and for search. Sort is not a filter: it is a select beside the trigger, though it also lives in the URL.

Anatomy

  1. Filter group<fieldset class="filter-group"> with a <legend class="filter-group__title"> in --text-label, --color-fg-subtle, 8px above the options. Groups sit 32px apart.
  2. OptionA checkbox or radio row (.choice), a select, or a minimum and maximum pair of number fields.
  3. Result count.result-count: --text-body-sm in --color-fg-muted; role="status".
  4. Filter trigger and count.filter-trigger: 44px pill, 1px --color-border-strong edge, filter icon and "Filters"; .filter-trigger__count is a 22px ink bubble. Below LG only.
  5. Active-filter chip.chip--filter: accent-subtle fill, accent edge and text, with a 24px remove button (44px below 48rem).
  6. Clear allA small link-style button at the end of the chip row that empties every filter but keeps the sort.

Responsive behaviour

  • XS and SM (below 48rem): the filter column is not displayed. The results header shows the count, the Filters trigger and Sort; the trigger opens a full-screen sheet with Sort and every group, and a footer with Clear all and "Show 7 studios" above the bottom safe area (L2-022.5). Chips and their remove buttons, option rows and the trigger are all 44px.
  • MD (48–62rem): the same trigger, but the sheet is a 28rem side sheet over a backdrop, so the list stays visible behind it.
  • LG and up (62rem+): .browse becomes two columns: the 15rem filter column (title above it) and the results, 48px apart. The trigger is hidden (.until-lg); filters apply as they change, with "Apply filters" as the no-script fallback. The location grid inside the results is 2 columns at LG and 3 from XL.
  • Chips wrap onto new lines; a long label such as "No permit needed for the selected use" wraps under its checkbox. Nothing scrolls sideways.

Theming

There are no component tokens. The trigger reads the button roles (--color-bg-surface, --color-border-strong, --color-bg-subtle on hover, --color-bg-subtle-hover when pressed, --color-fg-default for the open edge); the count bubble reads --color-action and --color-fg-on-action; chips read the selected roles (--color-accent-subtle, --color-accent, --color-fg-accent); legends read --color-fg-subtle and the count --color-fg-muted.

In light the bubble is ink on white and chips are a pale accent red with red text. In dark the bubble flips to light stone with dark text, and chips become a deep accent fill with light accent text. In forced colours the trigger keeps a CanvasText edge and filter chips a Highlight edge.

Accessibility

Role and pattern

The filters are a native GET form: each group a <fieldset> with a <legend>, options native checkboxes, radios and selects, so the legend gives each option its context ("Neighbourhood, Junction, checkbox"). The trigger is a <button aria-haspopup="dialog" aria-expanded> that opens an APG modal dialog (the sheet). Chips are static text with a native remove <button>. The count is role="status" with polite announcements. The filter column is an <aside> named by its heading ("Filter studios").

Keyboard

KeyAction
Tab / Shift+TabMoves through groups, the trigger, Sort, each chip's remove button and Clear all; inside the sheet it stays in the sheet.
SpaceToggles the focused checkbox; activates the trigger or a remove button.
↑ ↓Moves between radios in a group (Parking, Permit) and selects as it moves.
EnterSubmits the filters (Apply filters, or "Show 5 studios" in the sheet); activates buttons.
EscCloses the sheet with nothing applied and returns focus to Filters (L2-067.3).

Focus

The sheet opens with focus on Close; in the invalid state focus goes to the field in error. Close, Esc and "Show N studios" return focus to the Filters trigger. Removing a chip removes its button, so focus moves to the next chip's remove button or, when the last chip goes, to the Filters trigger below LG or the first filter group from LG. The ring is the shared 2px --color-focus-ring; on a chip it sits on the accent-subtle fill.

Labelling

The trigger's name includes the count through visually hidden text: "Filters, 2 active". Each remove button says what it removes: "Remove filter: Up to $150.00". The chip row starts with visually hidden "Active filters:". Minimum and Maximum are labelled and grouped under "All-in cost for 2 hours"; the range error is linked to Maximum and to the disabled Show button with aria-describedby. The count announces the sort too ("5 studios, sorted by all-in cost", L2-023.3).

Motion

The trigger's fill changes over --duration-fast; the sheet slides in over --duration-slow. Reduced motion zeroes both. Result updates do not animate.

Touch

Below 48rem the trigger, every option row, each chip and each remove button are at least 44px (L2-065.3); remove buttons grow to a 44px square so the × is easy to hit without catching the chip next to it. The sheet's two footer buttons split the width. Nothing depends on hover.

Content

  • Legends name the question in sentence case: "All-in cost for 2 hours", "Neighbourhood", "Space and light", "Included gear", "Parking", "Type", "Use case", "Permit".
  • Options are the values visitors see on cards: neighbourhoods in alphabetical order ("Bloordale" to "Riverside"), "On-site", "Street", "None". Single-choice groups start with "Any". Add a hint only where the value needs one: "Natural light — At least medium at some time of day".
  • Chips are short: "Up to $150.00", "Natural light", "Cyc wall", "Parking: on-site", "Family", "No permit needed", "Waterfront". Prices are CAD with cents.
  • The count uses the noun with the right number: "7 studios", "1 studio", "0 studios", "5 spots".
  • The sheet's primary previews the outcome: "Show 7 studios", "Show 5 studios", "Show 2 spots"; "Show studios" while the range is invalid. The column's button is "Apply filters".
  • Clearing is "Clear all" in the chip row and the sheet, "Clear filters" in the no-results empty state (L2-022.4).
  • No results: "No studios match these filters" and one sentence on what to do, with the total: "Try removing a filter, or clear them all to see all 7 studios."
  • Range error: "The minimum must be lower than the maximum".

Drift found during extraction:

  • Column heading reuses the legend class. "Filter studios" / "Filter spots" is <h2 class="filter-group__title" style="font: var(--text-h4); color: var(--color-fg-default)"> in 17 mocks (every studios and spots list state and every filters dialog backdrop), overriding both properties of the class inline. h2.filter-group__title { font: var(--text-h4); color: var(--color-fg-default); } now styles the heading, so the mocks' markup works without the inline style; the examples here use it.
  • The trigger is a link (<a class="filter-trigger" href="…dialogs/studio-filters/…">) with no aria-expanded, because the mocks navigate between files. Documented as a button; its open state is never shown in a mock.
  • Sheet controls are links. Close is <a class="btn btn--ghost btn--icon" aria-label="Close">, and the footer's "Clear all" and "Show 7 studios" are links, while the invalid state switches Show to a disabled <button>. Documented as buttons (type="reset" and type="submit" form="studio-filters") with Close named "Close filters".
  • Results header spacing is inline. The count row is .cluster.cluster--between with margin-bottom of --space-8 (no filters) or --space-4 (filters), and the chip row adds --space-8; the existing .browse__head (16px gap, 40px below) is unused. This page wraps both rows in .browse__head, which puts 40px instead of 32px above the grid.
  • Clear all is missing in no-results. The chip row ends with "Clear all" in filtered but not in no-results, where only the empty state's "Clear filters" remains. Both labels are kept as the content rules describe; the chip row should keep "Clear all" whenever it shows.
  • "Apply" in L2-022.5 is "Show 7 studios" in the sheet (the mock says it is the Apply action) and "Apply filters" in the column.
  • Focus after removing a chip or clearing is not shown in any mock; the rule above (next chip, then the trigger or first group) was added during extraction.
