Review layout

The page skeleton every studio and spot review shares: a head with the name and the basic facts, one hero photo, the review sections in a fixed order, and a summary panel that sits beside them from LG and comes straight after the photo on phones and tablets. Because every review uses the same skeleton, two locations read the same way and compare side by side.

Overview

Use the review layout for the two public review pages, and only for them:

  • Studio review (/studios/the-junction-loft): basics, pricing, measured specifications, gear, logistics, standard test shots, gallery, verdict with the disclosure, episode and "Featured in" (L2-003 to L2-013, L2-036).
  • Outdoor spot review (/spots/evergreen-brick-works): map, directions, light, sample shots, conditions, permits, best uses with the disclosure, episode and rain backup (L2-014 to L2-020, L2-037, L2-038).

The layout owns the frame, not the contents: the price block, score and pips, shot grid, episode poster, map and description lists each have their own page. The guide page reuses .review-head on its own, without the hero, columns or summary.

Don't use it for the studio and spot lists (they use the browse layout on Container), the comparison (Comparison table) or the admin editors (Editor layout).

Anatomy

  1. Review head .review-headThe location's name is the page's only <h1>, set in --text-display with tight tracking; long names wrap anywhere rather than overflow. --space-8 above, --space-3 to the meta line.
  2. Meta list .review-head__metaA <ul> of short facts in --text-body-lg, --color-fg-muted. The "·" separators are generated content with empty alternative text, so screen readers hear a plain list.
  3. Hero .review-heroOne photo, 3:2 on phones, 16:7 from MD, --radius-lg, --color-bg-photo behind it while it loads. Loaded eagerly with fetchpriority="high": it is the largest paint.
  4. Main column and sections .review-main · .review-sectionEach section is a <section aria-labelledby> with an <h2>; --space-16 between sections, --space-6 under the heading, --space-8 above an <h3>.
  5. Section head .section-headHeading plus a count or caption on one baseline ("From a real shoot · 8 photos", "Sample shots · 5 photos"); wraps on narrow screens.
  6. Summary panel .summary-panelAn <aside aria-label="Summary">, 22rem wide from LG, hairline border, --radius-lg, --space-6 padding, --space-5 between parts. Sticky from LG.
  7. Summary facts .summary-panel__rowA two-column <dl>: label in --text-label and --color-fg-subtle, value in --text-h3 with tabular figures. Exactly two facts.
  8. Action and captionOne full-width primary action (the studio's booking page or Google Maps), the compare toggle on studios, and a .text-caption that says what ShotThere doesn't do and when the data was checked.

Variants

There are two variants of one skeleton. They differ only in which sections they hold and what the summary panel says; the head, hero, spacing and breakpoints are identical.

Section order

The order is fixed for every studio and for every spot, so a reader who knows where the test shots sit on one review finds them in the same place on the next (L2-009.2). Optional sections disappear completely when there is nothing to show; required sections always render.

Sizes

One size. The page sits in .container (up to --layout-container-max with --layout-margin either side); from LG the summary panel is fixed at --layout-panel-width (22rem) and the main column takes the rest. Below LG everything is full width.

States

The skeleton itself is not interactive. Its interactive parts are the summary panel's action and compare toggle, and what changes from review to review is data: stale prices or permits, a photo that didn't load, a studio already in the comparison. The matrix shows the summary panel, where every one of those shows up.

  • The head and hero sit above the two columns at every width, so the photo always spans the content width.
  • The main column is min-width: 0, so wide content inside it (tables, the comparison of light by time of day) wraps or scrolls inside its own wrapper and never pushes the page sideways at 320px.
  • Long names and addresses wrap anywhere ("Leslieville Daylight Studio", "Ossington Ave at Dundas St W, ground floor"); the meta list wraps between items, keeping each fact whole.
  • Section headings land --space-8 below the top of the window when reached from a link (scroll-margin-top).
  • When the compare bar is showing, .has-compare-bar on <main> adds the bar's height plus env(safe-area-inset-bottom) to the end of the page.

Theming

The layout reads semantic tokens only and has no component tokens: --color-fg-muted for the meta line, --color-fg-subtle for separators and summary labels, --color-border-default for the panel's hairline, --color-bg-photo behind the hero, plus the type, spacing and radius tokens below.

The summary panel has no fill in either theme: it is an outline on the page canvas, so it never competes with the photos. In dark the canvas goes to deep stone, the hairline to --palette-stone-750, and the hero placeholder darkens so a loading photo doesn't flash light. Photos are content and keep their own colours in both themes.

To re-theme, change the semantic tokens; don't give the panel its own background or shadow. A raised, filled panel beside the review reads like an advertisement.

Accessibility

Role and pattern

Native landmarks and headings, no ARIA widget. <main> holds the page; the breadcrumb is a <nav aria-label="Breadcrumb">; the name is the only <h1> (L2-003.1); each review section is a <section aria-labelledby> named by its <h2>, so it is listed as a region; the summary is an <aside aria-label="Summary"> (complementary landmark). The meta line is a <ul> whose separators are written as content: "·" / "", empty alternative text, so they are not read. See APG: Landmark regions.

Keyboard

KeyAction
TabSkip link, header, breadcrumb, then each section's links and controls in reading order, then the summary panel's action and compare toggle, then the footer.
Shift + TabThe same, backwards.
EnterOn "Book on the studio's site" or "Open in Google Maps": opens the page in a new tab.
Space / EnterOn the compare toggle: adds or removes the studio; aria-pressed and the label change together.

Focus

Nothing moves focus on load. The skip link targets <main tabindex="-1">, which shows no ring. The sticky panel has its own column from LG, so it never covers a focused element (2.4.11). Known gap: below LG the panel is shown first but is last in the source, so it is reached by Tab only after the whole review (1.3.2, 2.4.3). The fix proposed for components.css is to move the <aside> first in the source and place it in the second column from LG; until then keep the panel's contents short so nothing important is only there. Every fact in the panel is repeated in the sections below it.

Labelling

  • The <aside> is named "Summary"; each <section> is named by its heading through aria-labelledby.
  • Scores carry the scale in hidden text: "3.8 out of 5".
  • External actions add "(opens in a new tab)" in visually hidden text; the arrow icon is aria-hidden.
  • The hero has real alt text describing the space (stored with the image); the review date is a <time datetime>.

The panel's hairline (--color-border-default) is decorative: it groups, but nothing depends on seeing it, and every control inside has its own 3:1 edge.

Motion

None of its own. Sticky positioning is not animation. In-page links scroll smoothly, and prefers-reduced-motion turns that off (scroll-behavior: auto).

Touch

The summary panel's buttons fill its width and are 44px tall (--control-height-md). Nothing in the layout depends on hover.

Content

  • Head: the name exactly as the location writes it, then two or three facts. Studio: neighbourhood · cross streets with the floor · "Reviewed 29 September 2026". Spot: neighbourhood · type ("Don Valley · Park"). Guide: "3 studios · Updated 3 October 2026". Long dates in the head.
  • Section titles are fixed and sentence case: "Pricing", "Measured specifications", "Gear", "Logistics", "Standard test shots", "From a real shoot", "Verdict", "Watch the episode", "Featured in"; "Location and map", "How to get there", "Best light", "Sample shots", "Practical conditions", "Permits", "Best uses", "Rain backup".
  • Summary facts: two, the ones a reader decides on. Studio: "All-in, 2 hours" and "Overall". Spot: "Portrait permit" and "Best light".
  • Summary action: "Book on the studio's site" or "Open in Google Maps", naming where it goes. Never "Book now": ShotThere takes no bookings.
  • Summary caption: what we don't do, then when the data was checked, short date: "ShotThere doesn't take bookings or payments. Prices verified 22 Sep 2026." / "Permit rules verified 1 Sep 2026. Check the source before a paid shoot."
