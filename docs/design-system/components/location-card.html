Location card

A location card is one reviewed studio or outdoor spot in a list: its photo, name and neighbourhood, the numbers that decide a booking, and for studios the compare toggle. The name is the one link, and it covers the whole card.

Overview

Every list of places on ShotThere is a grid of location cards: the studio list (L2-021), the outdoor spot list (L2-024), the home page's latest reviews and outdoor spots, and the list beside the map (L2-029) in its compact form. Because every location was shot with the same test setup, the cards show the same facts in the same place, so a visitor can scan a row and compare without opening anything.

  • Use it for any list where each item opens a studio or spot review.
  • Use a list row instead when a single number is the point and there is no room for a photo: the rain-backup studios on a spot page are list rows with a distance ("Riverside Rooftop Studio · 3.1 km").
  • Use a table instead in the admin, where rows are edited rather than browsed.
  • Use the comparison table once a visitor has picked studios; the card only starts that, through its compare toggle.

Studio cards and spot cards share one class. A studio card shows the all-in cost for 2 hours and the overall score; a spot card shows best uses and the permit rule for portraits and commercial shoots. Only studios can be compared, so only studio cards in the studio list carry the compare toggle.

Anatomy

  1. Media.location-card__media: 3:2 frame, --radius-lg corners, --color-bg-photo while the photo loads. The photo is decorative (alt="") because the name follows it.
  2. Name.location-card__name: a heading (h3 in lists) holding the only link, in --text-card-title. The link's ::after stretches over the card.
  3. Meta.location-card__meta: neighbourhood and review date for studios, neighbourhood and type for spots, in --text-body-sm muted.
  4. Facts or tagsStudios: .location-card__facts, a <dl> of all-in cost and score. Spots: .tags of best uses, then a second meta line with the permit rule.
  5. Actions (optional).location-card__actions: the compare toggle, raised above the stretched link with --z-raised so it stays clickable.
  6. Hit areaThe whole card. Hover zooms the photo and underlines the name; focus rings the whole card.

Variants

The content of a card changes with what it lists and where it sits; the frame never does. Pick the variant by the list, not by taste.

Inside a guide entry

A guide ranks locations, so its entries wrap a .location-card (media, rank and name, meta) beside the editor's note and data point; the card drops facts and actions, and the name becomes an h2 because each entry is a top-level section of the guide. See Guide entry.

  • Hover scales the photo to 104% inside its frame and underlines the name. Nothing moves outside the frame, so neighbours never shift.
  • Focus lands on the name link; the ring is drawn around the whole card (8px offset, --radius-lg) and the link's own outline is removed, so there is one ring, not two.
  • Loading (pages/studios/loading, pages/spots/loading) shows six .location-card--skeleton cards, two rows at LG; the grid has aria-hidden="true" and the result count announces when the list arrives. See Skeleton.
  • Image failed keeps the 3:2 slot and fills it with .media-fallback so the grid never shifts (L2-086.1). Card photos are decorative, so the fallback shows only the crossed-out image icon; where a photo carries meaning (a gallery shot), the fallback also prints its alt text.
  • Stale adds a warning badge in words after the facts: "Prices may be out of date" when a studio's prices were verified more than 183 days ago (L2-021.3), "Permit rules may be out of date" for a spot's permit rules.
  • Selected for comparison is a state of the compare toggle, not of the card; see Compare toggle and bar.

Responsive behaviour

The card itself is fluid: it fills its grid cell and its photo keeps 3:2 at any width. The grid decides the columns (L2-021.4):

  • Names wrap (overflow-wrap: anywhere) and never truncate; facts wrap onto a second line rather than shrinking.
  • The compare toggle (.btn--sm, 36px) grows to 44px below 48rem (L2-065.1).
  • Below LG the map page shows the map or the list, switched by a Map/List control; the compact items there sit two to a row from SM.

Theming

The card has no surface of its own: it sits on the page canvas and reads semantic tokens only, so it follows the theme with no component tokens. Photos are content and keep their own colours in both themes; only the empty frame behind them and the failed-image fill (both --color-bg-photo) change.

/* A denser list on a partner page: smaller title, tighter rows, no new classes */
.partner-list .location-card { --text-card-title: var(--font-weight-medium) var(--font-size-lg) / var(--line-height-snug) var(--font-family-sans); }
.partner-list .location-grid { gap: var(--space-6) var(--space-4); }

In the dark theme the name and facts stay at --color-fg-default, the meta at --color-fg-muted, and the warning badge switches to the dark warning pair; every pair below is checked in both themes.

Accessibility

Role and pattern

A <ul> of <li class="location-card">, so screen readers announce "list, 7 items". Each card is the "card with a stretched link" pattern: one native <a href> inside the name heading, its ::after covering the card. There is no ARIA widget role; the card is not a button and is never wrapped in an <a>, which would nest the compare button inside a link. The heading level follows the page: h3 under the list's (visually hidden) "Results" h2, h2 inside a guide.

Keyboard

KeyAction
Tab / Shift+TabMoves to the card's name link, then to its compare toggle when it has one, then to the next card. One or two stops per card, in reading order.
EnterOn the name: opens the review. On the compare toggle: adds or removes the studio.
SpaceOn the compare toggle: adds or removes the studio. On the name it scrolls the page, as on any link.

Focus

The name link's own outline is removed and the shared ring (2px --color-focus-ring) is drawn around the whole card through .location-card:has(.location-card__name a:focus-visible), 8px out, so the ring outlines what a click would open. A compact .map-list-item gets the same ring through .map-list-item:has(.location-card__name a:focus-visible), with --radius-md corners. Focusing the compare toggle rings only the toggle. :has() is supported in every current browser; without it the link would show no ring, so do not remove the selector.

Labelling

  • The accessible name of the card's link is the location's name only; meta and facts are read after it in order, not folded into the link.
  • The photo has alt="" because the name next to it says the same thing.
  • Facts are a <dl>: "All-in 2 h, $80.00; Score, 3.2 out of 5" (the "out of 5" is visually hidden).
  • Best-use tags are a list labelled "Best uses".
  • The compare toggle adds the studio's name in a visually hidden span, so 7 "Compare" buttons become "Compare Kensington Window Room", "Compare The Junction Loft" and so on.
  • The skeleton grid is aria-hidden="true"; the result count above it (role="status") announces "7 studios" when the cards arrive.

The tag outline (--color-border-default) is decorative: the tag's text carries the meaning.

Motion

The photo zoom runs over --duration-slow (320 ms) with --ease-standard. Under prefers-reduced-motion the photo does not zoom at all (scale: none), so nothing moves on hover. Skeleton shimmer stops under reduced motion.

Touch

The whole card is one target, far above 44 × 44px. The compare toggle sits above the stretched link and is 44px tall on phones. The actions row and the tag list are raised above the link, but they pass taps through (pointer-events: none, restored on their controls and linked tags), so the empty space beside the toggle and plain tags still open the card. Hover-only cues (zoom, underline) carry no information, so nothing is lost without a pointer.

Content

  • Name: the location's published name, exactly ("The Junction Loft", not "Junction Loft Studio"). Never truncated.
  • Studio meta: Neighbourhood · Reviewed 3 Oct 2026. Spot meta: Neighbourhood · Type, then the permit line Portraits: no permit needed · Commercial: permit required.
  • Facts: "All-in 2 h" with the price to the cent ("$145.00": rate × max(2, minimum hours) + mandatory fees), and "Score" with one decimal ("3.8").
  • Tags: best uses in sentence case, in the order the review lists them; at most four.
  • Stale: "Prices may be out of date" (studios) and "Permit rules may be out of date" (spots). No dates in the badge; the review shows the date.
  • Compact meta: the type first because the list mixes both ("Studio · Bloordale", "Outdoor spot · Garden District"), then one deciding fact ("All-in 2 h: $130.00", "Portraits: no permit needed").
  • Order comes only from the visitor's sort (most recent review by default); a card never says "featured" or "sponsored".

Drift found during extraction. The CSS fixes have landed in components.css; the mocks still carry their inline styles:

  • Inline name size on compact items. Every .map-list-item in pages/map/* and dialogs/map-popup/* sets style="font: var(--text-label); font-size: var(--font-size-md);" on .location-card__name. Fixed: .map-list-item .location-card__name { font: var(--text-label); font-size: var(--font-size-md); }, so the inline styles can go; the examples here drop them.
  • Inline skeleton size on compact items. pages/map/loading sets style="height: 100%; margin: 0;" on each thumbnail skeleton. Fixed: the .location-card--skeleton .location-card__media .skeleton rule now covers .map-list-item .location-card__media .skeleton.
  • No focus ring on compact items. .location-card__name a:focus-visible removes the link's outline, but the replacement ring only matches .location-card:has(…), so a focused .map-list-item showed nothing (WCAG 2.4.7). Fixed: .map-list-item:has(.location-card__name a:focus-visible) and .map-list-item[data-state="focus"] draw the ring with border-radius: var(--radius-md).
  • Dead zones over raised boxes. .location-card__actions and .location-card .tags are raised above the stretched link as whole boxes, so a tap on a plain best-use tag (every spot card in the mocks) or on the empty width beside the compare toggle opened nothing. Fixed: .location-card__actions, .location-card .tags { pointer-events: none; } plus .location-card__actions > *, .location-card .tags a { pointer-events: auto; }.
  • Two columns at LG on the studio list. Beside the 15rem filter sidebar the grid shows 2 columns from 62rem and 3 from 75rem; L2-021.4 asks for 3 "at LG and above". Recorded for a decision: amend L2-021.4 or accept three narrow columns at 992px.
  • The brief pointed at the rain-backup list on pages/spot/default as a card use; it is a list row (.list__item) and has no card overrides. The inline style on that page's a.tag best-use links belongs to Tag.
