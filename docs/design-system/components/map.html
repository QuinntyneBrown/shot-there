Map

Where a location is matters as much as what it costs. The map shows every reviewed studio and outdoor spot in Toronto, tells the two apart by shape, and opens a short popup that leads to the review.

Overview

One map frame, .static-map, appears in three places:

  • Locations map on the map page (L2-027–029): every published studio and spot as a focusable marker, a legend, a type filter (Both / Studios / Spots) and, below LG, a Map / List toggle. Activating a marker opens .map-popup with the kind, name, key fact and a link to the review (L2-028).
  • Spot map on an outdoor spot review (L2-014): .static-map--spot, 16:9, centred on the spot with a single marker that is a picture, not a control.
  • Preview map in the spot editor: .preview-map, the spot map bound to the latitude and longitude fields so the admin sees where the pin will land.

When the tile service is unreachable, .map-unavailable takes the frame's place at the same size and the rest of the page carries on (L2-086.2). Use the map for location only. A list of locations to choose from is a location card grid; distances to rain-backup studios are a list.

Studios are ink squares; spots are ringed circles. Shape carries the type, so the map reads the same in both themes, in forced colours and for anyone who cannot tell colours apart (1.4.1). Accent red is used only for the selected marker's ring.

Anatomy

  1. Frame and tiles.static-map: --radius-lg, sunken ground, at least 15rem (240px, L2-014.4). .static-map__tiles covers it behind everything (z-index: -1 inside an isolated frame).
  2. Studio marker.map-marker--studio: a 24px ink square (--color-action, --radius-xs) in a 44px transparent target, with a 2px surface halo and --shadow-2.
  3. Spot marker.map-marker--spot: a 24px surface circle with a 4px --color-fg-default ring, same target, halo and shadow.
  4. Selected markeraria-expanded="true": the mark grows to 1.2× and gains a second, accent ring outside the halo.
  5. Popup.popover.map-popup: kind overline, name (--text-h4), key fact, page link and a Close icon button, floated 32px above its marker; docked along the bottom on phones.
  6. Legend.map-legend--overlay: the two keys with their words on a raised surface in the bottom-left corner.

Responsive behaviour

  • XS–MD (below 62rem): the map page shows one view at a time. The bar holds the "Map" heading, the type filter and the Map / List toggle (.map-page__toggle); data-view="map|list" on .map-page hides the other view, and the choice is kept in the URL (?view=list, L2-029.2). The map fills the viewport below the header and bar (L2-029.1).
  • List view: one column of .map-list-item rows at XS, two columns from SM to MD.
  • LG and up: a 24rem scrolling list column beside the map, both filling the viewport below the header; the toggle is hidden (L2-029.3).
  • Popup: floats 32px above its marker from 48rem; below 48rem .map-popup--dock pins it across the bottom of the map, 12px from the edges, so it is never clipped by the frame or covered by a thumb.
  • Spot and preview maps are full content width at every breakpoint; the spot map never drops under 240px (L2-014.4).
  • Nothing scrolls sideways: the frame clips its tiles and markers, and the page bar wraps.

Theming

Tiles are content, like photos: they keep their own colours in both themes. Everything drawn on top reads semantic tokens, so it holds its contrast against the tiles through its own halo and surfaces:

  • Studio mark --color-action; spot mark --color-bg-surface fill with a --color-fg-default ring; both inside a 2px --color-bg-surface halo and --shadow-2. In dark the studio square becomes light stone inside a near-black halo and the spot becomes a dark circle with a light ring: still a square and a circle.
  • Selected ring --color-accent, outside the halo.
  • Legend overlay and popup: --color-bg-surface-raised with --shadow-2 / --shadow-3; in dark the raised surface is a lighter stone than the page, so both still read as lifted.
  • Frame ground and tiles-failed panel: --color-bg-surface-sunken, --color-fg-muted, --color-fg-default.

The marker has no component tokens; a re-skin overrides the semantic ones on the frame, for example .static-map { --color-action: …; } for a different studio fill.

Accessibility

Role and pattern

  • Markers on the locations map are native <button type="button"> elements with aria-haspopup="dialog", aria-expanded and, while open, aria-controls (APG Button).
  • Popup: a non-modal role="dialog" labelled by the location name (APG Dialog, without the focus trap: the rest of the map stays usable).
  • Spot map: role="region" named "Map centred on Evergreen Brick Works", holding a role="img" marker named after the spot (L2-014.1). It has no focusable content and never traps focus (L2-014.3).
  • Preview map: role="group" named "Map preview" and described by the help text under it.
  • Type filter and view toggle: segmented controls — role="group" ("Show", "View as") of aria-pressed buttons. A polite live region reports the count: "12 locations", "7 locations", "Loading locations…".
  • Legend: a <ul aria-label="Legend">; the keys are aria-hidden and the words carry the meaning.

Focus

The shared ring draws round the marker's 44px target (border-radius: full), outside the halo, so it is visible on any tile. Popup controls use the ring on the raised surface. Focus never lands on the tiles. In the list view .map-list-item removes its link's outline (inherited from the location card) and draws the ring round the whole row instead (.map-list-item:has(.location-card__name a:focus-visible), 8px offset, --radius-md).

Labelling

Each marker's name is the location and its kind, "The Junction Loft, studio" or "Evergreen Brick Works, outdoor spot", because the shape that tells them apart is visual. The popup is named by its heading; its link reads "View the review: The Junction Loft"; the icon button is "Close". The spot marker's name is just the spot name; the region adds "Map centred on". The tiles image is decorative (alt="").

Marks sit on tiles, which no token controls; the surface halo and shadow separate them from any tile colour. The popup link and the "Open in Google Maps" link on the sunken panel use --color-fg-link, checked at 4.5:1 on both surfaces in contrast-pairs.json.

Motion

Marks scale on hover and selection over --duration-fast; the popup enters with the popover's scale-in. Reduced motion zeroes both durations, so the change still happens, instantly. The loading skeleton's shimmer stops under reduced motion.

Touch

Every marker target is 44 × 44 although the mark is 24px. Hover only enlarges the mark; nothing is revealed on hover alone, so touch loses nothing. The docked popup on phones keeps the link and the 44px Close within thumb reach.

Content

  • Kinds: "Studio" and "Outdoor spot", in the popup overline, the legend and the list meta ("Studio · Junction", "Outdoor spot · Don Valley").
  • Key fact: "All-in for 2 hours: $145.00" for a studio; the portrait permit summary for a spot, "Portraits: no permit needed" or "Portraits: permit required".
  • Popup link: "View the review" for a studio, "View the spot" for a spot, with the name as a hidden suffix.
  • Filter: "Both", "Studios", "Spots"; toggle: "Map", "List". Count: "12 locations".
  • Tiles failed: "The map didn't load", then what still works — "The list of locations still works." on the map page, the coordinates "43.6846, −79.3653" and "Open in Google Maps" on a spot review.
  • Empty: "No locations on the map yet" / "The first studio and spot reviews are being shot now. Each appears here once it is published." Error: "We couldn't load the locations" / "Try again".
  • Coordinates to four decimals with a true minus sign (−79.3653), followed by a plain-words locator: "in the Don Valley below Bayview Ave".

Drift fixed during extraction:

  • Markers are <a href> elements pointing at the popup mock so the set can be clicked through, yet they carry aria-expanded and aria-haspopup. A marker opens a popup in place, so the system makes it a <button type="button"> (the CSS already resets button chrome). The popup's Close is likewise a <button>, not a link back to the map.
  • The key fact is worded "All-in for 2 hours: $145.00" in the popup but "All-in 2 h: $145.00" in the map list rows. The system uses the popup's wording in both.
  • Every .map-list-item heading carries the same inline style="font: var(--text-label); font-size: var(--font-size-md)"; .map-list-item .location-card__name now sets that font, so the examples here drop it.
  • .map-list-item had no visible focus: .location-card__name a:focus-visible removes the link outline and the replacement ring was only defined for .location-card. .map-list-item:has(.location-card__name a:focus-visible) now rings the row.
  • The empty, error and loading overlays are positioned with inline styles in the mocks; .static-map__overlay now centres the notice over the map and .static-map__overlay > .empty gives it its raised card, so the examples here use the class.
  • The map-page tiles image has no width/height; the system gives it 1600 × 1000.
  • The spot editor puts aria-describedby on a plain <div>, where it is ignored. The system gives the preview role="group" and aria-label="Map preview" so the help text is announced.
  • .map-unavailable has role="status" on the spot review but no role on the map page. Tiles fail after the page loads, so the system announces it politely on both.
