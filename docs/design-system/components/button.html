Button

Buttons do something: apply filters, add a studio to the comparison, save a studio, unpublish a guide. One solid ink button per screen marks the action that screen exists for.

Overview

Use a button when activating it changes something, opens a dialog or starts a request. Use a link when it only goes somewhere, an icon button for a lone glyph over a photo or map, and a segmented control to pick one view from a short row. A page's main call to action may be a link drawn as a button ("Book on the studio's site", "Browse studios", "New studio"); it keeps <a href> semantics.

  • Primary is solid ink (--color-action). It is the one action the screen exists for: "Book on the studio's site" on a review, "Show 7 studios" in the filters dialog, "Save changes" in an editor, "Sign in". When the compare bar appears, its "Compare" takes the primary and "Book on the studio's site" steps down to secondary (pages/studio/in-compare).
  • Secondary (the default look) is an outlined pill for every other action: "Apply filters", "Add to compare", "Publish" in the editor's status panel, "Cancel", "Try again", "Edit" and "Move up" in rows.
  • Ghost has no border. It sits where several actions repeat or must stay quiet: "Remove" on each image row, "Clear" in the compare bar, "Sign out", the site header's "Menu", the second action of an error state ("Go to the home page").
  • Link looks like a link but acts in place: "Clear all" at the end of the active-filter chips.
  • Danger is for loss and appears only inside a confirmation dialog: "Delete studio", "Remove test shot", "Discard".
  • Compare toggle (.compare-toggle) is a secondary button with aria-pressed: "Compare" on each studio card and "Add to compare" on a studio page. Pressed, it takes the accent tint. The bar it feeds is documented on Compare toggle and bar.

Accent red is never a button fill. On ShotThere it means "selected": a pressed compare toggle, an active filter chip, the current segment. An action painted red would read as a choice already made.

Anatomy

  1. LabelA verb phrase in sentence case; it is the accessible name, plus any visually hidden suffix such as " (opens in a new tab)" or " The Junction Loft".
  2. Icon (optional)1.25em outline icon in the label colour, aria-hidden="true". Leading for "New studio" (plus) and "Try again" (retry); trailing for links that leave ShotThere (the external arrow).
  3. ContainerPill (--radius-full) with a 1px border; height from --control-height-sm/md/lg (44px by default); side padding --space-3/4/6.

Variants

Variants change emphasis, not meaning. Pick by how much attention the action deserves on this screen.

Primary, secondary, ghost, link, danger: highest to lowest emphasis, with danger only inside a confirmation.
HTML
<button class="btn btn--primary" type="submit">Save changes</button>
<button class="btn" type="submit">Apply filters</button>
<button class="btn btn--ghost" type="button">Remove<span class="visually-hidden">: test shot 3</span></button>
<a class="btn btn--link btn--sm" href="/studios">Clear all</a>
<button class="btn btn--danger" type="button">Delete studio</button>

Compare toggle

A pressed-state button that adds a studio to the comparison (L2-030). On a card it is small and names the studio in hidden text; on the studio page it is medium and full width in the summary panel. Pressed (aria-pressed="true") it shows the accent tint, border and label, and its label changes to "Remove" as L2-030.1 asks.

Card toggles from pages/studios/selected; page toggles from pages/studio/default and pages/studio/in-compare. The bar, its count and the four-studio limit are on Compare toggle and bar.
HTML
<button class="btn btn--sm compare-toggle" type="button" aria-pressed="false">Compare<span class="visually-hidden"> Kensington Window Room</span></button>
<button class="btn compare-toggle" type="button" aria-pressed="true">Remove from compare</button>

With icons, icon-only, block and wrapping

.btn--icon is the dialog and sheet Close and needs aria-label; .btn--block fills its container (sign-in, summary panel, editor status panel); .btn--wrap lets a long label wrap left-aligned. No ShotThere mock uses .btn--wrap yet; every current label fits at 320px.

Links drawn as buttons

Book on the studio's site (opens in a new tab) Open in Google Maps (opens in a new tab) Browse outdoor spots
Booking happens on the studio's own site: ShotThere doesn't take bookings or payments. External button-links carry the arrow and the hidden "(opens in a new tab)".

Sizes

Medium (44px) is the default, so most buttons already meet the 44px phone target for submit buttons (L2-065.3). Small (36px) is for row and card actions ("Compare", "Edit", "Move up", "Add fee") from 48rem, with 8px to the next target; below 48rem it grows to 44px. Large (52px) is used only on owner sign-in, for "Sign in" and the "Show" password toggle beside the large input.

Heights --control-height-sm/md/lg; padding --space-3/4/6; label --font-size-sm/md/lg. Small reads 44px on a phone.

Pointer and focus states are forced here with data-state; real pages get them from :hover, :focus-visible and :active. Disabled, busy and pressed use the real attributes.

Both themes

  • Busy keeps the button's width and label (hidden visually, not changed), shows a spinner in the label colour, and sets aria-busy="true" with disabled, as every ShotThere mock does. Progress text goes in the form's or dialog's status line: "Saving…" beside "Save changes", "Deleting Corktown Garage Studio…" in the delete dialog. While a dialog is busy its Cancel and Close are disabled too (dialogs/delete-content/busy).
  • Disabled uses the native attribute at 50% opacity and always comes with a visible reason tied by aria-describedby: "Compare" in the bar with "Pick at least 2 studios to compare", "Save changes" with "Wait for uploads to finish", a published studio's "Delete studio" with "Unpublish before deleting.", "Add entry" until a location is picked.
  • Unavailable but focusable: the first row's "Move up" and the last row's "Move down" use aria-disabled="true" so focus does not jump while reordering.
  • Pressed is for the compare toggle (and the sign-in "Show" password toggle, which keeps the secondary look). Expanded is the site header's "Menu" (aria-expanded, aria-haspopup="dialog").

Responsive behaviour

  • Below 48rem every small button grows to 44px (L2-065.3), so card "Compare" toggles and row "Edit", "Move up", "Remove" are comfortable on a phone.
  • The studio page's summary panel and the editor's status panel stretch their buttons to full width at every size (.summary-panel .btn, .editor-aside .btn). Below 62rem the summary panel moves above the review, so "Book on the studio's site" is the first action on a phone.
  • Dialog footers keep buttons on one row and wrap when they don't fit; the confirming action stays last. The phone filters sheet stretches both buttons ("Clear all", "Show 7 studios") with .sheet__footer .btn.
  • .btn never exceeds its container (max-width: 100%). A label that would overflow at 320px gets .btn--wrap or a shorter verb phrase; it never truncates.

Theming

The button reads semantic tokens through five component tokens (--btn-bg, --btn-fg, --btn-border, --btn-bg-hover, --btn-bg-active) that each variant overrides. The compare toggle is built the same way: pressed, it points them at --color-accent-subtle, --color-fg-accent, --color-accent and --color-accent-subtle-hover. A theme changes the semantic tokens; a re-skin overrides the component tokens; neither edits .btn.

/* How .compare-toggle reuses .btn: only the component tokens change */
.compare-toggle[aria-pressed="true"] {
  --btn-bg: var(--color-accent-subtle); --btn-fg: var(--color-fg-accent);
  --btn-border: var(--color-accent); --btn-bg-hover: var(--color-accent-subtle-hover);
}

In dark the ink flips: primary becomes light neutral stone (--palette-stone-100) with near-black text, so it still reads as the one main action; danger becomes a light danger red (--palette-sorrel-300) with dark text; the pressed toggle becomes a deep accent tint with light accent text.

Accessibility

Role and pattern

Native <button type="button">, or type="submit" inside a form (APG Button). The compare toggle is the APG toggle-button variant (aria-pressed). A link drawn as a button stays an <a href>: "Book on the studio's site", "Show 7 studios", "Browse studios". A button that opens a dialog adds aria-haspopup="dialog" ("Add entry").

Keyboard

KeyAction
Tab / Shift+TabMoves focus to and from the button in DOM order. Disabled buttons are skipped; aria-disabled ones are not.
Enter, SpaceActivates; on the compare toggle, flips pressed. A link drawn as a button answers Enter only, like every link.
EscNo effect on the button; in a dialog it closes the dialog, the same as Cancel, and focus returns to the button that opened it (L2-067.3).

Focus

The shared ring (2px --color-focus-ring, 3px offset) shows on :focus-visible only (L2-067.2). The offset gap shows the surface behind, so the ring keeps 3:1 against both the ink button and the page.

Labelling

The visible label is the accessible name. Repeated buttons add the object in hidden text: "Compare Kensington Window Room", "Remove: test shot 3", "Edit Distillery District permits". Icon-only Close carries aria-label="Close". A busy button keeps its name; the status line says what is happening.

The compare toggle flips both its label ("Compare" → "Remove") and aria-pressed, so a screen reader hears "Remove The Junction Loft, toggle button, pressed". L2-030.1 asks for the label change; the APG advises a fixed label on a pressed button. This is flagged for review on Compare toggle and bar.

Motion

Background, border and shadow transition over --duration-fast (120ms); the active state nudges 1px down. Reduced motion zeroes the duration and removes the nudge. The busy spinner keeps turning because it reports status.

Touch

Medium (44px) and large (52px) meet the 44px target. Small is 36px only from 48rem, with 8px between buttons in a row; below 48rem it grows to 44px like every other target (L2-065.2, L2-065.3).

Content

  • Verb phrases in sentence case, Canadian English: "Apply filters", "Save changes", "Add to compare", "Create studio", "Try again". Never "Submit", "Yes" or "Click here".
  • Say what happens next when it helps: "Show 7 studios" updates with the live count; "Book on the studio's site" says where booking happens.
  • Destructive labels name what is lost: "Delete studio", "Remove test shot", "Discard". The safe action beside them is "Cancel", or "Stay" when leaving is the risk.
  • Three or four words where possible; a label that wraps at 360px is too long.
  • Acknowledge-only dialogs close with "Got it", not "OK".
