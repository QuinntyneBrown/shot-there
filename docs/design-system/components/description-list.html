Component · Data display

Description list

Description lists carry the measured facts every review shares: a studio's pricing, specifications, gear and logistics, a spot's directions and conditions, the verdict's "Who it's for" and the two numbers at the top of the summary panel. Same labels, same order, on every location, so reviews compare side by side.

Overview

Use a description list when each row is one label and one value. If people need to read down a second or third column (rating and note, status and date), use a table.

  • Key–value rows (.kv): the studio sections Pricing, Measured specifications, Gear (included and extras) and Logistics (L2-004, L2-006, L2-007, L2-008), and the spot sections How to get there and Practical conditions (L2-014, L2-017).
  • Regions (.regions): the verdict's two paragraphs, "Who it's for" and "Who should skip it", side by side from 48rem.
  • Summary row (.summary-panel__row): two headline facts at the top of the summary panel: All-in, 2 hours and Overall for a studio; Portrait permit and Best light for a spot.

The studio basics under the h1 (neighbourhood, cross streets, review date, L2-003) are a plain list in .review-head__meta, not a description list: they have no labels. Cards and the editor keep their own lists: .location-card__facts on the location card, .guide-entry__data on the guide entry and .editor-aside__meta in the editor layout.

Anatomy

  1. Labeldt, --text-label in --color-fg-subtle; a 12rem column from 36rem, above the value below it.
  2. Valuedd in body text; prices and measurements in .num for tabular figures. Long values wrap anywhere.
  3. Qualifier (optional)A badge after the value, pushed to the end: "Mandatory", "Optional, not in all-in".
  4. RuleA hairline under each value (and its label from 36rem) in --color-border-default.

Sizes

Each variant has one size, set by its role: .kv values in body text, .regions values in --text-body-lg, summary values in --text-h3.

Responsive behaviour

  • .kv: below 36rem each label sits above its value in one column and only the value carries the rule, so a row reads as one block (L2-003.3, L2-017.3). From 36rem the label takes a fixed 12rem column and both cells carry the rule.
  • .regions: one column below 48rem, two equal columns from 48rem.
  • .summary-panel__row: two columns at every width. Below 62rem the whole summary panel moves above the long sections, straight after the hero photo; from 62rem it is a sticky sidebar.
  • Values wrap anywhere (overflow-wrap: anywhere), so a long transit note never widens the page at 320px.

Theming

Labels read --color-fg-subtle, values inherit --color-fg-default, rules use --color-border-default. The lists have no fill, so they take the surface they sit on: the canvas on review pages. Badges inside values bring their own tone tokens. Nothing is overridden per theme.

Accessibility

Role and pattern

Native <dl>, <dt>, <dd>: no WAI-ARIA pattern or role is needed. Screen readers announce a list with term and definition pairs. .regions and .summary-panel__row group each pair in a <div>, which HTML allows; .kv must not, because its grid places dt and dd directly.

Keyboard

KeyAction
TabSkips the list: nothing in it is focusable.
Screen reader list keysMove pair by pair; the term is read before its value.

Focus

Not focusable. If a value ever holds a link, it gets the shared focus ring.

Labelling

Each list sits in a section named by its heading through aria-labelledby ("Measured specifications", "Practical conditions"). Units are spelled as symbols the screen reader can say ("m", "ft", "A"); the summary score adds <span class="visually-hidden"> out of 5</span>. Decorative middle dots are plain text and read as a pause.

Content

  • Labels are the same on every location and never change wording between reviews: "Usable shooting space", "Ceiling height", "Window direction", "Power", "Cyc wall", "Backdrops"; "Load-in", "Parking", "Transit", "Washroom", "Changing area", "Client seating", "Noise".
  • Measurements are metric first with imperial in brackets: "7.0 m × 5.2 m (23 ft × 17 ft)", "3.4 m (11 ft)".
  • Prices are CAD with two decimals in .num: "$45.50". Fees state whether they count: "Mandatory" or "Optional, not in all-in".
  • Join several facts in one value with " · ": "Weekday: Low · Weekend: High".
  • Absent values are words: "No", "None", "Nothing costs extra at this studio.", "Not measured". Never blank, never a dash.
  • Verdict regions are one or two plain sentences that name who and why: "Video crews, because of the streetcar…".

.numTabular figures for prices and measurements.
.naMuted "Not measured" for a value the visit did not record.
.dl, .facts, .inline-listStill in the stylesheet but used by no ShotThere mock; do not use. Use .kv.
