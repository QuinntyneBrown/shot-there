Tag

A tag is a quiet outlined label that says what a place is good for, such as "Engagement" or "Portrait", or links to a related page, such as the guide a studio is featured in. It never changes state.

Overview

Tags describe. On ShotThere they carry a spot's best uses, from the fixed set engagement, family, portrait, brand and video (L2-019), and on a review page they can link: a spot's best uses open the spot list filtered to that use (L2-019.2), and a studio's "Featured in" tags open the guides that rank it (L2-036). Three similar-looking pills do different jobs:

ComponentJobExampleHas state
Tag (this page)Describes a place or links to a related page.

If tapping it should change what the page shows, it is a chip. If it warns or reports a state, it is a badge. Admin publish states have their own status label.

Anatomy

  1. ContainerPill (--radius-full) with a hairline --color-border-default edge and no fill; 24px minimum height, --space-2 padding.
  2. LabelOne or two words in --text-caption, --color-fg-muted, on one line (white-space: nowrap).
  3. Group.tags: a list with no markers that wraps with --space-2 between tags. Named with aria-label when no visible heading names it.

A studio in no published guide has no "Featured in" section at all, rather than an empty one (L2-036.2).

Sizes

Two sizes. Compact (the base .tag) is for static labels inside cards and panels: 12px caption type, 24px minimum height, 8px padding. Large is for link tags, which are targets: 16px body type, 12px padding and the 44px phone target (L2-065.1).

  • Portrait · 24px
  • Portrait · 44px
Compact: --text-caption, --target-min, --space-2. Large: --text-body, --target-comfortable, --space-3.

Large is the default for a.tag: the rule sets the body type, the 12px padding and the 44px target, so a link tag needs no extra class. Every mock still writes it inline (style="font: var(--text-body); padding-inline: var(--space-3); min-height: var(--target-comfortable);") on each link tag; the examples here do not.

States

Static tags have no states. Link tags have the link states; pointer and focus are forced with data-state here, and come from :hover and :focus-visible on real pages.

Responsive behaviour

  • The group wraps onto as many lines as it needs; tags never shrink, truncate or scroll sideways.
  • A single tag never wraps inside itself (white-space: nowrap). The longest guide title, "Best studios under $120 for 2 hours", fits a 320px column at the large size; keep guide titles that short.
  • The size does not change by breakpoint: compact tags are never targets, and link tags are already 44px tall at every width.
  • On location cards, .location-card .tags is raised above the card's stretched link so a future link tag inside a card stays clickable.

Theming

The tag has no fill, so it takes the surface it sits on: canvas on cards, the summary panel and review sections. It reads --color-fg-muted and --color-border-default, and on hover --color-fg-default and --color-border-strong. There are no component tokens; re-theme by changing those roles.

In dark the label lightens to neutral stone 350 and the edge to stone 750 on the stone 950 page. Accent red is never used: on ShotThere red means "selected", which a tag never is. In forced colours the edge becomes CanvasText.

Accessibility

Role and pattern

A native list (<ul class="tags">) of plain text items or native links. No ARIA widget pattern applies: a tag is not a button and has no pressed or selected state. Name the list with aria-label="Best uses" when no visible heading or caption names it, as on cards.

Keyboard

KeyAction
Tab / Shift+TabMoves through link tags in order. Static tags are not in the tab order.
EnterFollows the link: the filtered spot list or the guide.

Focus

Link tags show the shared 2px --color-focus-ring on :focus-visible, following the pill shape because the tag keeps its --radius-full corners.

Labelling

The tag text is the accessible name; keep it unique within the group. A link tag's text is the destination ("Best natural light" is the guide's title), which meets 2.4.4 because the section heading ("Featured in", "Best uses") gives the context. Link tags are not underlined: they sit in their own list under a heading, not inline in text, so 1.4.1 does not require it; the pill edge marks them as targets.

The resting edge (--color-border-default) is decorative: the label carries the meaning and is 4.5:1. That pair is listed in contrast-pairs.json as decorative (minimum 1).

Motion

None. Hover changes colour without a transition.

Touch

Link tags are 44px tall at every width with 8px between them (L2-065.1). Compact tags are never targets, so their 24px height is not a target size.

Content

  • Best uses come from the fixed set and are written exactly: "Engagement", "Family", "Portrait", "Brand", "Video". Sentence case, singular, no plural "Engagements".
  • Show them in the spot's stored order on every surface, so the card, summary panel and best-uses section agree.
  • A "Featured in" tag is the guide's full title: "Best for a large crew", not "Large crew".
  • No counts, prices or verbs in tags: "Under $120" is a guide title's job, "Book now" is a button's.
  • Never use a tag for a warning or a status ("Permit required", "Stale"); those are badges or plain text.
